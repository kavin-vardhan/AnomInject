# Part B fixture authoring failure, retained

`part-b-resize-01` returned exit 1. Its Python report contained no exceptions, but the engine reported three transient no-miplevel errors and a persistent sampler mismatch for the roughness VT. The Interchange importer ignored the requested destination name when the same T_Stack*.png source was imported a second time for the ordinary control: the second task overwrote the VT asset and its settings. `stacks-probe-01` was mistakenly launched after inspecting the Python report before checking the commandlet's exit. It is invalid proof: the fallback material caused refusal. It is retained and excluded.

The correction supplies six distinct, correctly named source PNG files and asserts each task's imported asset path before changing settings. Both the commandlet exit and engine material compile output must pass before the next pixel leg. Part A's ten-asset fixture archive remains unchanged.

The second resize saved the correct six assets but again exited 1 with transient no-miplevel messages during reimport. The first separate validation queried asynchronous placeholder resources (32-square) and was invalid despite engine exit 0. The next validation loaded the map, ran Editor.AsyncAssetCompilationFinishAll, and checked all six 1024-square textures, VT flags, formats and material recompilation: Python errors empty, engine exit 0 with zero errors/warnings. The reports are part-b-fixture-validate-01.json, part-b-fixture-validate.json, and the two validation launch receipts. Lighting and authored per-texture LOD biases were then calibrated before the frozen positive gates. The validated final fixture is archived separately as fixture-part-b-calibrated.zip.
