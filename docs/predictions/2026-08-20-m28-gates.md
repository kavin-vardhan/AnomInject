m28 GATES - PRE-DECLARED
Written 2026-08-20, BEFORE any m28 implementation exists. Plugin HEAD at the time
of writing: 485b467 (m27 closed, tag m27 -> 4a92962).

Restate this file VERBATIM before reading any result. Nothing below may be
amended after a measurement has been taken. If a gate turns out to be
unrunnable, say so and stop - do not soften it.

SUBJECT
m28: capture output resolution, implemented as a DOWNSCALE ON WRITE. The render
stays native; the frame is resampled at the write step. Survey S0 established
that the m26/m27 stencil mask counts at the view's render resolution
(AnomalyMaskSceneViewExtension.cpp:100-101, :193-194, :208-224) and never sees
the capture output buffer, which is why this shape was chosen: a write-time
downscale structurally cannot reach the veto.

WHY THESE GATES AND NOT OTHERS
Every gate below is CATEGORICAL. There is no threshold and no tolerance
anywhere in this table, deliberately. The two that carry the most weight are
GATE B (read the artifact, not our own variable) and GATE D (a known-answer
control on a quantity that MUST NOT move).

---------------------------------------------------------------------------
THE GATE TABLE - VERBATIM AS ISSUED
---------------------------------------------------------------------------

  GATE A - THE LEVER PROVES IT DID SOMETHING
    A counter, resamples_performed, internal/log only (NOT a delivered field).
    Native leg:    resamples_performed == 0        EXACTLY
    Downscale leg: resamples_performed == total_frames   EXACTLY
    Neither "about zero" nor "roughly all". Exact equality or FAIL.

  GATE B - VERIFIED AGAINST THE ARTIFACT, NOT AGAINST OURSELVES
    On the downscale leg, read the DIMENSIONS OUT OF frame_00000's FILE HEADER
    on disk. They must equal the output size named in the StartRun echo.
    Reading our own variable back does not satisfy this gate.

  GATE C - THE RESOLUTION FIELD NOW DESCRIBES THE PIXELS
    On BOTH legs: annotation.json video.resolution == the dimensions read from
    frame_00000's file header. Exact match.

  GATE D - THE KNOWN-ANSWER CONTROL, and the most important gate here
    Same seed, same map, same exe. Native leg and downscale leg.
    Every bbox_norm value MUST BE IDENTICAL between the two legs.
    They never see a pixel dimension, so they cannot legitimately move.
    IF ANY bbox_norm MOVES, something reached the projection path, the design
    is wrong, and you STOP AND REPORT. Do not fix it in the same turn.
    (labels.jsonl is required for this gate - run these legs with delivery
    mode OFF.)

  GATE E - PROVENANCE SEPARATES, four legs, m27 Gate 3's shape
    nothing set        -> native,       provenance = compiled default
    ini set            -> that value,   provenance = ini
    cvar set           -> beats ini,    provenance = cvar
    per-run arg set    -> beats cvar,   provenance = per-run
    Each read from the StartRun echo line, not inferred.

  GATE F - EDGES
    Odd height requested   -> output even, echo states the snap
    Height >= native       -> output IS native, resamples_performed == 0,
                              echo explicitly states no upscale
    Height <= 0            -> native

  GATE G - A GUARD THAT HAS NEVER FIRED IS NOT A GUARD
    Send "jpg" over the wire  -> JPEG. (Before D9 this silently gave PNG.)
    Send garbage over the wire -> PNG **plus a warning naming the value**.
    Break it on purpose and show the warning firing. If it cannot be made to
    fire, it is not a guard and the gate FAILS.

  GATE H - THE PAIRED JPEG ARTIFACT (produce, do NOT grade)
    One additional leg: same seed, same map, format=jpeg. Bank it beside the
    PNG leg. DO NOT compare them, DO NOT judge quality, DO NOT propose a
    threshold. This gate is satisfied by the pair EXISTING and being banked.
    Grading is a separate, later, properly designed instrument.

---------------------------------------------------------------------------
THE LOCKED DESIGN THESE GATES ARE WRITTEN AGAINST
---------------------------------------------------------------------------
Recorded here so a later reader can tell which gate answers which decision,
and so a silently changed design is visible as a mismatch against this file.

  D1  NO WIDTH PARAMETER EXISTS. One knob: target output HEIGHT. Width is
      derived from the frame's own aspect. The bad state is UNREPRESENTABLE,
      not guarded against.
  D2  0 = NATIVE, output byte-identical to today. H_out snapped to nearest
      EVEN, minimum 2. W_out = round_even(H_out * W_frame / H_frame).
      NEVER UPSCALE.
  D3  DERIVE PER-FRAME FROM THE FRAME IN HAND. Never from GetViewportSize().
  D4  annotation.json video.resolution sourced from the FIRST WRITTEN FRAME's
      real dimensions; a later differing frame emits a loud WARNING naming
      both. NO new fields, NO new counters in any delivered artifact.
      run.json "viewport" is unchanged.
  D5  AREA / BOX RESAMPLE. Not point, not bilinear.
  D6  ONE RESAMPLE SITE that all write paths funnel through.
  D7  PRECEDENCE, highest first: per-run argument; IAI.Capture.OutputHeight;
      [AnomalyCapture] CaptureOutputHeightDefault; compiled default = 0.
      ONE UNCONDITIONAL StartRun line names native WxH, effective output WxH,
      and WHICH LEVEL WON.
  D8  DASHBOARD CONTROL beside the existing format select, same wire pattern.
      Absent field = fall through to level 2.
  D9  FIX W1: accept "jpeg" and "jpg" server-side; make the no-match branch
      LOUD, naming the unrecognised value and the fallback taken.
  D10 W2 IS FILED, NOT FIXED. No format field in the control snapshot.

---------------------------------------------------------------------------
FAILURE BRANCHES - what a FAIL means, decided before any result exists
---------------------------------------------------------------------------
  GATE A fails       -> the resample is not where we think it is, or it is
                        running on frames that are not being written. STOP.
  GATE B fails       -> the written file does not match what we told the
                        operator we wrote. This is the m28 equivalent of the
                        m27 count gate and it is not negotiable. STOP.
  GATE C fails       -> video.resolution is still describing something other
                        than the delivered pixels, i.e. survey S0 section C
                        was not actually fixed. STOP.
  GATE D fails       -> a pixel dimension reached the projection path. The
                        chosen shape is wrong. STOP AND REPORT, no same-turn
                        fix. This is the one gate whose failure invalidates
                        the design rather than the implementation.
  GATE E fails       -> a precedence level is unreachable or the echo is
                        reporting a value that is not the effective one
                        (G139's exact failure mode). STOP.
  GATE F fails       -> an edge produces an output nobody asked for. STOP.
  GATE G fails       -> if the warning cannot be made to fire, D9 shipped a
                        guard that has never fired, which G96 says is not a
                        guard. FAIL, do not argue it down.
  GATE H cannot fail on quality by construction. It fails only if the pair is
  not produced or not banked.

  NO GATE HERE IS SATISFIED BY A LOG LINE ALONE EXCEPT E, WHICH IS ABOUT THE
  LOG LINE. A, B and C are read off artifacts on disk.

PREDICTIONS - stated now so they can be wrong
---------------------------------------------------------------------------
  P-A  GATE D will PASS trivially and that is the point of running it.
       bbox_norm is written unchanged at AnomalyLabelWriter.cpp:71 from
       ProjectBoxToNormalizedRect (AnomalyViewport.cpp:248-281), which takes
       no pixel dimension. If it moves, the cause is somewhere I have not
       looked, and that is worth far more than the gate passing.
  P-B  GATE C will pass on the NATIVE leg for a reason that is NOT the m28
       change: survey S0 measured grabbed == slate-window == GetViewportSize()
       (all 1280x720) on both banked m27 smoke runs, so today's already-wrong
       source happens to produce the right number at this resolution. A native
       leg alone therefore does not demonstrate C is fixed - THE DOWNSCALE LEG
       IS THE ONE THAT PROVES IT. Recorded so a green native leg is not
       mistaken for evidence.
  P-C  I expect a residual I am declaring in advance rather than discovering:
       because H_out is snapped even and W_out is derived and snapped even,
       the delivered image's aspect can differ from the render's by up to
       roughly one part in a thousand. bbox_px, labels width/height and
       video.resolution all use the SAME derived pair, so labels stay exactly
       consistent with the delivered pixels; what drifts is only the
       correspondence between the render's projection aspect and the output
       image's aspect. Sub-pixel. Stated, not hidden, and not gated.
  P-D  I expect GATE G's "garbage" case to be the one that catches a real
       defect, not the "jpg" case, because the silent-PNG fallback is the
       behaviour nobody has ever seen fire.
