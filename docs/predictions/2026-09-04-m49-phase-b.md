## §0. What Phase B is, in one paragraph

`m49` A1 derived `observable` from three CPU-side facts (the fire is labelled this frame, the
anomaly's visual condition held at `OnWorldTickEnd`, and the target drew at least
`ObservableMinPixels` front-most pixels). The **third** of those is same-frame GPU evidence; the
**first two are not**. Phase B closes that for the hide class by asking the GPU directly: the mask
shader gains a second output, `drawn` = the reserved tag where the tagged surface **is** the scene's
front-most surface (`|CustomDeviceZ − SceneDeviceZ| ≤ DepthBias`), reduced per tag to `DrawnCount`.
For a correctly hidden target the silhouette is present (`Count > 0`, from custom depth, which `m45`
keeps) while `DrawnCount == 0` — **the GPU's own statement that the target is absent from the picture
where it would have been.**

⛔ **RT0 and table indices 0..4 are untouched by construction**, so `MASK-TIE`, the delivered PNG,
`target_pixels`, `bbox_drawn_px`, ONSET, MASK-PICTURE-PAIRING and `G7` are unchanged and are re-run
as regression, not as new gates.

🚨 **This is a global-shader source change AND a shader-parameter-struct change ⇒ a FULL COOK
(`G129`).** ⇒ **NO leg in this campaign is valid pre-cook**, and the pre-cook/post-cook validity
table in §6 says so per leg rather than leaving it to be discovered.

### §1.2 🚨 THE BRIEF'S LITERAL RULE IS NOT SUFFICIENT, AND THE REASON IS ARITHMETIC — DECLARED HERE, BEFORE THE FIX EXISTS

The ruling says *"the whole-frame mean EXCLUDES the pixels of every live fire target's mask on that
frame"*. Applied **only to the current frame**, that does not remove the false positive, and the
arithmetic says why. Let `N` = frame pixels, `S` = silhouette pixels, `A` = mean over the complement,
`B` = the object's own mean, `C` = the mean of the background revealed when it is hidden.

- whole-frame mean, object visible: `M_vis = ((N−S)·A + S·B) / N`
- whole-frame mean, object hidden:  `M_hid = ((N−S)·A + S·C) / N`
- today's drop, hidden vs a visible window: `S(B−C) / (N·M_vis)` — this is what fires.
- **exclusion on the hidden frame only**: compares `A` against a window of `M_vis`, i.e.
  `S(B−A) / (N·M_vis)`.

⇒ **if the revealed background is representative (`C ≈ A`, the ordinary case for an object standing in
front of ordinary level content) the two are the SAME SIZE and the mark does not move.** The
exclusion must be applied to the window frames as well, and the window frames are mostly *unlabelled*
frames on which no target mask is ever armed (`m44`: masks appear only on frames labelled for that
event).

### §1.3 The shipped rule — AND semantics over two means, both computed on every captured frame

**A run-scoped, sticky exclusion region** is accumulated: the first time a live fire's target mask
resolves with pixels for that event's tag, those pixels are folded into a union bitmap
(`ExposureExclusionMask`, one byte per pixel at mask resolution). ⛔ The bench pairing-probe tag is
never folded in. Every captured frame then yields **two** subsampled means from one pass:

- `LumaAll`  — the whole picture, byte-identical to `m48`'s quantity.
- `LumaExcl` — the same subsample over the complement of the union.

**`exposure_dip` is marked iff BOTH tests fire** (each against its own rolling mean of the previous
8 captured frames, the `m48` window and threshold unchanged at 4.0 %).

🔑 **AND semantics can only REMOVE marks, never add them.** The defect being fixed is a false
positive, so a rule that is incapable of creating one is the right shape. Its cost is stated rather
than discovered: **a genuine auto-exposure dip can be missed for up to 8 captured frames after the
union first grows**, because `LumaExcl`'s own window then mixes two regions. That cost is bounded, it
is in the safe direction for the client (a missing warning flag, not a wrong label), and it is
**counted**: `frames_exposure_dip_suppressed` is the number of frames where `LumaAll` fired and
`LumaExcl` did not.

📌 **The suppression is a paired reading, not a silent absence.** `frames_exposure_dip` going 4 → 0
is only believable beside `frames_exposure_dip_suppressed` = 4 on the same leg.

⚠ **Why the sticky region is sound on this fixture and where it stops being sound:** at the AA-off
arbiter (Lumen / GI / reflections OFF) and with `m45` silencing shadows, a hidden target changes
**nothing outside its own silhouette**, so the complement mean really is invariant across the hide.
On a host with GI on, hiding a bright object also changes bounced light outside the silhouette, and
`LumaExcl` will move. **Phase B does not claim otherwise**, and the gate is run at the arbiter for
exactly that reason (`G228`).

## A1.1 `PB-4`'s `observable: false` clause is SUPERSEDED, and so is the whole veto design

§2.4 predicted that with the `m45` depth lever on, the affected rows would read
`target_drawn_pixels > 0` **AND `observable: false`**. The second half no longer exists: the
drawn-count no longer touches `observable` at all.

**Why, in one line: the milestone's own gate leg refuted the briefed design.** `PB0_SMOKE_try3` si 57

band of **167–168** — **the object was ABSENT from the picture while its depth was present.** `m45`
silences the main pass and the depth pass through separate flags, so `DrawnCount > 0` does not
establish presence. Using it symmetrically deleted a TRUE positive label. ⇒ the conjunct is removed
(commit `1c3d62c`); `target_drawn_pixels` and `frames_drawn_unexpected` ship as MEASUREMENTS.

✅ **The half of `PB-4` that matters is UNCHANGED and PASSED:** the lever drives
`frames_drawn_unexpected` to **16 in both tick orders** against **0 of 96** on natural legs, so
`PB-1`'s zeros are readings and not blindness (`G96`).

## A1.2 `PB-5a`'s predicted `0 / 0 / 0 / 0` was TOO STRONG

Measured **`1 / 0 / 0 / 0`** with `frames_exposure_dip_suppressed` **3 / 3 / 5 / 5**. The one surviving
mark (`PB1G_BL_NAT` si 53) was settled on the pixels: the picture **outside** the target's box fell to

plugin's own excluded reading (`73.267 vs 76.569` = 4.31 %) to two decimal places, while the inside-box
value stayed constant at **93.07**. **The mark is CORRECT; the prediction assumed a pinned-exposure
bench has no luminance excursions of its own, and that assumption is refuted.**

🔑 **And the miss is worth more than the prediction:** a clean four-way zero could not distinguish
*"the rule works"* from *"the detector stopped firing"*, so it would have left prove-it-can-fire
resting entirely on the AE-ON leg. The surviving mark **is** the post-fix can-fire proof on a pinned
leg. ⇒ **the criterion should have been "every mark attributable to the anomaly is suppressed", not
"the count is zero".**

## A1.3 🚨 FALSIFIER `F6` WAS TOO STRONG AND CONTRADICTED THIS PROJECT'S OWN RECORD
