## §5. Named limitation, declared before the gates rather than discovered after

**`EventClaimed` is never released mid-run**, by design — `mask_map.json` maps value → event for
the whole session, so re-using a value would make two events in one session ambiguous. With **55
assignable values** and **one permanent value per event**, a long enough run exhausts the pool
however much headroom the census leaves. **The headroom rule removes the measured cause (the census
taking the last free values); it does not and cannot remove that structural ceiling.**

⇒ **What `m50` changes is what happens WHEN the pool is exhausted:** the allocator now issues **no
tag**, the record is marked unmeasurable, no arm is made, the state stays `NOT_MEASURED`, the veto
admits, and the event ships honestly labelled. **The old behaviour was a confident wrong number; the
new behaviour is an honest absence.** `TAG-POOL EXHAUSTED` remains an `Error` line and a gate read.
