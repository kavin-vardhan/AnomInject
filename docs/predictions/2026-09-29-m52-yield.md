## 0. The answer in three lines

1. **Today's purity rule holds a texture only if exactly ONE component in the whole loaded world uses it** (two components
   of the target itself already fail), and **a refused `Apply` wastes the whole burst** (the picker draws one target and
   never retries). On our own MainWorld, **2 of 342** renderable actors own a private streamable texture.
2. **Option A (co-affected labelling, K = 8)** admits a texture whose users form a small family of maskable components,
   and every one of them gets its own mask value and label entry. **On StackOBot it barely moves the count**, because
   StackOBot's sharing is bimodal (1–2 users, or 165–315 users, almost all of them Nanite). Its value at the office
   depends on the office's own user counts, which its log already prints.
3. **A needs the picker pre-filter to deliver any yield** (B's mechanism, applied with A's rule): without it, a pool
   where 1 target in 6 can fire still wastes 5 bursts in 6. **A second wall exists independently of sharing: the 8×
   ratio gate needs a ≥ 512 px on-screen target** (the floor leaves a 64 px top mip).

## 1. Why it fires zero — from source

`Anomaly_StuckLowMip.cpp` at `02d15a4`, by function:

- **`Apply` → `BuildWorldTextureUsers` (the PURITY ENUMERATION, `:116-180`, called `:526-559`).** It walks every actor in
  every loaded level (`GatherLoadedLevels`, `:49-73`) and every primitive component plus decals, registered or not,
  visible or not. For each candidate texture it collects the user components.
- **`ClassifyPurity` (`AnomalyStuckMipWindow.h:564-593`)** returns `Pure` only if `NumUsers == 1 && Foreign == 0`. A
  target with two mesh components sharing one material is `Shared`. Refusal is `shared_world` (`:664-683`), per texture.
- **`baseline_pending` (`:686-697`)** refuses a texture whose stream operation is in flight. ⚠ It is counted inside
  `RefusedNotStreamable`, so the `HELD NONE` line reports it as "not streamable or already at the floor".
- **The ratio gate (`:720-754`, auto-pool only)** needs `longest on-screen side / top resident px ≥ 8.0`. With the
  deepest hold at the engine floor (7 resident mips, measured `floor_mips=7` on every held texture), the top mip is
  **64 px**, so the target must be **≥ 512 px** on its longest side.
- **`not_restored` (`:561-587`)** refuses a target whose texture a previous hold has not given back.
- **`HELD NONE` (`:839-853`)** returns false. ⚠ Its bucket text "shared with a visible component" is stale since 084-02:
  it counts whole-world `shared_world` refusals.
- **The hold monitor (`:1366-1637`)** reverts the hold and flags `stuck_mip.contaminated` when a new user of a held
  texture that the target does not own appears mid-hold (`EvaluateNewHoldUser`, window `:610-615`).
- **The picker (`AnomalyAutoInjectorSubsystem.cpp:199-400`)** draws the id, then one random visible target, and calls
  `ApplyAnomaly` once. A false return is a zero-match burst (`AnomalyCaptureSubsystem.cpp:5023-5032`). **There is no
  retry and no per-anomaly pre-filter hook.**

History: 084-01 found the wrong-object cause (the co-user count looked only at the visible, in-radius, above-6 % set,
and targeted fires bypassed it). 084-02 fixed it with whole-world purity. That fix is correct, and it is the yield
collapse.

### 2.5 `baseline_pending` exposure — reasoned from source, not measured on a moving camera

- **Home:** 0 `baseline_pending` lines on all 13 fix-branch MainWorld legs (settled camera).
- **The mechanism:** `HasPendingInitOrStreaming()` is true while a mip change is in flight. The streamer re-plans every
  `r.Streaming.FramesForFullUpdate` frames (5), and a texture's wanted mips change each time its on-screen size crosses a
  factor of 2, or continuously when the pool is over budget.
- **Who is exposed:** the textures the picker offers (≥ 6 % coverage, ≤ 18 m) are the ones whose screen size changes
  fastest under a moving camera.
- The refusal is **per texture**, so it zeroes a fire only when **every** candidate texture is in flight. That is
  plausible under pool thrash on a large level, and unlikely otherwise.
- ⛔ No rate is predicted. The office's `baseline_pending` count is the reading.

## 3. Option A — co-affected labelling (the owner's choice, K = 8)

Staged, so that the Thursday build carries the parts that the existing gate machinery can prove:

- **A-core, for Thursday:** §3.1–3.3, §3.5, §3.7–3.9.
- **A-ext, after Thursday:** §3.4 (mid-hold additions) and §3.6 (the settle-wait). Until then the existing behaviour is
  kept: revert + `contaminated`, and the `baseline_pending` refusal.

### 3.1 Admission (pick time; targeted fires included, as purity is today)

1. For each eligible candidate texture, take its world users `U(t)` from the existing enumeration (unchanged scope).
2. Classify each user with the table in §3.1a. **Refuse `t` if any foreign user is unmaskable** (reason
   `unmaskable:<kind>`).
3. Greedy, ascending by `|U(t)|`: admit `t` if `|Affected ∪ U(t)| ≤ K`, else refuse it (`over_cap`). `Affected` counts
   components, the target's own included.
4. The ratio gate is unchanged: the primary target at pick time. Each co-affected entry reports its own
   `stuck_mip.entry_ratio` per frame, as a reading and never a label input.
5. **K = 1 reproduces today exactly:** a candidate texture always has a target user, so the only texture that fits is one
   with that single user. That is the byte-level regression lever.
6. Knob `IAI.Anomaly.StuckMipCoAffectedCap` / ini `StuckMipCoAffectedCap`, compiled **8**, range [1..32], echoed at
   `StartRun`. The legacy `MaxCoAffected` stays the legacy-lever path only.

#### 3.1a Which users can and cannot be masked (UE 5.1)

| user | maskable | why |
|---|---|---|
| static mesh (non-Nanite), spline mesh, ISM/HISM (whole component) | **yes** | custom depth/stencil per component |
| skeletal / skinned mesh | **yes** | same |
| foliage ISM (as a co-user; foliage is never a *target*, m27) | **yes** | mask is exact; the box comes from the drawn mask |
| landscape component | **yes, unverified** | custom depth supported; needs a bench cell before it is claimed |
| **Nanite** mesh | **no** | the 5.1 custom-depth pass has no Nanite path (G134). A′ would label it with `target_pixels -1` |
| translucent material without `bAllowCustomDepthWrites` | **no** | never enters custom depth (m49 A2) |
| **decal** | **no** | no geometry of its own; the blur lands on the receiver's pixels, which carry the receiver's stencil |
| **Niagara / Cascade** particles | **no** | translucent sprites; custom depth not written (an opaque mesh renderer might be — treated as no) |
| text render / widget component | **no** | glyph/UI content |
| **UI/Slate brushes, UMG, HUD, post-process materials** | **not seen at all** | not components, so invisible to the enumeration. The UI LOD group is already excluded; a *world* texture used by a UMG brush or a post-process material would blur unlabelled. **Residual limit, stated.** |

### 3.2 Masks — one value per affected component

- **Primary:** the target keeps today's actor-level `TagActor` and its record (K = 1 byte-identical).
- **Each foreign co-affected component** gets its own record `(Id, StartFrame, component)` and its own value through a new
  `AnomalyStencilTag::TagComponents` (only that component, not its actor's others).
- **Records are born at `OnWorldTickEnd` of the fire's first frame** (m44 record-birth rule), like the primary's.
- **Why per component and not per event:**
  - per-entry `target_pixels` and `bbox_drawn_px` need per-value reduce counts;
  - the m50 `TAG-OWNER VIOLATION` gate (one value ↔ one actor, `AnomalyCaptureSubsystem.cpp:1231-1264`) keeps its meaning
    unchanged;
  - one value per event would force relaxing that gate to "one value ↔ one event", and would lose per-entry pixels.
- **Pool arithmetic:** 55 assignable values, census headroom 8. One stuck_low_mip event needs ≤ K = 8 values, and only one
  stuck_low_mip fire is live at a time (registry one-instance-per-id).
- **Recycling (084-05a, `ReclaimReleasableTag`)** releases values when the fire has ended and its trail no longer blocks.
  All of an event's records follow the same trail state, so they release together.
- **Exhaustion at arm ⇒ refuse the fire** (`mask_pool`). **Never mask partially**: a partial mask is the wrong-object
  defect again.
- **Ownership:** extend m44's rule to *"a component in a live event's affected set belongs to that event"*. The census
  skips it and `ArmTargetMaskOwn` re-asserts its value.

### 3.3 Labels

- **`labels.jsonl`:** per frame, the primary entry (unchanged), plus one entry per co-affected component **on frames where
  it is drawn**. Drawn means its value's reduce count > 0.
  - On an unmeasured frame (mask unavailable), the entry is emitted with `target_pixels -1` when its projected box is on
    screen (m49/m50 honesty).
  - Each entry carries its own `mask_value`, `target_pixels`, `bbox_px` (projected from the **component's** bounds) and
    `bbox_drawn_px`.
  - Additive keys, **only on co-affected entries:** `component_name`, `stuck_mip.co_affected: true`,
    `stuck_mip.entry_ratio`. Every other entry of every anomaly is byte-identical.
- **`labelled`:** from the one annotation authority. `IsAnnotationMember` / `RenderHeldWindow` membership comes from the
  event's render residency record, so every entry of an event has the same `labelled` on a frame, by construction.
- **`annotation.json`:** one event.
  - `affected_objects.nodes[]` gets one node per affected component, primary at `primary_index` 0. **This is a value
    change, not a shape change: `P6` does not move** (nodes already carry `asset_name` / `component_class` / `bounds`).
  - `frame_indices` / `injected_frames` stay event-level.
- **`mask_map.json`:** one entry per value, as now. `component_name` is added only on co-affected entries.
- **m26 veto:** keyed to the primary, unchanged. A co-affected component that never draws simply has no entries.
- **Readme:** §8.3a gains the three keys, and the rule: *"one stuck_low_mip event can list several objects; key entries by
  `(id, start_frame, target_name, component_name)`"*. §8.7 notes several mask values per event. The `HELD NONE` bucket
  text is corrected ("shared in the loaded world").

### 3.4 Users that appear mid-hold (A-ext)

- **Within K and maskable:** `EvaluateNewHoldUser` becomes three-way (Add / RevertNow / None). An Add allocates a value, tags
  the component **in the same tick** (the monitor runs in the injector's tickable tick, before `OnWorldTickEnd`, so the
  value is in place before that frame's arm), births its record at `OnWorldTickEnd`, and adds a node.
- **A lagging trigger:** the dirty-render queue, or a registration after the tickable tick, can mean the component drew one
  frame before it was seen. Then `ContaminatedFromSI` is set to the **previous** frame, so that frame is flagged. Never
  silent.
- **Above K, or unmaskable:** revert and flag `contaminated` per frame, exactly as today.

### 3.5 Timing (unchanged proof)

- One render residency record per held texture drives every entry. The event's membership per frame is computed once
  (`ComputeRenderMembership`) and applied to all entries.
- `partial` / `unresolved` / `temporal_aa` are computed per entry, from the same record restricted to the textures that
  entry's component uses.
- No new clock, no new sample site.

### 3.6 `baseline_pending` — bounded settle-wait (A-ext)

- A texture in flight at `Apply` is not refused at once. It goes to a `PendingJoin` list, polled each `TickAlways` for at
  most W frames (`IAI.Anomaly.StuckMipSettleWait`, compiled 8).
- When its operation clears, the baseline is read **then** (never before), the bias written and the texture appended to
  `Held`.
- The per-frame render watch is rebuilt from `GetRenderTruthTextures` at every arm (`FinalizeRenderTruthArm`,
  `:6021-6134`, with `ExtendRenderWatch` for same-tick joins). A late joiner therefore enters the record from its first
  armed frame, and the existing "ANY held opens / unknown is never clean" rules label it.
- After W frames without clearing: dropped, counted `baseline_pending_timeout`.
- If **every** texture is pending, the pre-filter (§3.7) has already skipped the target.

### 3.7 Picker pre-filter (required for yield)

- New `IAnomaly::IsTargetEligible(UWorld*, const AActor*) const`, default true. `TryFireOnce` applies it after drawing the
  id and before drawing the target, so there is still **one target draw per burst**.
- stuck_low_mip implements it with the §3.1 admission (one world scan per burst for the union of the candidates'
  textures; the runtime enumeration costs 1–5 ms).
- It also skips targets whose admissible textures are all pending or restoring.
- **Seeded selection changes for stuck_low_mip bursts only (a `G140` boundary on stuck_low_mip auto-pool legs); every other
  id's candidate list is identical.**
- K = 1 with the pre-filter **is option B**.

### 3.8 Interactions

- **m53 exclusion** (`EvaluatePartnerExclusion(FName Id)` on the m53 branch): id/family-level and target-agnostic, so it
  already covers co-affected actors. Unchanged.
- **MASK55 / recycling:** re-run the MASK55 leg with co-affected events, so that multi-value events are recycled. The pass
  bar stays `TagExhausted 0` and `TAG-OWNER VIOLATIONS 0`.
- **The office check kit** (`label_sync_check.py`) is per event today. It must read the extra entries (a kit change, owned
