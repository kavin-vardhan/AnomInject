## 3. The m52 ⟂ m53 exclusion, on m52's fixed lifecycle

### 3.1 Live, per side
- **m52 is live from Apply until its restore trail stops gating:** open ∧ ¬closed ∧ ¬unresolved (`GatesNextBurst`,
  `AnomalyStuckMipWindow.h:401-404`). "Closed" = a render record showed every held texture back at baseline (confirm run +
  fence); "unresolved" = `restore_unresolved` at the trail timeout. So m52 stays live after `BeginRevert` for as long as
  its blur can be in the picture (the owner's failure). A trail that **reopens**, even after detach (`BreakRun`,
  `:304-323`), is live again; adopted and carried trails count (`AdoptCarriedTrails`, ACS 6338).
- **m53 is live from Apply until its revert completes:** the live fire, plus its `post_revert` ledger reading still
  `not_yet_due` (R + 2 engine frames).

### 3.2 Where the check sits
- One pure rule in `Public/AnomalyExclusion.h` (states `fire_live | trail_open | restoring | revert_settling`).
- One injector predicate, `IsExcludedByPartner(Id, OutWhy)`. "Live" is the injector's `ActiveRecords` (every apply path
  passes through it), plus §3.3's residual signal.
- **Three call sites, all ahead of a draw:**
  1. `TryFireOnce`'s eligible-id loop (fix AAI 239-252): the id is dropped from `Eligible` **before** the id draw, so no
     m53 attempt happens and no mode draw is consumed.
  2. `TryFireSpecific`, after `IsIdLive` and before the hold draw (AAI 435 on).
  3. `ApplyAnomaly`, as the backstop for raw `IAI.Apply`, control-server `inject` and the selector, beside m52's existing
     `RefusedIds` check (fix AIS 714). See ND-3.

### 3.3 The residual signal (the inverted provider)
- The capture owns the trails and AnomalyInjector cannot call it (G127), so the capture registers a provider on the
  injector at `StartRun` and clears it at `FinishRun` / `Deinitialize` (the census-provider pattern). It answers
  `trail_open` for `stuck_low_mip` while any trail gates (live, reopened, adopted or carried).
- **With no provider** (free-running `IAI.Auto.Run`, between runs), m52 is `restoring` while its game-thread Restoring set
  is non-empty (`IsAwaitingRestore`). `revert_settling` comes from a new `AnomalyTexCorrupt::IsRevertSettling(UWorld*)`
  over the pending ledger (same module).

### 3.4 The RNG contract (P2-8) holds
- An excluded id never becomes an attempt: exactly one mode draw per m53 attempt, none for non-m53.
- An all-excluded pool returns before any draw, as today's empty `Eligible` does (AAI 253-256), and logs
  `Auto.Draw … result=all_excluded` with `seed_after == seed_before`.
- The stream depends on exclusion state exactly as it already depends on `IsIdLive`. `Auto.Draw` carries
  `eligible=<n>:<fp>` and a new `excluded=<ids>`, so G-SEED's replay stays exact.

### 4.1 When the picture does not change (normal modes; uv on flat textures)
- **The problem:** an inverted or green-flipped normal changes shading only where the lighting has a tangent-plane
  component. Under flat, head-on or back lighting the picture barely moves, and the label is a false positive. `tile` /
  `scramble` on a near-uniform texture has the same shape.
- **`observable` cannot carry it this delivery.** It measures silhouette pixels and install state, not appearance. The
  only in-product appearance reading, m55's `change_evidence.jsonl`, covers a phase's first four labelled frames, refuses
  on non-default capture settings and by contract changes nothing else; folding it in would make `observable` change
  meaning with capture settings, and G258 bars a diagnostic from becoming a label input. A true per-frame test needs an
  uncorrupted render of the same frame: new GPU work, not by Thursday.
- **Proposal (ND-5):** (1) B-M53 measures the rate on realistic content: per mode, the share of MainWorld events judged
  NOT-MEASURABLE at t50 and at strict. (2) The readme states the limitation with that rate, plus a recipe: drop an m53
  event whose m55 event line has a small `ref_gt8_max / chg_n` (the threshold is the client's). (3) The rate feeds the
  owner's Thursday default-on decision. (4) Next delivery: a two-sided-calibrated pre-apply lighting screen (the m30
  pattern), or an event-level `effect_change` key — never `observable`.
- On the **fixture**, a NOT-MEASURABLE event is a **FAIL**: the cells are built to change.

## 7. All-or-nothing (IN 5)

  **New V1P between them:** `0 < qualified < slots` → `partial_footprint`, sub
  `<qualified>/<slots>:<earliest non-qualifying reason>` (e.g. `12/30:not_fully_resident`).
- **Precedence:** E1–E7 > per-slot steps > V1 > **V1P** > V2 (the full footprint's budget) > allocation. So a partial set
  never reports `over_budget`, and a fully refused set keeps its specific reason.
- Every slot is still logged; none is touched and no RT is allocated. `texcorrupt_refused_partial_footprint` is always
  emitted.
