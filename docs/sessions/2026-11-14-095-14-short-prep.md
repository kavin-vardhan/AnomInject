## 2. Findings and decisions inside the brief
1. **G5 could not see the change it was asked to allow** (G583). The node name lives in `annotation.json`; G5 read
   `labels.jsonl` only. The amendment adds a node-identity check (events joined by `event_id` as a frame offset;
   `affected_objects` must be equal apart from the control pair's run-unique node fields) with the allowance on
   `asset_name` / `component_class` only. An event one session lacks is a reading, never a failure (vetoes and refusals
   can differ between builds). Missing `annotation.json` or `event_id`: exit 2.
2. **The allowance is wider than the ruling's words, on purpose and listed separately.** `Anomaly_TexCorrupt.cpp` sets the
   component scope when parts were skipped **or** on every `stuck_low_mip` proxy-route fire, so both rename. Causes:
   `texcorrupt_skipped_parts` (an entry carries `texcorrupt.components_skipped` > 0) and `stuck_mip_proxy_route`
   (annotation `stuck_mip_route` `proxy`), read from the newer session. LOD events are not covered (G5 legs use
   fire-window types).
3. **C4 with the down-pop on is now simulated, not only computed:** `TestBenchSimulation` runs approach_retreat at
   config `2 60 120 14 0` with the switch off and on; both read one fire at 59, labelled 128..132, one up swap at 133, no
   re-hold, nothing labelled on the retreat. A run with `LodDownPop 1` can be told from the default only by the settings
   echo.
4. **`run_summary` has no per-trigger event count.** Ruling 095-13 D2 says "the per-mode event counts in run_summary";
   the readme line names the fields that exist: `lod_swaps_by_cause` (`distance`, `view_entry`), each event's
   `anomaly_subtype`, and the `Auto.Yield` refusals. No code change.
5. **Fixture placement.** `CB_LodPair` at (1000, −/+150, 600), scale 1 (MeshLod = `SM_LodFix_N`, MeshOne = engine Cube);
   `CB_LodFix_MinLod1` at (1100, 0, 390), scale 1.5 (a 4.6 copy would block the second pair and stand on the distance
   paths). Checked offline with conservative bounding spheres: both fully in the bench view, neither blocks an existing
   target from the bench pose or any `lod_v1` path pose, no camera path passes through them. The component naming uses
   `rename_subobject`, then `Object.rename`, and fails before saving if neither takes.
