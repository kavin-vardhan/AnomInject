### Ambiguities ratified (all as recommended)
- **AMB-1 — skinned LOD-count accessor → `USkinnedMeshComponent::GetNumLODs()`** (component-level,
  runtime render-data count), **not** the brief's candidate `GetSkeletalMeshAsset()->GetLODNum()`
  (asset-authored count, can diverge on a cooked/stripped mesh). It is the true analog of the static
  `UStaticMesh::GetNumLODs()` we already use and the right number for G15's runtime-LOD reasoning.
  Verified in 5.1 source: `SkinnedMeshComponent.h:828`, impl returns `RenderData->LODRenderData.Num()`
  (`SkinnedMeshComponent.cpp:3412`). Settled in **gotcha G19**.
- **AMB-2 — per-target record → single tagged record keyed to `UMeshComponent` + internal `Cast<>`
  dispatch** (not two typed lists). `UMeshComponent` is the verified common base
  (`UStaticMeshComponent : UMeshComponent`; `USkinnedMeshComponent : UMeshComponent`;
  `USkeletalMeshComponent : USkinnedMeshComponent`). This is what makes "one apply handles a static
  prop + the skeletal Bot" fall out for free — proven live (see gates).
- **AMB-3 — `lod_popping` default 2 Hz, ceiling 30 Hz.** A fast LOD pop blurs into noise; the discrete
  snap needs dwell time, so the lower ceiling vs flicker (60 Hz) is intentional.
- **Cosmetic Hz-parse divergence left as-is:** `lod_popping` parses Hz via `GDPArgs::GetFloat`;
  `flicker` keeps its M1 inline parse (validated code untouched — no refactor for a cosmetic diff).
