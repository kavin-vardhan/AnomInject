## 2. camera_clipping: bounds broad phase, triangle confirmation (ruling 2, F2 folded in)

- **Design.** SAT on the oriented render box stays the broad phase. Every SAT-positive component — and every SAT-positive
  ISM instance — becomes a candidate. `AnomalyNearClipSlab::ConfirmSlab` casts a **16×9 grid of view-ray segments from the
  baseline near plane to the anomalous one**, clips each to the candidate's box (`ClipSegmentToBox`) and traces only the
  clipped part with `FBodyInstance::LineTrace(..., bTraceComplex = true)` on **that candidate's body** (per-instance body
  for ISM; the `ULandscapeHeightfieldCollisionComponent` for landscape, read through the render component's
  `CollisionComponent` UPROPERTY, so no `Landscape` module dependency). A candidate crossed by fewer than 6 grid rays also
  gets a 4×4 grid over its own screen footprint (`BoxFootprint`). Any hit ⇒ positive, not flagged.
- **Unconfirmable ⇒ SAT stands + flag.** `ResolveConfirmTarget` decides BEFORE tracing (G360): skinned → unconfirmable;
  collision `NoCollision` or no valid body → unconfirmable; no cooked triangle mesh (`ChaosTriMeshes` empty) or
  `CollisionTraceFlag == CTF_UseSimpleAsComplex` → unconfirmable. Over 16 candidates, over 320 traces, or a candidate no ray
  reached: unconfirmed. If no confirmed hit exists and any candidate is unconfirmed, the frame stays positive and carries
  `transition: 1`, `transition_reason: ["camera_clipping_unconfirmed"]`, `camera_clipping.unconfirmed: true`. All candidates
  traced with no hit ⇒ **negative** (the hollow-mesh case).
- **Per frame:** `camera_clipping.bounds_candidate`, `.clipped_ray_fraction` (share of the 16×9 global rays that hit),
  `.confirm_traces`, `.confirm_hits`, `.confirm_misses`, `.confirm_unresolved`. **run_summary:** rule
  `view_slab_bounds_then_triangle_confirm_v2`, bounds-candidate / confirmed / unconfirmed / rejected-by-triangles frames,
  traces total/max, unconfirmable split (landscape, skinned, no-collision, no-complex, over-cap, trace-capped, no-ray),
  `camera_clipping_confirm_us_mean_per_labelled_frame`, `_per_candidate_frame`, `_us_max`, budget 500.
- **Cost.** The confirmation's own grid and clipping overhead measured standalone: **16.4 µs per frame at 16 enclosing
  candidates** (2,304 trace requests, trace stubbed). ⛔ **The trace cost itself cannot be measured without the engine;
  the ≤ 0.5 ms mean assertion moves to the next bench** and is instrumented for it. Worst case is bounded by the 320-trace
  cap (a frame over it flags rather than labels a guess).
- **What it can miss:** a sub-grid sliver belonging to a LARGE candidate (e.g. a 0.4 cm pole inside a room mesh) falls between
  the 16×9 rays and reads as a miss — a documented selftest case. Small candidates are covered by their footprint grid.
  Translucent/masked surfaces are traced as solid; geometry that renders but has a different collision mesh is judged by
  its collision mesh.
- **F2.** ISM instances no longer come from `GetInstancesOverlappingBox` on plain ISM (translation ± unscaled mesh extent —
  Codex's counterexample). HISM uses its own query only when its cluster tree is built (the engine override transforms each
  instance box); otherwise every instance is enumerated with its full transform and tested `InstanceBoxMayTouchSlab`
  (AABB then SAT). Counters `HismTreeQueries`, `IsmFullScans`, `InstancesTested`.

## 3. F3 — the sync capture path (inherited): fixed

- **Why it differed:** `CaptureLabeledShot` built the row from `Auto->GetLiveFires()` alone and wrote it; only afterwards did
  `CaptureCurrentFrame` append the session globals and accumulate them into `annotation.json`; `bPositive` counted the auto
  fires only; and the sync path derived hide activity from `AActor::IsHidden()` — which the m45 invariant forbids and which is
  false for `blinking`/`missing_object` (they do not call `SetActorHiddenInGame`), so a sync frame recorded no hidden frame.
  Sync rows also got no hide-return processing.
- **Fix:** one `FCaptureSnapshot` is built first — auto fires, non-view globals, view-dependent globals via
  `AppendViewDependentGlobals` (the slab + confirmation, same counters as async), `FireActive` from `ComputeFireActive` (the
  logical-hidden registry), `FireLabelled`, `StepHideTransitions` — and the row (`CaptureLabeledShot(..., &SyncFrame)`), the
  event accumulation, the entry/reason counts and the positive count all come from it. `run_summary.sync_frames_written`.
- **Were delivered labels affected?** Reachable in delivery through the per-tick fallback (viewport rect unresolved) or
  `IAI.Capture.Async 0`. **Not observed on the bench:** 0 of 88 banked 084-03/084-06 sessions contain a sync-shaped row (a
  row without `mask_state` in a target-mask run). Fixed regardless; the engine-side assertion (a sync leg writes the same
  event set as its annotation) moves to the next bench.

## 4. F4 — mask-ID retirement

`AnomalyStencilTag::RetireStencilValue` walks every TRACKED holder (`GTaggedComponents`, by saved identity, not the old actor's
current components): a holder still carrying the value is restored — value and flag if its custom depth is on, **value only
if the host turned custom depth off** (the host's decision kept). It then verifies no tracked component and none of the old
actor's components still carries the value. `ReclaimReleasableTag` tries victims in order; a value that fails verification
is **quarantined** (stays event-claimed, never issued) and the next releasable value is tried
(`mask_tag_retire_quarantined`, `mask_tag_retire_host_flag_kept`, log `TAG RETIRE UNVERIFIED`).

## 5. F5 — transition history across a run boundary

At `FinishRun` (after the drain) `CarryLabelSyncAcrossRun` keeps every transition track whose event continues (attached
trail) or whose off window is unfinished, rebased so the next run's first frame is adjacent (`CarryTransitionTrack`), and
every hide track still hidden or owing frames. `ResolveLabelSyncForRun` adopts them after its reset; detached tails re-enter
through `CarriedTailFires`. The remaining onset allowance is carried as the actual earlier members, so it no longer collapses
into "onset already passed". The boundary is treated as uninterrupted, which can only add flagged frames. A −1 sentinel bug
this exposed is G359.

## 9. Deviations, limits, NEEDS-DECISION

- **Ruling 1 guard vs this data:** the partial flag is residency-derived, so it fires on exactly the frames whose record
  shows a partial set — including frames the picture shows at 6–9 % (084-06 order). Ruling 1 counts a partial-flagged onset
  frame under 10 % as **label-early**. If the next bench repeats 084-06's order, ~6 of 16 events will carry 2 label-early
  frames each although the record proves the set is partially held (diffuse + AORM at the held level). Chat decides whether
  that count is intended as a finding or whether the < 10 % rule should read the render record.
- **Warm-up events exceed 3 partial frames on an edge** in both banks (onset 5 in each). The gate's "> 3 ⇒ investigate"
  will fire on them unless the harness keeps excluding warm-up events.
- The camera_clipping confirmation cost is unmeasured in-engine (by construction here); it is instrumented for the bench.
- `visible_positive` changes value on existing families (§6). Consumers that treated it as "an event is active" must read
  `anomaly_present` instead; `verify_capture.py` and the harness should be checked against the new rule before the bench.
