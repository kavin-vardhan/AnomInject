## M2.6 — MCP bridge sever (Bridge-on-5.1)

### Diagnosis
The bridge (GenOrca **UnrealMCPython**, `GenOrca/unreal-mcp`) **targets UE 5.6+** and does not build on 5.1.
Sequence of breakage: missing `BehaviorTreeEditor` private/Classes include paths → then a missing
`#include "Async/Async.h"` → then **7 `LNK2019` unresolved externals** for the `BehaviorTreeEditor`
graph-node UCLASSes (`UBehaviorTreeGraphNode`, `UBehaviorTreeGraph`, `_Root/_Task/_Decorator/_Service/
_SubtreeTask`), which lack `BEHAVIORTREEEDITOR_API` before 5.6 → unexported, unlinkable. This is the G8
SimpleParallel issue **generalized to 7 symbols**.

### Severability finding → route decision
The BT coupling is isolated to **one Python router** (`behavior_tree_router.py`) + **three C++ functions**
(`GetSelectedBTNodes`, `CreateBTGraphNodeRecursive`, `BuildBehaviorTree`). Our needs — `execute_python`,
Output-Log reads, actor/component state reads — have **zero** BT dependency. Routes weighed:
(a) **sever** the BT dep (no engine change), (b) engine-side export patch (rejected — per-sync tax on the
shared engine that builds the real target games, for an unused feature), (c) fork/lean bridge (deferred —
the future capture/replay harness is custom on any bridge; revisit then). **Owner chose (a).**

### Sever (implemented)
`UnrealMCPython.Build.cs`: dropped `"BehaviorTreeEditor"`. `MCPythonHelper.cpp`: removed the editor-graph
`#include`s; `#if 0`-compiled-out the 3 editor-graph functions; replaced the 2 public UFUNCTIONs with
"unsupported on 5.1" JSON stubs. `behavior_tree_router.py`: marked the 2 tools unsupported. Kept the
`Async/Async.h` fix. **Dropped 2 tools:** `build_behavior_tree`, `get_selected_bt_nodes`. **Retained the
4 runtime-BT read tools** (`get_behavior_tree_structure`, `get_bt_node_details`, `list_bt_node_classes`,
`set_blackboard_to_behavior_tree` — AIModule runtime, exported). Full detail + restore-on-5.6 recipe in G8.

**Result:** bridge **compiles, links, loads clean on 5.1**; `LogMCPython: TCP server started at
127.0.0.1:12029`. The bridge folder is **not under version control** (host tooling, unversioned).
