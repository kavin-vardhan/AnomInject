## 2. Decision 1 — every fire changes exactly the actor its label names (`8d4732b`, integ)
- **New token `@<path>`** in `AnomalyTargeting::FindActorsMatching`: the one actor whose `GetPathName()` equals the text
  (compared only where the short name equals the path's last segment). `MakePathToken`, `CountActorsNamed`,
  `DescribeFirstPaths` added.
- **The pool, `TryFireSpecific` and the selector** apply with `@` + the target's path. Every anomaly still resolves its
  target through `FindActorsMatching` (`IAnomaly` unchanged), so it now finds that actor only. `Fire.TargetName`,
  the labels and `annotation.json` are unchanged (`nodes[].path` was already the path).
- **Targeted capture:** a bare or `=` name that matches more than one actor (name or class) is refused
  `target_ambiguous:<n>`; the log lists the first three paths and suggests `@<path>`. Unique names work as before.
- **`ApplyAnomaly`** (every caller, object scope): a text that is exactly the name of more than one actor is refused the
  same way. A substring that is no actor's exact name keeps its documented meaning (`SM_Ramp` → 2 actors, an old gate);
  `=ClassName` keeps its class meaning when no two actors share that text as a name. Apply-level reasons are kept in
  `ApplyLevelRefusals` and returned first by `GetAnomalyLastRefusalReason`, so `Auto.Yield` names them.
- `camera_clipping` reads an `@` token as targeted mode; the capture's session-global targeted path and the texture
  uniform kick keep an `@`/`=` prefix as given.
- Pool candidates sort by name, ties by path (only namesakes tie; a seed draws the same where names are unique). The m57
  lod candidate list got the same tie-break in decision 4's commit.
- Not changed: the read-only texture census (`IAI.TexCorrupt.Census`) still builds `=name` tokens per visible actor, so
  on a host with repeated names it evaluates namesakes together. It is diagnostics only; its output format is read by
  office tools.

## 3. Decision 2 — host-hidden actors refused, `target_hidden` (`4f940be`, integ)
- `IsRenderableComponent` is false when the owner is hidden by the host: `AActor::IsHidden()` and not hidden by the plugin.
  The plugin's pre-m45 bench hide is now tracked (`AnomalyHiddenClass::IsHiddenByPlugin`); the m45 hide never sets the flag
  (G589).
- The picker (`ClassifyRenderableVisibleLive`) logs `EXCLUDED-HIDDEN` once per actor in view (frustum and poll radius, no
  traces) and counts distinct actors: `run_summary.hidden_excluded_targets` (additive).
- `TryFireSpecific` and `ApplyAnomaly` refuse `target_hidden` when the actor is host-hidden or has at least one static or
  skinned mesh and none visible (a light actor has no mesh and is never hidden by this rule). A multi-actor substring
  apply is refused only when every match is hidden.

## 4. Decision 5 — HLOD proxies refused, `hlod_proxy` (`b67dfba`, integ)
- `/Script/Engine.LODActor` and `/Script/Engine.WorldPartitionHLOD` are resolved once by path (no header, no module, like
  the m58 landscape lookup). `IsRenderableComponent` is false for a component whose owner IsA either. The picker logs
  `EXCLUDED-HLOD-PROXY` and counts `run_summary.hlod_proxy_excluded_targets`; `TryFireSpecific` and `ApplyAnomaly` refuse
  through one rule, `AnomalyTargetPolicy::DecideTargetEligibility` (hidden is reported first). The capture logs an
  `HLOD RULE` line at run start naming which paths resolved. The texture search is not widened.

## 5. Decision 6 — terrain-only blink ceiling (`37d61ce`, integ)
- In the pool, a census `above_ceiling` verdict is re-admitted only for `blinking` on terrain (m58 rule) whose measured
  drawn coverage is at or below `IAI.Blink.TerrainCeilingPct` / ini `BlinkTerrainCeilingPct`, compiled 25 (the census
  default, so nothing changes). Range [0..100], refused not clamped. On the `TERRAIN RULES` line; `TERRAIN-CEILING` logged
  once per actor. Pure rule `AnomalyTerrainRule::ReadmitAboveCeiling`.
- Readme commit `440a2ef`: the target forms, the refusals, the terrain ceiling (the office tests 40 % before a default),
  five 2.2 changelog rows.

## 6. Decision 3 — `lod_corruption` contrast and coverage (`b2d7f2c`, m57)
- `GetForcedLodContrast` (used only by `lod_corruption`) takes the shown LOD from `PredictEngineLod` for a static mesh;
  under a dither the coarser of the engine LOD and the two temporal samples counts; no prediction =
  `current_lod_undetermined`. Then `not_coarser_than_current`, then **`no_contrast_lod`** unless triangles[forced] × 4 ≤
  triangles[shown], then **`below_min_coverage`** under `LodPoppingMinCoveragePct` (7 %, component bounds coverage, the
  m57 function). Every fire (lod_corruption is targeted-only). Counted per kind; dominant reason to `Auto.Yield`.

## 7. Decision 4 — spatial LOD trigger (`9f70d22`, m57)
