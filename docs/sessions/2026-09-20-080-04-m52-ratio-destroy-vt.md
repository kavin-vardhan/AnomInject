## 4. 🚨 G4e worked on its first run, and the first thing it found was a pre-existing defect

The lever, the binding and the restore all did what `R4` asked, in one engine frame:

```
[ 44] IAI.Bench.DestroyTarget: DESTROYING 'StaticMeshActor_..._2044254803' now - ... an anomaly has
      been measurably anomalous for 3 tick(s), so this destruction lands MID-WINDOW
[ 44] stuck_low_mip: TARGET LOST - '...' ended play (destroyed or removed from the level) while 6
      texture(s) were held for it. Reverting NOW ...
[ 44] stuck_low_mip: revert of 6 held texture(s) - restored=6 left-to-game=0 unresolved=0
[ 49] stuck_low_mip: RESTORE VERIFIED 'T_rock_02_AORM' resident 11 >= baseline 11 after 4 frame(s)
```

**The delegate used is `AActor::OnEndPlay`** (`Actor.h:2016`), broadcast at `Actor.cpp:2652` from
`RouteEndPlay`, which `AActor::Destroyed()` calls first (`Actor.cpp:2692`, before `OnDestroyed` at
`:2695`), reached from `UWorld::DestroyActor` (`LevelActor.cpp:872`). `OnEndPlay` was chosen over
`OnDestroyed` because it is **strictly more general** — it also covers level removal and world
teardown — and it fires **earlier** in the destroy path. A weak-pointer poll in `TickAlways` is the
backstop for garbage collection, which no delegate covers.

🚨 **AND THE FIRST RUN FAILED HALF OF `R4`'s CLAUSE, FOR A REASON THAT PREDATES `m52`.**
The A-side leg (binary `F65A8C90`) produced:

```
injected=[35, 36, 37, 38, 39, 40, 41]   affected=[35, 36]   unheld-in-window=[37, 38, 39, 40, 41]
```

Frames 37–41 carry **no anomaly entry in `labels.jsonl` at all** — so `IsFireLabelledThisFrame` was
already correct — while `annotation.json` claimed them as injected. The cause, read from source:

```cpp
if (Source == EAnomalyActiveSource::AnomalyState)
{
    return !FActor ? 1 : (... IsAnomalyCurrentlyAnomalous(F.Id) ...);   // ComputeFireActive
}
```

**A fire whose target actor is gone was counted ACTIVE without the anomaly being consulted at all.**
That is correct for a **GLOBAL** anomaly — `camera_clipping` has no target by design — and exactly
backwards for an object-scoped one, where it means *"the object has ceased to exist, therefore the
anomaly is present"*. It over-claims, which is the dataset-poisoning direction.

**Fixed by discriminating on `F.bWholeFrameExtent`**, the flag the accumulator at `:5677` already
uses for exactly this distinction. **Blast radius is structural, not argued:** only two anomalies
are `AnomalyState` — `camera_clipping` (global, `bWholeFrameExtent` true, returns 1 as before) and
`stuck_low_mip` (object-scoped). **No other anomaly in the catalog can reach the changed branch.**

**A/B on the same recipe, one code change between them:**

| | A-side `F65A8C90` | B-side `5588F6FB` |
|---|---|---|
| `injected_frames` | `[35,36,37,38,39,40,41]` | `[45,46]` |
| `affected_frames` | `[35,36]` | `[45,46]` |
| `unheld-in-window` | **`[37,38,39,40,41]`** | **none** |

⚠ **The two legs are NOT frame-matched and that is stated rather than glossed:** the destroy latch
fires once a hold is measurably live, and the streamer's schedule varies run to run, so the two
legs destroyed at different bursts (1 held texture vs 6). **The decisive quantity is internal to
each leg** — whether `injected_frames` extends past the last held frame — and it does not depend on
which burst was hit. `F65A8C90` is archived and is **LOAD-BEARING as this A/B's A-side**.

**On Lyra at the bench override `MaxCoAffected 8`, three events read `NO-TRACE` with ratios of
26.76, 26.76 and 31.59 — three to four times the gate `R1` just raised.**

These are large objects (968–1537 px on screen), held to a 64 px top mip, with 131k–146k measured
target pixels, `held:true` on every labelled frame — and the verifier finds no change above the
noise floor. ⇒ **the footprint/mip ratio cannot see TEXTURE CONTENT.** A low-frequency paint or
normal map is imperceptible at any achievable mip, and no pick-time predicate computed from bounds
and mip sizes can know that.

✅ **It is NOT a regression, and that is measured rather than assumed.** The 080-03 banked Lyra
bench-override leg, on the OLD binary `DC8BA0C1`, reads **`NO-TRACE 2` of 3 events, exit 2** on the
same tool. **080-03 never ran the verifier on its Lyra legs**, which is the only reason this went
unreported. Same shape both times: the `Cube*` targets read NO-TRACE, the character does not.

✅ **It is NOT reachable at the shipped configuration.** All three Cube events carry
`co_affected_visible = 4`, so at the shipped `MaxCoAffected 0` they are refused as shared — and
Lyra leg 1 at the shipped default reads **1 event, `NO-TRACE 0`, exit 0**. **Nothing in this
session produced a NO-TRACE at a configuration the client would receive.**

🔑 **Three consequences, stated and not acted on:**
1. **`R2`'s escalation target is now supported by direct measurement.** `m55` — an in-engine
   per-frame measurement of the target's own change fraction — is the only thing that separates
   these cases, because the distinguishing fact is in the pixels and nowhere else.
2. **The shipped `MaxCoAffected 0` is doing real work beyond neighbour purity**: it happens to
   exclude exactly the class the ratio gate cannot judge. That is luck, not design, and it should
   be read as an argument against raising the cap rather than for it.
3. **It bears directly on S2'** (AMENDMENT 3 §A3.6), whose whole point is to admit co-affected
   actors — the same actors that produced these three NO-TRACEs.

⛔ **CAUSE NOT ESTABLISHED BEYOND THE ARITHMETIC AND NOT CHASED** (`G120`). The ratio was NOT
tuned, `MaxCoAffected` was NOT raised, and no default moved on this reading.
