## 2. A — F1

**The rule.** `AnomalyLabelSync::IsAnnotationMember(Policy, bActive, bOnScreen, bInstalled)`: for `FireWindow` it returns
`bOnScreen && bInstalled`; the other policies ignore `bInstalled` and keep their own authority. `DecideInterruptedEntry` turns a
`Normal` FireWindow entry whose effect is not installed into `TransitionOnly`; a `Suppress` entry stays suppressed.

**The installed bit and where it is sampled.** It is the anomaly's own `IsVisualConditionHeld()` through
`UAnomalyInjectorSubsystem::IsAnomalyVisualConditionHeld(Id)` — already sampled per fire as `Snap->ConditionHeld` in
`SampleDeferredActiveState` (the `OnWorldTickEnd` point where the activity bit is taken). For `missing_texture` and
`corrupted_texture` it is "our checker / pink material (or a MID of it) still on every captured slot"; on m53 for
`uv_corruption` / `normal_corruption` it is "our MID on every committed slot and every RT binding reading back". A raw
revert sets the anomaly inactive, a host swap replaces the slot, a teardown leaves no live slot — all three read false.
The sync capture path did not sample it; it now does (same call).

**Where it is applied (one authority, three consumers):**
- `AnomalyLabel::MarkInterruptedEffects(Snap)` at the end of `FillAnnotationInputs` (both paths) → the entry is
  `TransitionOnly` with `ReasonEffectInterrupted`;
- `AnomalyLabel::IsFireInAnnotation(..., FireInstalled, i)` → the row's `labelled` and `AccumulateFrameEvents`'
  `MemberByIndex` (hence `injected_frames`);
- `IsFireLabelledThisFrame` (FireWindow default case) → mask arming, `m26` arms and the change stage stop on the same frames,
  which keeps the m44 rule (masks only on labelled frames).

`run_summary` gains `label_transition_effect_interrupted_entries`; `label_labelled_rule` is now
`annotation_membership_per_policy_v2_effect_installed`. The reason arrays went from 5 to 6 entries with a `static_assert`.

**Cost.** Instrumented, not yet measured on a run: every installed check inside `IsFireLabelledThisFrame` is timed with
`FPlatformTime::Cycles64`, and the run log prints `Capture(F1): EFFECT-INSTALLED CHECK calls=... total=... us mean=... us
max=... us`. Tonight's smoke reads it. By construction the check is one `TMap` lookup plus, per targeted slot, one
`GetMaterial` and a short parent walk (texture swap) or one `GetTextureParameterValue` per binding (m53), a few times per
live fire per captured frame.

**The m53 exclusion's "live".** An interrupted m53 event **still counts as live for the m52/m53 exclusion until its
retained entry clears** (the scheduled end plus pending snapshots). The rows keep carrying the m53 entry — now
transition-only — and the co-entry rule counts any m53 entry, labelled or not. So F1 moves `labelled`, not the exclusion.
`exclusion_selftest`'s raw-revert case was updated: labelled 10..19, `effect_interrupted` 20..39, admission of a forced m52
fire still at 40 (latency 1) / 42 (latency 3), no co-entry. That was the old expectation "m53 labelled on 10..39", replaced.

**Tests both ways.**

  labelled, 20..39 transition-only `effect_interrupted`, and the old rule labels 10..39 so it must disagree); host
  replacement at 15 with our re-install at 18 (labelled 10..14 + 18..24, flagged 15..17); off screen and installed →

## 3. B — the Nanite skip

**The setting.** `IAI.Targets.AllowNanite <0|1|default>`, ini `[AnomalyInjector] AllowNaniteTargets`, compiled default
**0 = refuse**; console beats ini beats compiled; the first read echoes the value and its source; `run_summary` writes
`nanite_target_policy` (e.g. `refused(compiled)`).

**The predicate.** A target is refused when **any** of its renderable components (`AnomalyViewport::IsRenderableComponent`)
renders as Nanite. The per-component test is the capture module's existing `AnomalyMeasurability::ComponentRendersAsNanite`
— the same one the unmeasured contract uses — registered with `AnomalyViewport::SetNaniteComponentProbe` at
`AnomalyCapture` startup and cleared at shutdown (G429: `ShouldCreateNaniteProxy` is protected, and re-implementing it would
put RenderCore into `AnomalyInjector`). The pure decision is `AnomalyTargetPolicy::DecideNanite(bAllow, renderable, nanite)`.
The old unmeasured contract applied only when **every** renderable component was Nanite; the new refusal also removes mixed
actors, whose masks were partial.

**Where it applies.**
- **Auto-pool:** in the candidate loop, right after `IsActorLive` and before the census consult — so before
  `RandHelper(Candidates)` on the fix branch and inside the `CandidateCount` lambda before `TexCorruptPure::DrawAttempt` draws
  the target on m53. Not at the G33 chokepoint, so the census still sees Nanite candidates (`census_unmeasurable_nanite`).
- **Targeted fire:** `TryFireSpecific` after the target is found and before the hold draw (`TargetedAttempt` on m53), so a
  refused targeted fire consumes no random number. Session globals are exempt.
- **`ApplyAnomaly` backstop:** for object-scoped ids, every actor the target token matches is checked; any Nanite match
  refuses the whole apply (on m53 before the partner exclusion, so a Nanite refusal never enters the exclusion accounting).
- **m53 decision tree:** event step `E7N` after `no_mesh` refuses `nanite_unmaskable` through the read-only
  `ActorDrawsAnyNaniteReadOnly`, so the office census counts it as its own reason (format unchanged, `v1`).
- `camera_clipping` has no target and is untouched.

**Accounting.** One `REFUSED-NANITE` Warning per actor per run (every time for targeted and apply); `refused_nanite` =
distinct actors; the run end logs `Capture(090-05): NANITE TARGETS REFUSED = N distinct actor(s) (M refusal(s))`.

**The RNG contract and the KAT.** The filter runs in the loop that builds the candidate list, so the stream is consumed in
exactly the same order: when no Nanite actor is visible, the draws are identical; when some are, the target index is drawn
over the survivors; when all are, the attempt takes the no-candidate path after the id draw.
- Fix branch `tools/target_policy_selftest.cpp` **25 / 0**: with seed 4242, the known answers of m53's KAT rows
  `non_m53_no_mode_draw` (id 0/1/0, target 5/4/4 of 7, hold bits, seed after `D69ED00F` / `ABE074E8` / `79A8096D`, 3 draws)
  reproduce with the filter on and no Nanite; with 2 of 7 Nanite: still 3 draws and the same seeds after, targets **index
  3 of 5 = Rock5 / Rock5 / Rock5** (computed by the independent Python stream `tools/texcorrupt_draw_kat.py` — my first
  declared answers were written before computing them and were wrong, and the test caught it); all Nanite: 1 draw each;
  setting 1: byte-identical to the unfiltered protocol.
- m53 `texcorrupt_draw_test` **987 checks**: the same three cases on the production `TexCorruptPure::DrawAttempt`; its 8
  draw mutants fail.
- Mutants of `AnomalyTargetPolicy.h`: ignore the setting (decision) → FAILS; ignore the setting (filter) → FAILS; ignore
  Nanite → FAILS.
- m53 `census_readonly_check` 38 cases (new mutant: the quiet guard removed from `GetAllowNaniteTargets` → fails) and source
  PASS.

**Setting 1 = today's contract.** With 1, `DecideNanite` admits, the filter keeps every candidate (the KAT above), no
refusal fires, and the capture-side unmeasured path (`IsKnownUnmeasurable`, the event rows with `target_pixels -1`,
`observable null`, `observability_measured false`) is untouched in source. The live proof is tonight's `NANITE_ALLOW1` leg.
