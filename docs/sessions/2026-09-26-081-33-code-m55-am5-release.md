## A.6 as implemented (`_reviews/081-23-lib.py`, `c36a60c2…` → `9901be63…`; window runner unchanged `56e86f2e…`)
- `colour_file_meta(session, rel)` reads the **PNG header only** (IHDR: width, height, bit depth, colour type). A non-PNG falls back to the
  image header (format, size, mode). A missing file and an unreadable file (e.g. zero bytes) are recorded as such and never match.
- `colour_condition(leg, si, …)`: the colour file is the label row's own `image` reference, falling back to
  `Actual_Frames/frame_<si>.png`. It must exist and equal **every other leg's** file for that si on dimensions and pixel format.
  - **A missing or unreadable comparison-leg file also fails the condition.** "The same as the comparison leg's" cannot be established
    without it. This is the conservative reading, stated here and proven below.
- In `legacy_compare`, a signed, unmeasured frame is excused **only if A.6 holds**. Otherwise nothing is excused and every ordinary rule
  runs as before. No problem line, verdict path or threshold was added.
- Every evaluation is reported as `coalesced_colour_condition`, with the leg's and every comparison leg's metadata and the reasons. The
  excused entry and the group ledger row carry it too.
- **The six derived fields needed no code.** 081-32 already excuses them only at the value the writer produces, because the comparator is
  re-read as if the frame were unmeasured (`_unmeasure_raw` / `legacy_view`). Ruling 2 confirms that reading; the off-by-2 negatives below
  prove it.
- Readings are unchanged. The new lib's readings and flats are byte-identical to the 081-32 lib's on all 30 legacy legs, and to the
  pre-081-32 lib's on every pre-existing key.
