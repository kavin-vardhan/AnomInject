## Findings that shaped the plan
1. **8 files conflict (13 hunks), and one break git does not flag.** After the auto-merge, `Anomaly_StuckLowMip.cpp` holds
   **two destructor definitions**: m53's instance registry and the fix's `StopHoldMonitor`. That is a compile error with no
   conflict marker. Every hunk is a union (§2.2).
   - Candidate gotcha, not minted: *a clean auto-merge can still fail to compile when both sides add the same special
     member.* Its number after the merge would be the next free across all refs (G370).
2. **In the fixed schema, `temporal_aa` is keyed to `stuck_low_mip`'s trails only.** Material swaps carry no transition
   flag. So "the TAA flags apply to m53 as to every other anomaly" means **none** for m53, and B-M53's AA-on legs are what
   decide whether that holds.
3. **The bench twins are listed in the Development delivery's catalogue today:** registered under
   `#if !UE_BUILD_SHIPPING` only. IN 7 needs the gate.
4. **Engine facts that make a cheap lever gate possible:**
   - `ECVF_Unregistered` makes the console refuse an object while keeping it alive (`ConsoleManager.cpp:1853`,
     `:1561-1564`, `:1632-1667`). So one sweep at injector init masks every `IAI.Bench.*` name. The alternative was
     converting 46 static registrations (§R2.11's approach).
   - `FParse::Param` needs whitespace after the token, so `-IAIBench` and `-IAIBenchFixture` never alias.
5. **Inside a capture run, the FSM already waits for m52's trail before the next fire** (`RestoreTrail`). An m53 attempt
   can meet a live m52 trail only through a reopen, an adopted or carried trail, or out-of-band input. That is G366,
   confirmed in source. EXCL-A therefore uses the carried-trail path (two runs, one process) as a deterministic producer.
