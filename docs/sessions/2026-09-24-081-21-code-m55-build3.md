## 6. Deviations and observations

1. **Counter name.** The ruling's `multi_view_families` ships as `change_multi_view_families`: every
   stage counter carries the `change_` prefix and there is no stage (so no key) with evidence off.
2. **F7 scope.** Besides `duplicate_completion`, unsupported frames also no longer raise `late_results`
   (their drain admissions and mask completions after the frame was final used to count there).
3. **Oracle exit 1 includes reference comparisons.** A row whose own numbers match but whose
   reference comparison mismatches also exits 1 ("any mismatched compared row" read to include the
   row's reference comparison). An `empty_region` cross-read that disagrees stays a printed reading
   and does not change the exit code.
4. **Gate devices re-predicted before any run** (predictions §D): gate 8's throwaway family now
   consumes SI 8's arm (SI 8 `unsupported_delivery`, legacy PNG absent, the duplicate-claim check no
   longer reached), gate 2's SI 8 mask is served in frame 8, gate 15 gets an explicit mask hold.
5. ⚠ **What the legacy-exact rule restores (for chat).** The model shows one shape where build 2 kept
   a legacy frame that build 3 (and pre-m55) loses: an eligible foreign family that renders **after**
   the capture viewport in the same frame publishes its own key for that frame number, and the newest
   key wins at lookup (`owner_then_foreign`, game-thread-first ordering: build 2 12 submissions,
   pre-m55 and build 3 0). Build 2 had masked this pre-m55 defect by refusing foreign families. In PIE
   the engine makes other level viewports non-realtime (`PlayLevel.cpp`: "Can't allow realtime
   viewports whilst in PIE"), so it needs an invalidated editor viewport to redraw; on the bench's
   packaged single-viewport legs it cannot occur (`change_view_rejected` was 0 on every normal banked
   leg). Implemented as ruled and recorded with the multi-view unsoundness for the m51 pairing work.
6. Harness: the round's idle check classifies by engine and folder; `dotnet.exe` was added mid-round
   after a poll showed our own UnrealBuildTool (a `dotnet` process) was invisible to the name list.
   The build had already started behind a passing check, so nothing was affected.
7. F8 (pre-existing comments in the Stage 1–2 C++) remains a merge-checklist item.
