## The finding

**The agreed takeover cannot corrupt a host material; it can only replace it with a reconstruction.**

- A takeover MID shades with our graph. The host graph is editor-only data (stripped at cook), and
  no cooked API says which texture feeds BaseColor or Normal, or with which sampler.
- The content scan shows what that costs on the fixtures:
  - StackOBot's modular kit is world-aligned and tinted, and its only sRGB candidates are a sand
    overlay and a 1-pixel constant.
  - Lyra's gym cubes are triplanar and tinted.
  - `SM_FloorBase` has only a mask texture.
  - The hero `SKM_Bot` and Lyra's characters are masked and two-sided, so the agreed opaque-only rule
    refuses them.
- The consequence for the dataset: the positives would carry a material change beside the named UV or
  normal bug — a shortcut feature for the client's model — and the weak modes would be dominated by the
  reconstruction.

**The source supports a host-preserving alternative (route B).**

- Put a MID of the **host's own material** on the slot and override only the texture **parameter**,
  with a render target into which a plugin corruptor material drew the transformed host texture once
  at Apply.
- A MID of a MID renders the default material, so a slot that already holds a runtime MID is cloned
  from its parent with `CopyParameterOverrides`.
- Why it is better:
  - the scene keeps the host's shaders, PSOs, usage flags, blend mode and two-sidedness;
  - the identity mode becomes a real null twin (`G-ID`);
  - one UV transform can move every map coherently.
- What it costs:
  - render-target memory;
  - textures that are not parameters are refused;
  - `lerp to TexCoord[1]` is not expressible and becomes `uv_scramble`;
  - Nanite-override materials are refused;
  - a cloned host MID stops following the game's later parameter animation.

**Recommended:** route B, with Stage 1 gated on `G-ID`. If the identity round-trip does not reproduce
the host picture within the `null_effect` band, Stage 1 stops and the agreed takeover (fully specified
in the plan, §3.1) is the fallback.

## Other results worth carrying

- `GetUsedTextures` works cooked and resolves instance overrides. It **returns an empty list silently
  when no shader map is loaded**, so `no_textures` must say both readings.
- A virtual texture bound across the VT boundary renders **black** in a cooked build, so VT textures
  are skipped per texture.
- PSO precaching is off by default in 5.1, so a new material × vertex-factory pair builds its PSO on
  first draw.
  - Route A pays that in the first labelled frame, once per VF family.
  - Route B pays it once, off-scene.
- Swapping a static component's material leaves its original static streaming entries in place.
  Tiling ×8 makes the streamer over-request, not blur.
- 🔻 **Precision to G150:** a pool member that is not enabled does not enter `Eligible` and re-rolls
  nothing, so shipping both ids default-off keeps banked auto-pool comparisons valid.
- Three traps in the render-target draw, found at source and designed around:
  - a **UI-domain** material has no local-VF shaders in a cooked build, so it draws the default
    material while working in the editor;
  - an **opaque** draw writes **alpha = 0**, so the corruptor is AlphaComposite with a pre-clear
    (derived, and proved or refuted by `G-ID`), with a no-re-cook fallback;
  - normal maps unpack `.rg` unless `Compat.UseDXT5NormalMaps` — read at runtime.
- 🚨 **`UStaticMesh::GetNumUVChannels` returns 0 in a cooked build** (editor-only body). The route-A
  `channel1` check must use `GetNumTexCoords` instead.
- A missing TexCoord[1] returns **UV0** on the local vertex factory (so the mode would be invisible) and
  **zero** on Nanite.
