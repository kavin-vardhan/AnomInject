## 2. What the source read actually changed about the plan

The brief enumerated four levers (`L1` raw `StreamOut`, `L2` unlink, `L3`
`LODBias`/`MaxTextureSize` + `UpdateResource`, `L4` a sampler-side mip bias) and
expected `L3` to be refused. **Three of the four are refused, the expected one is refused
for the wrong reason, and the chosen lever is a fifth the brief did not name.** Full
citations are in the predictions file §1; the three findings worth carrying are:

### 2.1 🚨 `UTexture::LODBias` is IGNORED on a cooked platform

`Texture->LODBias` is a runtime, public, `BlueprintReadWrite` `UPROPERTY`
(`Texture.h:1292-1294`) and `UpdateCachedLODBias()` is `ENGINE_API` and **not**
editor-gated (`TextureDerivedData.cpp:2765-2768`). So the obvious lever compiles and runs
in a packaged build. And it does nothing:

```
if (!FPlatformProperties::RequiresCookedData())
{
    // When cooking, LODBias and LODGroupInfo.LODBias are taken into account to strip the top mips.
    UsedLODBias += LODBias;                       TextureLODSettings.cpp:176-186
```

⇒ **it works in the editor and is a silent no-op in the configuration the client
receives.** `G119` (read it back out of the artifact, not out of the source) and `G114`
(a lever that does nothing produces a clean null indistinguishable from a clean result)
in one place. Had this shipped, a PIE smoke would have been green and every packaged
client capture would have carried positive labels for frames nothing happened on.

**This is why the m52 gates are pre-declared PACKAGED-only (`G76`).**

### 2.2 🚨 The streamer does not merely undo a foreign stream-out — it CANCELS it

```
else if (RequestedMips > max(ResidentMips, WantedMips + 1) ||
         RequestedMips < min(ResidentMips, WantedMips))
{  CancelationRequests.Add(AssetIndex);  }        AsyncTextureStreaming.cpp:803-808
```

executed at `StreamingManagerTexture.cpp:1333-1339` → `PendingUpdate->Abort()`. A manual
`StreamOut(floor)` on a **visible** texture satisfies the second clause by construction.
⇒ `L1` fails twice over, and — the part that matters — **`L2`'s only workable ordering
is destroyed too**: unlink-then-StreamOut stalls because nothing ticks an unlinked
asset's pending update (`StreamingTexture.cpp:268` is the sole manager-side caller of
`TickStreaming`, and `TickStreaming` is **not** `ENGINE_API`, `StreamableRenderAsset.h:201`),
while StreamOut-then-unlink is exactly the cancellation race.

### 2.3 ✅ The lever that works makes the streamer the enforcer

`NumCinematicMipLevels` is a **public runtime `UPROPERTY`**
(`StreamableRenderAsset.h:253-256`) whose term in `CalculateLODBias` sits **outside** the
cooked gate (`TextureLODSettings.cpp:171-175`). Writing it and calling
`UpdateCachedLODBias()` reduces `CachedCombinedLODBias`, which reduces `MaxAllowedMips`
on every streamer update (`StreamingTexture.cpp:188-192, 229, 233`), and **every**
wanted-mips path is clamped to `MaxAllowedMips` (`:310, :346-348, :361, :366`) —
including under force-fully-load.

⇒ the streamer performs the stream-out itself, `RequestedMips == WantedMips`, the
cancellation predicate of §2.2 is false, no resource is recreated, nothing blocks the
game thread, and the hold persists for exactly as long as the bias stands.

Its five named failure modes (`r.Streaming.UseAllMips`, `r.TextureStreaming=0`, a host
`SetForceMipLevelsToBeResident` with a cinematic group mask, a host `UpdateResource()`,
and virtual textures) are tabulated in predictions §1.5. **Each is either refused at pick
time and counted, or shows up as `held:false` — and because the label is driven by the
same measurement, a frame it fails on is simply not labelled.**

### 2.4 A tick-order fact worth keeping

`OnWorldTickEnd` (`LevelTick.cpp:1814`) → `RedrawViewports()` (`GameEngine.cpp:1891`) →
`IStreamingManager::Get().Tick()` (`GameEngine.cpp:1899-1901`, with the engine's own
comment saying why it is last). So a resident-mip sample at tick-end describes the state
that same frame draws with — `m40`'s rule holding for a new quantity — **and** a bias set
during `UWorld::Tick` cannot take effect in that frame, so onset is latent by at least
one captured frame. The latency is gate `G4` and **no value is predicted for it.**

## 3. The sharing measurement

New read-only tool `tools/m52_texture_sharing_scan.py` (no engine, no build, no leg): it
reads the name table out of the head of every `.uasset` under a content root, builds
`mesh → material → texture`, and reports per texture how many **other meshes** reach it.
The 1-hop/2-hop split matters — without it a target's own master material and instances
read as "sharers" and every target looks shared.

Target names were **not invented**: they are the measured target set harvested from
`affected_objects.nodes[].asset_name` across the banked sessions (393 StackOBot
`annotation.json`, all 6 Lyra ones).

Declared weaknesses travel with every number (predictions §3.1): **level-wide not
view-wide**, **asset-wide not instance-wide**, blind to runtime MIDs, a reference is not
proof of sampling, and 421/3,974 (StackOBot) and 1,237/4,688 (Lyra) files were
head-truncated at 192 KB. The classifier prints its own both-ways control (`G96`): it
accepted 647 and **rejected** 386 of the assets carrying the `Texture2D` token on
StackOBot, so it discriminates rather than accepting everything.

**Result (full tables in predictions §3.2/§3.3):**

| fixture | targets | all textures exclusive | ≥1 exclusive | least-shared ≤ 1 |
|---|---|---|---|---|
| StackOBot | 18 | **0 (0 %)** | 3 (17 %) | 7 (39 %) |
| Lyra | 5 | 0 (0 %) | 1 (20 %) | **4 (80 %)** |

- StackOBot's heavy sharers are **utility/tiling** textures — `BaseFlattenNormalMap` 84,
  `127grey` 74, `T_Grunge_A` 58 — and **six** measured targets sit on one identical
  9-texture modular family.
- Lyra's authored content is near-exclusive: the three weapons' four textures each have
  **exactly one** other mesh reaching them.
- 🚨 **`CB_GateLevel`'s targets have NO TEXTURE TO HOLD, which is a stronger result than
  sharing and it corrected my own first reading.** The scan says the `BasicShapes` mesh
  *assets* reach `T_Default_Material_Grid_M/N` (25 sharers) through their default
  material slot, and I first wrote the fixture up as "maximally shared". **The gate level
  overrides that slot**: `make_gate_level.py:60` loads
  `/Engine/BasicShapes/BasicShapeMaterial` and `:68-69` assigns it to every target, and
  that material carries **zero** textures — 9,557 B with no `Texture2D` token and no
  outbound reference but its own path. The script's own comment at `:75-76` says it
  (*"the targets use the plain white BasicShapeMaterial"*); only the non-target floor
  gets `WorldGridMaterial` (`:79-81`).
  ⇒ `stuck_low_mip` refuses 100 % of that fixture as `not_streamable`, **before** the
  sharing gate is consulted. `G135` again, and the fixture is ruled out as an m52 gate
  host in advance rather than during implementation — and it must not be edited to fix
  that (`G99`; `make_gate_level.py:50` deletes `LEVEL_PATH` before authoring).
  🔑 The asset-graph scan was right about the assets and wrong about the level; checking
  what the level actually *assigns* is what caught it, and that check happened because
  the citation was being verified before the record was committed.
- ⚠ Six Lyra targets (`MeshA_*`, the `L_Convolution_Blockout` set) **were not found** in
  the content tree — generated/merged blockout meshes. Stated, not papered over.

**Policy consequence:** all three options the brief listed are refused by this
measurement — `S1` and `S3` are per-TARGET filters that on StackOBot admit at most 3 of
18 and on the bench fixture 0 of everything; `S2` is schema-compatible
(`affected_objects.nodes[]` has been an array since `m22`) but not machinery-compatible
(one stencil tag per event since `m50`, one-target ownership since `m44`,
`target_pixels`/`bbox_drawn_px`/the `m26` veto all one-target quantities). The
recommendation is **`S4`: gate per TEXTURE on the VISIBLE set** — hold the subset of the
target's textures with zero visible co-users, refuse the target only if that subset is
empty or imperceptible. On `SM_rock` that holds `T_rock_01_D/N/AORM` and leaves
`T_black` (39 sharers) alone. `S2` is filed as the Tier-2 escalation if gate `G7`'s
yield is unacceptable.

## 4. Evidence design, in one paragraph

`stuck_low_mip` registers as **`EAnomalyActiveSource::AnomalyState`** (the `lod_popping`
slot, not the `missing_texture` slot) and `IsCurrentlyAnomalous()` returns *the mip is
measurably below baseline*, so **a frame where the hold has not yet engaged, or where the
streamer won, is not labelled at all.** That is what makes `m44`'s ONSET gate satisfiable
by construction instead of by hoping the latency is zero, and it is why none of the five
failure modes can produce a false positive. `observable` needs no change: the m49 A1 rule
is `bLabelled && bHeld && Px >= ObservableMinPixels`
(`AnomalyCaptureSubsystem.cpp:3906`), and m52 does not touch the silhouette, so
`target_pixels` comes from the existing target mask exactly as it does for
`missing_texture`. Per-frame engine truth ships as additive `stuck_mip.*` keys inside the
anomaly entry only (`m47`/`m48` precedent: a run without this anomaly gains no key), and
`annotation.json` does not move (`P6`).

**The perceptibility rule is a PICK-TIME FILTER and never decides `observable`**
(`P >= 4 * top_resident_px` over the projected bbox, bounds only, `G127`-safe), because
its stated weakness is real: a tiling texture repeats N times and the rule over-admits.
The engine's own better metric — `WantedMips - ResidentMips` — exists and is **not
reachable**: `FStreamingRenderAsset` lives in `Engine/Private/Streaming/`. Filed so
nobody re-derives the wish.

## 5. Deviations from the brief, stated

1. **The chosen lever is not one of `L1`–`L4`.** `L4` as briefed (a sampler-side
   `MipValueMode`/`MipBias`) would need an `m54`-style material swap; the source read
   found a cheaper per-texture streaming bias that needs no material change. Recorded as
   `L4′`.
2. **Console names follow the shipped convention, not the brief's.** The brief suggested
   `IAI.Anomaly.StuckMip.*`; the existing surface is `IAI.Anomaly.BlinkHalfPeriod`,
   `IAI.Anomaly.LodHalfPeriod`, `IAI.Anomaly.LodMaxDistance` — no dot after the anomaly
   name. Followed the existing one.
3. **The sharing policy is a fourth option (`S4`).** `S1`/`S2`/`S3` were each evaluated
   against the measurement and each is refused or deferred, with the numbers.
4. **The numbers are level-wide, not view-wide.** The brief's example phrasing
   ("62 % of candidate targets have a unique base texture") implies a visible-set join,
   which cannot be obtained without a runtime probe, which needs plugin code this brief
   forbids. What is reported is the obtainable bound, labelled as a bound. **The
   visible-set measurement is gate `G7` and is named as the first number the
   implementation session must produce.**
5. **One executable artifact was produced** — `tools/m52_texture_sharing_scan.py`. It is
   a read-only offline scanner, sanctioned by the brief's "read-only probes are fine",
   and it lives in the plugin's `tools/` (the standing rule from session 051: internal
   diagnostics ride the plugin repo) specifically so **CaptureBench stays tracked-clean
   for `m51`**.
