## §1. The fix — one term, and the counter that was hiding behind it

### §1.1 The defect, restated from the artifact

`OBS-1` read `affected_frames` EMPTY on all four `FireWindow` events while `injected_frames` was
correct. `target_pixels` read **48,591** on those frames and `frames_condition_lost` read **0**, so
neither the pixel term nor the condition term was false. **The false term was `active`.** It read
`Snap->FireActive`, and `ComputeFireActive`'s fallthrough returns `IsLogicallyHidden(FActor)`, which
is **false for a texture swap**. Journal 071 §3.1 says `FireActive` is never consulted for
`FireWindow` ids; 072-02 consulted it.

### §1.2 What shipped

**`observable`'s active term is now `IsFireLabelledThisFrame`** — whose `default:` branch returns
`true`, and which is **already the predicate `ArmTargetMaskOwn` uses in the same tick-end** to decide
whether that frame's mask is armed at all. ⇒ the term that decides `observable` is now the same term
that decided whether `target_pixels` could exist.

🔑 **It is SAMPLED, not read late.** A new per-frame `Snap->FireLabelled` is filled in
`SampleDeferredActiveState`, beside `FireActive`. **Reading live state in the drain would be exactly
the stale-read class A1 had just fixed**, one function over.

**`FramesConditionLost` no longer hangs off the `observable` expression.** It is counted from its own
two per-frame samples — **labelled AND not held** — and **above** the unmeasured early-out, so a
mask-blind frame can no longer hide a lost condition. Before, it sat inside `if (bActive && !bHeld)`
and therefore could never fire for the two types whose `IsVisualConditionHeld` override exists;
**its `0` was blindness, not a reading (`G96`).**

⚠ **RECORDED INTERPRETATION (AMENDMENT 1 §A1.3), stated rather than left implicit.** Counting
`!bHeld` *unconditionally* was considered and **rejected with its reason**: for `AnomalyState` ids
(`lod_popping`, `camera_clipping`) `IsVisualConditionHeld` defaults to `IsCurrentlyAnomalous`, so
`!bHeld` there means *"the toggle is in its off phase"* — normal operation, not a lost condition —
and an unconditional count would read non-zero on every un-popped `lod_popping` frame, turning a real
signal into noise. ⇒ for `ActorHidden` and `AnomalyState` ids the counter is **structurally zero**;
**the only ids that can move it are the two with a real override, and for those it is now live.**

### §1.3 `LG-3`, and a correction to the brief's premise
