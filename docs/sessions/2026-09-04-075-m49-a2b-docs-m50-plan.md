## §1. Brief 074-01's three NEEDS-DECISION items — RULED

### §1.1 Ruling 1 — `MPP_Outline` / host post-process custom-depth readers: **NO RULE**

**RULED: no refuse-or-warn rule ships.** Leg B's like-for-like control (session 074 §5.2) found **no
detectable effect** — profiles agreeing within 7 % at every radius, the ring *below* ambient in both
classes, and a whole-picture argument that does not depend on the pairing at all (14 actors tagged at
once including a 733,944 px sky sphere, and the ambient measure is LOWER on the treatment side).

**What ships instead:** nothing new in code. The reader count and the **reader NAMES** already reach
the delivered artifact (`census_host_pp_customdepth_readers`,
`census_host_pp_customdepth_reader_names` — `LG-3`, PASS on two Lyra sessions), and
`client-delivery.md` gains one paragraph saying so, with the escape hatch named (turn the census off)
for a client whose host does show an effect.

⛔ **`G120` wording is load-bearing here and is in the shipped paragraph verbatim: this is a statement
about the measurement, not a claim that `MPP_Outline` never draws on our tags.** One host, one outline
material, one fixture.

🔑 **Why "no rule" is the honest default and not laziness:** a refuse-or-warn rule keyed on a
condition that has never been shown to produce an artifact would refuse targets on a host that is
fine, and it would do so *invisibly to the client*. Adding a rule whose trigger is unmeasured is the
`G118` shape — a guard that fires on the safe case looks like diligence and buys nothing.

### §1.2 Ruling 2 — `G246`, the census stencil collision → **`m50`, before any client cook**

**RULED: fixed in `m50`, and `m50` lands before any client cook.**

The defect (session 074 §4): rows sharing a `mask_value` read different `target_pixels` across runs;
the delivered PNG shows **two connected components** for that tag (66,837 + 18,330 px); incidence
**22 of 448 tag-instances (4.9 %), 12 on the A1 binary and 10 on the A2 binary ⇒ PRE-EXISTING, not
binary-attributable**. `target_pixels` and `bbox_drawn_px` both inherit it, and **`MASK-TIE`
structurally cannot see it** — the intruder is in the reduce table *and* in the PNG, so the tie reads
MATCH.

**Design direction as briefed:** *"the allocator excludes every value held by a live fire (and a fire
never takes a value the census holds) — ownership on BOTH sides of the pool, the `m44` rule completed;
plus a gate that CAN see it."*

🚨 **The first half is already implemented. See §3.1 — this is the session's main finding and it
redirects the fix.** The second half (a gate that can see it) is unaffected, mechanism-independent,
and is planned as written.

### §1.3 Ruling 3 — `I11-A` on Nanite hosts → **`m50`, admitted as unmeasured**

**RULED: a target known to be unmeasurable before the fire is classified `NOT_MEASURED` at arm time,
admitted by the veto, and labelled honestly.**

The measurement (session 074 §5.3, `LG-9` on `L_Convolution_Blockout`): `census_candidates` **63**,
`census_unmeasurable_nanite` **55 (87 %)**, 7 bursts, **6 events all vetoed as `MEASURED_ZERO
maxCount=0`, all six targets carrying the Nanite signature (verified per asset offline)** ⇒
**`anomalies: []` out of 90 frames and 43 positive frames.**

The chain, and every link is already in the code: the census correctly says `NOT_MEASURABLE(nanite)`
(which ADMITS — the `H6` safe direction); the picker fires anyway; the custom-depth pass **does** run
because *other* actors are tagged; the Nanite target contributes nothing; and `m26` reads that as a
MEASURED zero and deletes the event.

⇒ **On a Nanite-heavy host the `m26` zero-veto fires BEFORE `m49`'s unmeasured fallback can, so the
fallback is not what protects the dataset there — and the dataset gets nothing at all.**

**The delivered shape after `m50`:** `target_pixels -1` on every frame · `observable null` ·
`observability_measured false` · `affected_frames == injected_frames` · `bbox_source "projected"` ·
`mask.provided false` · **the event STAYS in the file**.

🔑 **The reasoning, recorded as a judgement rather than dressed as a derivation: honest labels without
pixel evidence beat no labels.** A dataset of correctly-boxed anomalies marked *"visibility not
measured"* is usable; an empty `anomalies` array is not. ⛔ **It is not a claim the anomaly was
visible** — `observability_measured: false` is the field that says so, and a consumer needing
pixel-confirmed labels filters on it. `client-delivery.md` states this to the client in as many words.

### §3.1 🚨 THE FINDING THAT REDIRECTS RULING 2: THE OWNERSHIP LEDGER ALREADY EXISTS

**Read, not run. Every line reference below is from the current tip `0d05c4b`.**

`FAnomalyStencilTagLedger` (`AnomalyStencilTag.h:10-21`) already carries three sets — `HostReserved`,
**`EventClaimed`**, **`CensusClaimed`** — and:

```
AnomalyStencilTag.cpp:34-37
  IsFree(V) == IsAssignable(V) && !EventClaimed.Contains(V) && !CensusClaimed.Contains(V)
```

Both allocators already consult it:

| allocator | site | behaviour |
|---|---|---|
| **event** | `AnomalyMaskMeasure.cpp:80-115` (`AllocateTag`) | tests `Ledger->IsFree(Tag)`, then `EventClaimed.Add(Tag)`; logs how many values it skipped |
| **census** | `AnomalyCensus.cpp:715-723`, `:763` (`ArmNextBatch`) | tests `Ledger->IsFree(Cursor)`, then `CensusClaimed.Add(Tag)` |

And `EventClaimed` is **never released mid-run** — it is cleared only in `FinishRun`
(`AnomalyMaskMeasure.cpp:67-70`), so once an event owns a value it owns it for the whole session.

⇒ **The brief's design direction is already the shipped behaviour, in both directions.** A census
batch cannot take a value a live fire holds; a fire cannot take a value an in-flight census batch
holds. **Implementing ruling 2 as literally worded would change no line of behaviour, and would ship
a "fix" that leaves the defect in place behind a green tick — `G118`'s exact shape.**

**What is NOT excluded, and it is the leading candidate:**

```
AnomalyCensus.cpp:550-554   ReleaseBatch:
    Ledger->CensusClaimed.Remove(Tag);
    RecentlyReleased.Add(TPair<uint8, uint64>(Tag, GFrameCounter));
```

`RecentlyReleased` is consumed by **`GetLegitTags()` only** (`:217-225`), which feeds the *pollution
detector's* allowed set, and it expires after `LostAfterTicks` (`:376-379`). **It is not consulted by
`IsFree`.** So a value released at tick T is **immediately re-issuable** — to a fire, or to the next
census batch — while the previous owner's restore may not yet have reached the pixels.

🔑 **`RecentlyReleased` is the project's own record that a released tag lingers.** It was built to
stop the pollution detector firing on that lingering value. It was never wired into allocation.

**And journal 074 §4's mechanism sentence does not follow from the line it cites.** That line is:

```
AnomalyCensus.cpp:794-797
  "Census: ARM cycle=%d batch id=%llu size=%d tags=%d..%d ..."
  , (int32)Batch.Tags[0], (int32)Batch.Tags.Last()
```

It prints **first and last, not the set**, and the allocator skips non-free values *inside* that
range. So `tags=200..226` does **not** show that 224 was issued. ⛔ **The OBSERVATION stands
unchanged — two connected components under one value, 22 of 448 tag-instances, on both binaries. The
mechanism attributed to it in 074 §4 is an over-read of a range summary and is WITHDRAWN as an
established fact; it survives as one of the candidates below.**

*(This is `G120` catching a mechanism, and the correction is cheap because it was caught before a fix
was built on it. It is also the reason `m50` step 0 is a diagnosis.)*

### §3.2 `m50` STEP 0 — DIAGNOSIS, with the branch table pre-declared

⛔ **No fix is written until step 0 returns.** One instrumented leg, no behaviour change.

**The one product change step 0 needs, and it is worth making regardless of the outcome:**

- `AnomalyCensus.cpp:794-797` — **print the ARM's tag SET, not `first..last`**, and print the
  ledger's `EventClaimed` set at the same tick. *A log line that summarises a set as a range is what
  produced the over-read above; a set is one `FString::Join` away.*

**Branch table, fixed before the leg:**

| branch | what it would mean | discriminator |
|---|---|---|
| **D1 — direct collision** | a value appears in the census ARM set **and** in `EventClaimed` at the same tick ⇒ `IsFree` is being bypassed somewhere | the two sets printed at the same tick, from step 0's log line |
| **D2 — release window (LEADING)** | the intruder blob belongs to a census actor **released within `LostAfterTicks` of that frame** | join the intruder's pixel count and bounds against the census's own per-tag reduce for that value over the surrounding ticks; `IAI.Bench.CensusMaskDump` already writes exactly that per batch |
| **D3 — rate dependence** | incidence tracks the census RELEASE rate, corroborating D2 | re-run at a longer census cycle (`IAI.Capture.CensusMaxAge`, `IAI.Bench.CensusBatchCap`) and re-count multi-component tag-instances |

⚠ **The connected-component count is a PROXY and is labelled one** (074 §4 already says so): a
legitimately disjoint silhouette also reads >1. **The log join is the measurement; the proxy only
finds the frames worth joining.**
