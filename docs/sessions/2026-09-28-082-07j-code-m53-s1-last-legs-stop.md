**Cause (read from source and the attempts' own records; no fix attempted):**

1. **The feature.** `StartRun` enters `ArmedPending` only when `bFocusGate && HasGameWindow(World) &&
   !IsGameWindowFocused(World)`. Otherwise it calls `BeginActualRun()` synchronously
   (`AnomalyCaptureSubsystem.cpp:3362-3373`). A `Stop` in the same batch then finds `bRunBegun` true and FINISHES; only an
   armed-pending run CANCELS (`:5874`). That is the m16 contract, and the build followed it.
2. **The runner.** It forces the game window into the foreground from 400 ms after launch (`Hold-Focus` → `[M53Fg]::Force`
   on every startup sample, `082-07-run.ps1:59-68`). `launch.json` records `focus_at_s` **0.9 / 1.3 / 1.2 s** and
   `focus_held=True`. The ExecCmds batch runs at engine frame 1, about 2.3 s after launch (A1: log opened 23:41:44,
   `STARTED` 23:41:46.057 UTC).
   ⇒ **Under this runner the window is always focused when `Start` runs, so cancel-before-focus is unreachable.**

**Reading:** a **leg-premise / encoding defect in the harness, not an S1 qualification FAIL.** No G4 row was evaluated;
the leg never became valid.

  checked against the runner, which guarantees the opposite.
