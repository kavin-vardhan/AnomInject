## 4. What the oracle does (`ea9946a`)

`tools/verify_capture.py --change-oracle [SESSION]` (or `--dir SESSION --change-oracle`;
`--oracle-json FILE` writes the per-row detail; `--quiet` prints only mismatched/unavailable rows).

- **Same pair ids:** every `"kind":"pair"` row with `chg_measured: true`; decodes
  `Actual_Frames/frame_%05d.png` for `session_index` and `prev_session_index` and
  `target_mask/frame_%05d.png` for `session_index`. Rows naming a reference (`ref_session_index`
  with non-null `ref_gt8`/`ref_mean`) are recomputed against that delivered frame.
- **Same region and threshold:** target `mask == mask_value`, control `mask == 0`,
  `d = max(|dR|,|dG|,|dB|)` of the delivered bytes (Pillow `ImageChops.difference` + `lighter`),
  counted when `d > tau_px`. Statistics come from Pillow's masked 256-bin histogram of `d`, so
  `n`, `gt8`, `sum` and the eight bins are exact integers and the mean is the exact `sum/n/255`.
- **Compared:** `chg_n/gt8/sum/hist` and the `ctl_*` twins exactly; `chg_mean`/`ctl_mean`/`ref_mean`
  within **0.00005** (declared in the predictions before the banked run); `ref_gt8` exactly;
  identity fields `tau_px == 8`, `prev == si − 1`, `frame_file` naming, both denominators positive.
- **Coverage printed:** sidecar rows by kind, rows claimed / compared / matched / mismatched /
  unavailable (each reason), reference comparisons the same way, not-claimed pair rows by reason.
- **Unavailable, never guessed:** missing/unreadable files, JPEG colour, non-grayscale mask, PNG size
  ≠ receipt rect (resampled), `capture_path == backbuffer`, no receipt rect.
- **Extra reading, beyond §6.2 and reported separately:** `empty_region` refusals cross-read against
  the mask PNG (agrees / disagrees / unverifiable when no mask PNG exists).
- **Independence:** Pillow only, no `measure_label_offset` import, no port of the C++. Producer
  `chg_*`/`ctl_*`/`ref_*` values are read only after recomputing, to compare. A contract test
  scrambles every published value and asserts the recomputed values are unchanged.
- **Exit codes:** 0 whenever it ran — a mismatch is printed, it is not a verdict — and 3 when it
  cannot run. No 079 vocabulary word is used; the peak/consistency machinery is not called.
- **Printed sentence (spec §6.2, verbatim, last line of every oracle output including CANNOT RUN):**
  *agreement validates arithmetic and transport only — that the numbers in the sidecar are the
  numbers the delivered images contain. It does not establish renderer pairing, visible effect, or
  cause.*

## 7. Deviations and limits, stated

1. **Exit code of `--change-oracle`.** §6.2 says exit codes are unchanged on the six existing cases and
   no new verdict; it does not say what the new mode returns. Chosen: 0 when it ran (a mismatch is
   printed, not signalled), 3 when it cannot run — the existing execution-error code. A consumer that
   wants a failing exit on a mismatch must read the printed counts or `--oracle-json`. Flagged for chat.
2. **CLI form.** The brief writes `--change-oracle <session>`; §6.2 writes a flag. Both work
   (`nargs="?"`, falling back to `--dir`). A bank leg folder holding exactly one session resolves to it.
3. **Beyond §6.2, additive and reported separately:** `chg_sum`/`ctl_sum` and both histograms compared
   exactly (the brief asks for the histogram "if it is in the row"); identity checks (`tau_px == 8`,
   consecutive ids, `frame_file`, positive denominators); the `empty_region` cross-read. On the bank the
   cross-read could never *confirm* a refusal — all 25 had no mask PNG (none is written for an all-zero
   mask) — so it is proven to fire only on the synthetic fixture.
4. **Contract tests in a new file** (`test_verify_capture_change_oracle.py`) so the existing suite's
   count stays 25 by construction.
5. **Binary attribution** for 12 sessions (09-21 Stage 2, 5EADBCBD / 2C21EDE5) and all Stage 1 sessions
   is inferred from archive times, labelled *inferred*. Stage 1 sessions carry no measured rows.
6. **Not validated by the oracle, by design (§6.2 scope):** that the producer chose the right pair (it
   uses the row's own ids; a producer that published consistent wrong ids *and* matching numbers would
   pass — the must-fail "swapped predecessor" case is caught only because the numbers came from a
   different frame than the ids name), refusal reasons other than `empty_region`, event records, the
   `_sofar` maxima, `prev_target_pixels`, camera caveat fields.
7. **Rows unmeasured by the producer carry `ctl_*` when identity permitted arithmetic** (field
   reference); the oracle does not compare those — they are not claimed measured rows.
8. **Pre-existing comments in Codex's Stage 1–2 C++** are untouched; the stripper was applied to this
   round's two Python files only (both `nochange`). It must run over the branch before merge (081-17
   deviation 6, unchanged).
