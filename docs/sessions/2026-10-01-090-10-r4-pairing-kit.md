## 1. R4 async — the label's geometry is frozen at the tick-end sample

**Rule.** At the tick-end sample (`SampleDeferredActiveState`, `OnWorldTickEnd` of the armed tick) every fire's label
geometry is frozen together with the installed state, event identity and view that were already frozen there:
`AnomalyLabel::FreezeSnapshotGeometry` stores, per fire, a source (`whole_frame` / `box` / `none`) and the actor's
renderable bounds box (`GetActorRenderableBounds`, the same union `ProjectActorBoundsToScreenRect` used) in
`FCaptureSnapshot::FireGeometry`, and the same for `TransitionFires` (`TransitionGeometry`) and the stuck-mip
`TransitionCandidates` (`CandidateGeometry`). At readback completion nothing reads the live actor:
`FillAnnotationInputs` (on-screen ⇒ `labelled` and annotation membership), `BuildFrameLabelRecord`
(`bbox_px` / `bbox_norm` / `bbox_valid`) and `AccumulateFrameEvents` (`coverage_ratio`) all project the **frozen box
with the frozen view** (`ProjectFrozenFireBox` → new `AnomalyViewport::ProjectBoxToScreenRect`, which is the old
projection with the live bounds read split off, so the math is identical by construction).

**The decision is pure and UE-free** (`Source/AnomalyInjector/Public/AnomalyFrozenGeometry.h`): `DecideAtSample`
reproduces the old `ProjectFireBox` rule but evaluated at the sample — whole frame if the fire is whole-frame or its
actor is gone and it has no target name; a box if the actor is alive and has renderable bounds; else none — and
`Resolve` projects only what was frozen (an entry never sampled is off screen, never a member).

**Also moved to the sample, so the completion path has no live read:** the fire position `FirePos` (was read at the end
of the capture tick, before the sample), and the event's anchor identity — `node.path`, `asset_name`,
`component_class`, node bounds, selection provenance (`coverage_pct`, occlusion samples, poll distance) and the
camera path — frozen once per event at its first sample (`FreezeEventAnchor`, map `FrozenAnchors`, reset per run).
Fires appended after the sample keep the rule: a stuck-mip reopen freezes the trail fire's geometry where it is added
(`HandleTrailReopens`), and a detached transition candidate carries its sample-time geometry when it becomes a
transition entry (`ResolveDetachedTransitionCandidates` → `AddTransitionFire`).

**Remaining live reads at completion — one, and why it is safe.** `AccumulateFrameEvents` still passes
`F.TargetActor.Get()` to `MaskMeasure.FindOrAddRecord`: it is the m26 mask record's actor handle, used for later
mask arming; it computes nothing for this frame's label, and the record normally already exists (m44 record birth at
tick end), in which case the pointer is ignored. Everything else that reaches a label at completion is either frozen at
the sample (above), read from the GPU for that frame (mask PNG, `target_pixels`, `target_drawn_pixels`,
`bbox_drawn_px`), or keyed by id (policy, render-truth class). The source gate (below) prints this as its one allowed
line.

**Tests both ways.**
- `tools/r4_capture_pairing_selftest.cpp` (46 checks): a world model in which the target moves off screen, behind the
  camera, is destroyed, loses its bounds, grows, or enters the view between sample and completion; the record must
  equal the sample-time projection and membership, and the old completion-time rule is shown to disagree in every
  moving case (so each case has teeth) and to agree when nothing moved. Header mutants `r4_freeze_drops_box`,
  `r4_whole_frame_decided_never` fail it.
- `tools/r4_pairing_gate.py` (new, `--root` / `--selftest`): extracts the completion-path function bodies from the
  real production source (`ProcessCompletedFrames`, `FillAnnotationInputs`, `AccumulateFrameEvents`,
  `ApplyRenderTruthToSnapshot`, `ResolveDetachedTransitionCandidates`, `ComputeRenderMembership`,
  `BuildFrameLabelRecord`, `BuildLabelRecordForSnapshot`, the projection and marking helpers) and fails on any live
  read (`TargetActor.Get(`, `ProjectActorBoundsToScreenRect(`, `GetActorRenderableBounds(`, `GetActorLocation(`,
  identity/provenance/camera reads, the freeze functions themselves); it also requires the sample to freeze and the sync
  path to be flagged. Its selftest builds **mutants of the real source that read live bounds** —
  `r4_live_annotation_inputs`, `r4_live_record_box`, `r4_live_coverage`, `r4_live_anchor` — plus
  `r4_sample_not_frozen`, `r4_sync_not_flagged`, `r4_sync_not_marked`, `r4_record_labels_unpaired`: all 8 fail, the real
  source passes, an unreadable tree fails (no blind pass).
- Existing suites unchanged: m52_window 305/0, camera_clipping 154/0, target_policy 41/0, install_state 27/0, and the
  15 earlier mutants still fail.

## 2. R4 sync — every sync-path frame is `capture_unpaired`; the path is unsupported for delivery

**Why.** The synchronous block of `CaptureCurrentFrame` reads the fire state during tick N and then `ReadPixels`
returns the picture presented after tick N−1 (UE runs `UWorld::Tick` before `RedrawViewports`), so a change made
earlier in tick N is in the label and not in the picture. Ruling 2 takes the 1-hour route: flag, do not repair.

**Rule as built.**
- New reason bit `capture_unpaired` = 128 (bit 7, `AnomalyLabelSync::ReasonCaptureUnpaired`, `NumReasons` 8; never
  rewritten as a legacy temporal flag). Pure decisions `DecideUnpairedEntry` (any non-suppressed entry becomes
  transition-only) and `IsAnnotationMemberPaired` (an unpaired frame is never a member under any policy).
- In the sync block: `SyncFrame.bCaptureUnpaired = true` and `AnomalyLabel::MarkCaptureUnpaired` mark every entry
  (and every transition entry) with the reason; `BuildFrameLabelRecord` writes the row-level `capture_unpaired: true`
  and `transition_reason: ["capture_unpaired"]`, never a labelled entry (`&& !bCaptureUnpaired`, defensively, on top of
  the transition-only marking), so `anomaly_present` and `visible_positive` are false. The sync path never measured
  masks, so the frame is unmasked. `AccumulateFrameEvents` is no longer called for a sync frame: it is never listed in
  `annotation.json`, and an event seen only on sync frames does not appear there.
- Counted: `run_summary.capture_unpaired_frames` (equals the existing `sync_frames_written`),
  `label_transition_capture_unpaired_entries`; the labelsync summary line prints `capture_unpaired=%d`; one
  `Capture(090-10): CAPTURE-UNPAIRED` warning per run names the path (`async_off` / `async_rect_fallback`).
- Geometry on a sync frame is frozen at its own capture moment (`FreezeSnapshotGeometry(SyncFrame)`), so even its
  informational `bbox_*` is not read later.
- Not changed: the single-shot console command `IAI.Capture.Shot` (rows `label_rule: legacy_shot`, not part of a capture
  run, outside the ruling); its record now takes the box from geometry frozen at the shot (`BuildLegacyShotRecord`)
  instead of re-reading the actor, which is the same instant.
- Readme (`docs/client-readme.md` §8 field table and §8.6a): the `capture_unpaired` row in both reason tables, the new
  row-level key, the run_summary keys, and **"The synchronous capture path is unsupported for delivery. The shipped
  defaults (asynchronous capture and scene-colour capture both on, no ini key needed) never reach it."** Also corrected
  in passing: the `labelled` row still described 090-05's "every slot" rule and named the v2 rule string.
- The one-deep history fix (pairing sync labels with the previous tick's sample) stays a follow-up, per the ruling.

**Rule string.** `label_labelled_rule` becomes `annotation_membership_per_policy_v4_sample_bound` (the on-screen test now
uses the sample's geometry, and sync frames are never labelled), and a new `label_geometry_source:
bounds_frozen_at_tick_end_sample`. Neither tool keys on the string (checked).

**Tests both ways.**
- C++ `r4_capture_pairing_selftest`: the reason bit and name, `ReasonsOrLegacy` never turns it into `temporal_aa`, entries
  become transition-only (suppressed stays suppressed), never a member under any of the four policies × 16 input
  combinations while a paired frame keeps exactly the 090-09 gated rule, and a present frame stops being present.
  Mutants `r4_sync_left_labelled` (sync frames left labelled), `r4_sync_still_member`, `r4_unpaired_read_as_aa` fail.
- Production-source gate mutants `r4_sync_not_flagged`, `r4_sync_not_marked`, `r4_record_labels_unpaired` fail.
- `verify_capture --label-rule` and the kit know the reason (§3, §4).

## 3. Kit 1.3 — the two older limits closed, and `capture_unpaired` known (`tools/label_sync_check.py`, `tools/OFFICE-CHECK.md`)

- **A missing labels row inside a labelled run ⇒ unjudged, never a silent skip.** `analyse_d` built its spans and unreadable
  lists only from `si in s.rows`, so an index listed in `annotation.json` with no `labels.jsonl` row was skipped and the run
  could PASS around it. Now any labelled run with a missing row in `a..b`, or whose neighbour hole (between two runs of the same
  event) consists of missing rows, is unjudged with why `labels row missing`; the event reads UNJUDGED unless a judged run FAILs
  (1.2's accepted precedence). A missing row outside the event's labelled span keeps the censored-edge reading (`brk`).
- **A truncated or undecodable PNG is INVALID on both decoders, and they agree.** One strict validator, shared and run before
  every full and partial decode (cached per file): signature, chunk framing, every chunk CRC, IHDR first, IEND present and last,
  the IDAT zlib stream complete and exactly `h × (1 + w × channels)` bytes; any failure is `PngError("invalid PNG: …")`, and
  Pillow's `SyntaxError`/`EOFError` are caught. Before: the stdlib decoder ignored CRCs and decoded the first rows of a file cut
  after them (the partial reads), while Pillow refused it — and a bad CRC raised an uncaught `SyntaxError` under Pillow.
- **`capture_unpaired`:** known, no AA excuse (`NO_AA_EXCUSE`), never a reference or evidence; a run edge beside an unpaired
  frame is censored; a session made only of unpaired frames is refused as `sync-path capture: unsupported for delivery`.
  READ BACK and the per-type events line end `| unpaired N`; the office card explains it in one paragraph and says what to do.
- **Tests:** selftest 54 → **73** checks, OK on **both** decoders (Pillow 107 s, stdlib 96 s; 1.2 took about a minute), incl.
  a missing row inside a run, missing rows filling a gap, truncated / bad-CRC / no-IEND PNGs (direct decoder checks for full and
  partial decodes on both decoders, plus a session case each), an unpaired frame after a run, unpaired + `temporal_aa`, and an
  all-unpaired session. **Mutants, each must fail and does:** `M1_row_missing_skipped`, `M2_no_png_validation` (on each decoder),
  `M3a_unpaired_unknown`, `M3b_unpaired_as_aa_excuse`, `M3c_unpaired_aa_excusable`, `M3d_unpaired_ignored`, and 1.2's
  `A`, `A2`, `B`, `C`, `taa_flag`, `ignore`. **Regression** (1.2 vs 1.3, the same 8 real sessions as 090-09): 91 events,
  60 judged, **0 per-event differences** and identical report lines after removing only the new text, on Pillow **and** on
  stdlib; 2,791 PNGs validated, **0 invalid**. Wall time: Pillow 1.2 342–398 s vs 1.3 420 s; stdlib 1,915 s vs 1,787 s.

## 4. `verify_capture --label-rule` knows `capture_unpaired` (`tools/verify_capture.py`)

A known reason on every type, unlabelled-only, never given the `temporal_aa` gate or the veto latitude. A row with the row-level
flag must have `anomaly_present`/`visible_positive` false, every entry `labelled: false` with `transition` 1 and the reason, the
row-level reason, and must not be listed by any `annotation.json` event in any frame list (new FAIL lines `UNPAIRED-POSITIVE`,
`-LABELLED`, `-LISTED`, `-INCONSISTENT`); `run_summary.capture_unpaired_frames` must equal the flagged rows (`UNPAIRED-COUNT`). An
all-sync session (or an older build whose `run_summary` says every frame was sync) reports **NOT JUDGED**, exit 3 (the existing
cannot-judge code), never a pass. Label-rule selftest 31 → **51** cases; mutants (sync checks removed so labelled sync frames are
accepted; the reason treated as AA; listing read from `injected_frames` only; all-sync reported as a pass; count ignored) all fail;
the other selftests and both unit-test files unchanged; 48 banked sessions give identical exits before and after (all old-rule
sessions, so this proves no regression, not the new rule on real data). The file never keys on the rule string.

## 10. Judgement calls for chat (none blocks)

1. **More than the box is frozen.** Besides the box and on-screen test the ruling names, the event's anchor identity
   (`node.path`, `asset_name`, `component_class`, node bounds, selection provenance incl. `coverage_pct`, camera path) and
   `FirePos` are frozen at the sample, so the completion path's only live read is the m26 mask-record handle.
2. **Rule string bumped** to `annotation_membership_per_policy_v4_sample_bound` (the on-screen input changed source and sync
   frames are never labelled), plus `run_summary.label_geometry_source`. Neither tool keys on the string.
3. **Sync frames feed nothing in `annotation.json`**: an event seen only on sync frames does not appear there (dropped), and on a
   mixed run its frame lists simply omit the sync frames.
4. **`IAI.Capture.Shot` (single shot, `label_rule: legacy_shot`) is not flagged**: it is not part of a capture run and the
   ruling names `Async 0` and the SVE-off fallback. Its box now comes from geometry frozen at the shot (the same instant).
5. **Checker:** an all-sync session is NOT JUDGED, exit 3; so is an older build whose `run_summary` says every frame was sync
   (none in the bank). `labelled` must be exactly `false` on a sync entry (a missing key fails).
6. **Kit:** bytes after IEND make a PNG invalid (strict; 0 of 2,791 real frames affected).
7. **The one-deep sync history** (pairing sync labels with the previous tick's sample) stays a follow-up, per ruling 2.

8. **A stale kit 1.2 does not reliably fail safe on `capture_unpaired` frames** (measured on the new selftest cases, both
   decoders): it FAILs in the realistic shape (the frame after a run end shows the previous picture; a stuck_low_mip end), but
   can PASS when the unpaired frame's picture happens to be clean, when an unpaired frame before the onset shows the previous
   clean picture, when the frame also carries `temporal_aa` (1.2 excuses it), or when the annotation lists it; a row flagged
   only at the root is invisible to it, and an all-unpaired session reads "events 0, judged 0" instead of refused. ⇒ **captures
   from a 090-10 build must be checked with kit 1.3** (it ships beside the plugin); with the shipped defaults no frame is
   unpaired, so the exposure is the unsupported path only.
9. **Kit 1.3 censors, it does not fail, an edge beside an unpaired frame**, mirroring the Nanite end: a label that ends one
   frame late onto the frame before an unpaired one reads CENSORED, not FAIL. Also: an annotation that lists an unpaired frame
   (forbidden by the contract) leaves its run unjudged ("labelled frame unpaired"); the PNG check also rejects a second IHDR,
   leftover data after the image stream and a row filter byte above 4 (0 of 3,624 real PNGs — 3,000 frames, 624 masks — affected).
