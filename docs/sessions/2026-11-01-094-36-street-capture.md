# 094-36: census parity and a frozen street pre-pass

Scope: stock 4.25 only, current player view on the unchanged street map. One game session and one qualified retry; 2100-second owned-tree limit, native capture limit 2000 seconds. No smoke or rehearsal. FM1 builds use two actions, BelowNormal, 8 GiB commit admission and 3 GiB owned-tree stop. Runtime uses FJ1/FK1: 5 idle minutes, 8 GiB commit and 4 GiB physical, D: start 25/floor 15 GiB.

## Predictions and references, written before any 09436 session

Six yaw poses at the player's starting position, base yaw plus 0/60/120/180/240/300 degrees; pitch -12, roll unchanged. Each turn takes 18 captured frames and settle takes 30. For each pose, census-off has 240 clean held frames, immediately followed by 240 census-on held frames. Auto-injection remains off throughout the pre-pass. Warm-up waits for streaming and shader compilation as in 09435. Scored holds are 480 frames each with the same turns/settles and seed 4242, restricted to the four smoke routes, 0.8-second interval, 0.4-second hold, one concurrent event. Total 6336 frames. The first scored hold is pose zero; transition frames are counted but not edge-scored.

The standard 4.25 tonemapper has no working grain-quantization-off switch for its normal display path: `PostProcessTonemap.cpp:810-819` reads `r.Tonemapper.GrainQuantization`, then `RemapPermutation` at 215-219 forces it on except for linear output devices. Changing the display device would also change output encoding/format, so this job uses FT3's explicit phase-matched fallback. `PostProcessTonemap.cpp:492-506`, `PostProcessTonemap.h:36-40`, and `ScenePrivate.h:1047-1051` give the exact period: GetFrameIndex(8) is FrameIndex modulo 7. The render hook records that actual phase. Exposure and AA remain locked to the C4 command line; no config or saved-asset edit.

For each pose and each of seven recorded phases, the first census-off hold frame is the reference. Within each phase, mark pixels with any RGB max-minus-min greater than one; union phases and dilate by two pixels. The first 120 frames build the self-check map; the second 120 compare to the phase reference on its stable pixels. The complete 240-frame map is used for the census-on hold and for scoring. Clean means changed stable fraction <=0.001, the retained C2 clean threshold; >=0.05 is active and intermediate values are ambiguous. Keep only poses with >=50% stable pixels and a clean self-check and interference hold. Every census-on frame's changed stable count is retained. Any census interference still fails the gate even if its pose is not scored. No z-fighting exclusion is assumed or implemented for the initial attempt.

Native code writes all phase-reference PNGs, unstable PNGs, per-frame self/interference counts and the frozen manifest before allowing the first scored-pass frame request. The independent reader recomputes those files and checks every file time and frozen UTC against the first scored-pass image's write time, not injection-start time. First held census samples per actor define pose silhouettes before scoring. Score events only when both edges lie in scored holds and at least half of their visible reference pixels are stable. Unstable pixels are excluded from every C2/C3 numerator and denominator. The pixel classifier does not read the affected label until comparison. FQ2/FQ3/FR2 thresholds are unchanged; a one-frame shift and wrong nonempty target must fail for all four routes. Three complete scored events per route and a late-entering scored target are required. No post-result reference or metric selection.

## Port citations and implementation

* Census: 5.1 `AnomalyCensus.cpp:629-699` credits and releases the matching completed batch; 703-738 bounds in-flight batches and preserves event headroom. The 4.25 map now holds tags through its matching request readback, with at most two batches; event bindings are keyed by ID plus StartFrame and retain their actors/values through the event. Per-frame global restore/flush is removed. Floor 0.5% and ceiling 25% remain inclusive.
* Ledger: shared 5.1 `AnomalyStencilTag.cpp:237-259` restores an individual actor, and 385 onward restores teardown. The 4.25 adapter preserves write masks as well. Host custom-depth actors are excluded before selection and tagging and are never modified. This intentionally differs from 5.1 and is a recorded follow-up, not a change to the 5.1 path.
* Annotation: 5.1 `AnomalyLabelWriter.cpp:768-801` freezes/projects the target bounds; `AnomalyCaptureSubsystem.cpp:10076-10084` accumulates clipped projected screen area and `10270` averages it over affected frames. The adapter uses the same shared frozen-geometry helper. `10097-10103` and `10272` set bbox_source from nonempty drawn measurements, now derived from the independent reduction table. Schema serialization stays byte-equal to the existing 5.1 serializer body.
* Camera: 5.1 captures the view anchor at `AnomalyCaptureSubsystem.cpp:10047-10058`, but exports its legacy default far plane at 10291. FT4 explicitly replaces that default on 4.25: near/far are derived from the actual reversed-Z view projection; zero far denotes an infinite projection. Both values appear in frame rows and annotation, so the reader checks the anchor. This remaining 5.1 default is a follow-up.
* Evidence: street-session raw uint4 bytes are shuffled into 16 byte planes before zlib, with an ASP1 header; decoding reverses the operation exactly. Existing interleaved evidence remains readable. This is lossless storage only, introduced because the longer pre-pass would otherwise approach the D: floor. A kept real frame round-trips byte-for-byte (1,742,236 to 973,612 bytes in the sample).
