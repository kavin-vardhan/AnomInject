## 4. Explanation (hypotheses labelled)

- Source (read, not measured): the writer (`AnomalyAsyncWriter.cpp:23`) and the stage worker (`AnomalyChangeStage.cpp:413`) are both
  `Async(ThreadPool)` at Normal priority → `BackgroundNormal` (`QueuedThreadPoolWrapper.h:460`), 12 background workers on this 16-logical-core box.
  A census head that is `pending` with empty `waits_on` means all four inputs arrived and the queued worker has not started.
- **H-Q (hypothesis, R4 NOT SUPPORTED by the predeclared rule):** the worker waits in that FIFO behind PNG jobs. L4: 11 of 13 census lines
  head-ready, head wait median 185 ms (max 438), ρ 0.99 with the head's own writer latency; L1: 4 of 6 (0.67 < 0.70), median 9 ms.
- Retention tracks the writer backlog; today the writer kept pace with the arm rate on every Lyra ON leg, so the backlog (15–25 frames) and
  retention stayed flat. The build-2 G270 run (081-17R, 300 frames) had arm 23.2 / PNG 21.7 fps and grew 672 → 1528 ms; the writer code is
  identical between build 2 and build 3 and today's first 300 frames show no such growth. **Cause of that difference not established**
  (081-17R had no process sampler and ran 5 min after a three-target build; build 3 changed only the SVE/stage path).

## 5. Change proposed

**None needed for the requalification.** If the stage's retention must later be decoupled from the writer backlog, the smallest change is the
one call at `AnomalyChangeStage.cpp:413`: `AsyncPool(*GThreadPool, …, nullptr, EQueuedWorkPriority::High)` (BackgroundHigh / the High queue),
so the worker is dequeued ahead of queued PNG jobs. It would remove the head-ready dispatch wait, not the head's own writer latency; risk: each
worker slice (~5 ms per frame of arithmetic, under the stage lock) runs ahead of PNG jobs on a saturated CPU. Not implemented.
