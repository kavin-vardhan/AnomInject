## 3. The P2-9 determination (R2.9)

**YES — the product auto-injection path can hold m52 and m53 at the same time on different actors, under its default
concurrency rules.**

- **The concurrency facts:**
  - `MaxConcurrent` defaults to 4 (AAI.h:132; no ini key);
  - `TryFireOnce` removes only the live id (AAI:241-252) and the live actor (AAI:285-289) under the cap (AAI:209-212);
  - the free-running loop expires each hold independently (AAI:187-197, :699-724).
- **The pool:** `stuck_low_mip` is in the pool (AAI:30); only the enabled-set defaults keep it (AAI:35-41) and the m53
  ids (D4) off.
- **m52's co-affected enumeration keeps only `UTexture2D` users** (SLM:101-116), so it cannot see an m53 host, whose MID
  binds render targets.
- **Inside a capture run, the unassisted FSM cannot overlap them:** Run is paused (ACS:2998-3003), there is one fire per
  burst, and every fire is reverted together. But `IAI.Auto.Run` / `Step` / `FireOnce`, raw `IAI.Apply` and the control
  server's `inject` / `auto_fire_once` have no capture-active guard.
- ⇒ **The ruling's "can by default" branch: S2 includes the source fix.** m52 counts an m53 host as a user of the textures
  its MID replaced (`AnomalyTexCorrupt::AppendOriginalTexturesFor`), tested by G5-REV. R2.2's snapshot isolation stands.
- ⚠ **The reading of "by default" is Code's default.** If chat means "with the default enabled set", the answer flips to
  the narrowed limitation, and the fix is still harmless.
