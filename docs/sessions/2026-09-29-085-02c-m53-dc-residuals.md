## 4. Deviations and interpretations, stated

- **F1 is scoped to an m53 partner.** For an m52 partner the pending scan still counts render-truth fires only, and no
  retained-fire read was added (the m52 side has its own trail machinery; the ruling names m53). The retained entry
  reads `label_tail`, and no new state name was added.
- **Consequence, stated:** after an ordinary revert the m53-partner release is now max(R + 2, the last m53-carrying
  snapshot finalized). At readback latency 1 that is still R + 2. Under starvation it can be later, which can shift an
  m52 eligibility (and so a draw) on legs with both families. After a raw early revert, m52 stays out until the
  capture's scheduled revert of that event.
- **N1:** under a lever the round-robin counter does **not** advance (a lever fire is not a round-robin pick, the same
  as a mode-given fire). With `TileProbe` set and no identity lever, a `normal_corruption` targeted fire still takes
  the round-robin, because the tile probe defines a mode for uv only, which is what `Apply` already said.
- **F4 covers the four reachable getters only.** The stuck-mip, LOD-popping and camera-clipping getters are not
  reachable from the census and were left untouched, which keeps the merge surface with `fix/m52-label-timing`
  small. Clause (g) fails if one becomes reachable. Quiet reads re-read `GConfig` on every call inside the scope; the
  cost is one config lookup per candidate and family.
- **The log case is frame-delimited, with no census grammar change** (G385): the census still prints exactly four
  lines, as pinned in the DC plan and the checklist.
- **`tools/m53_glue_check.py` was not asked for.** It was added because the pure mutants test the rules, not the
  engine call sites Codex named.
