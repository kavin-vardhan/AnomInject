## §2. Mount — a worktree, and why the junction was refused

The 4.25 host uses a junction because its build outputs cannot collide with 5.1's. **Lyra is the SAME
engine as StackOBot** (identical EngineAssociation GUID, §1). A junction would make both projects
write the **same** `Plugins/AnomalyInjector/Binaries` and `Intermediate`, so a Lyra build could
silently invalidate StackOBot's byte-identity anchors (`P-C7`) with nobody attributing it.

```
git worktree add --detach E:\UEProjects\LyraStarterGame\Plugins\AnomalyInjector 9083d95
```

**DETACHED, deliberately** (the brief allowed either; this is the choice and the reason): a second
worktree **cannot** check out `master` while the main checkout holds it, and a detached HEAD cannot
be committed to in a way that moves any branch. Refresh with `git -C <path> checkout <sha>`.

✅ **`.gitignore` STOP CONDITION NOT TRIGGERED** — checked BEFORE mounting: `.gitignore:2-3` covers
`Binaries/` and `Intermediate/` (plus `Saved/`, `DerivedDataCache/`), verified with four
`git check-ignore -v` probes, all IGNORED.

⚠ **`.uproject` edited, backed up first** to `LyraStarterGame.uproject.bak` (4,712 B). One entry
added — `{"Name":"AnomalyInjector","Enabled":true}` — 4,712 → 4,774 B, re-parsed with
`ConvertFrom-Json` (68 plugins) to prove it is still valid JSON. **Nothing else in Lyra was enabled.**

🚨 **THE TRAP THAT MADE "MOVE ASIDE" INSUFFICIENT: UE scans `Plugins/` RECURSIVELY for `.uplugin`.**
Parking the stale clone anywhere under `Plugins/` would have been a fatal duplicate-plugin-name
error, not a harmless leftover. It had to leave the tree entirely. → the rule refinement now in
`CLAUDE.md` shared-tree **rule 5**.

## §4. The smoke leg

**New runner `CaptureBench/tools/lyra_leg.ps1`** (CaptureBench is the local-only harness repo).
It is a THIRD runner rather than a flag on the other two, for one substantive reason:

> `-ExecCmds` fires at **STARTUP ONLY**. On `CB_GateLevel` the world is up almost immediately, so
> arming from `-ExecCmds` and letting the focus gate hold frame 1 is fine. **Lyra is not that**: it
> resolves a GameFeature Experience, activates five game-feature plugins, spawns bots, possesses a
> pawn and shows a `CommonLoadingScreen` while doing it. A capture armed at startup would either
> film the load or ride out the focus gate's **30 s safety timeout and start anyway, mid-load.**
> So the runner launches with `IAI.Server.Start` only, waits for `Bringing World … up for play`,
> settles, and **then sends `capture_start` over the control-server WebSocket** (the WS client idiom
> is lifted from `verify_lastrundir.ps1`, which exists for the same reason).

pinning TSR/Lumen/auto-exposure off would delete the thing we came to see.
