### §2.1 The instrument (`40a5202`), committed before the fix

### §2.3 🚨 THE 075 QUARANTINE IS CONTRAINDICATED BY ITS OWN PRE-DECLARED COST

The 075 plan's ruling-2 design was a `Quarantined` map folded into `IsFree`. It also wrote down the
price: *"the quarantine SHRINKS a 55-value pool against a 77-candidate census, so `TAG-POOL
EXHAUSTED` … are pre-declared reads on every leg."*

**Step 0 measured that read to be already non-zero on the A-side, and measured the exhaustion
fallback to be the entire defect.** ⇒ **a quarantine would shrink the pool further and make this
defect MORE frequent.** It is not built, and the predictions file says so before any gate ran.

🔑 **Pricing a fix before writing it can REFUTE it, not merely qualify it.** That is what happened
here, and it is the second time in two sessions that a fix was stopped by reading the thing it was
supposed to change (`G249` was the first).

### §2.5 🚨 THE FIRST VERSION OF THE GATE EXONERATED A REAL COLLISION

The single-owner gate was first built as an **ownership-log join**: rebuild who held each value from
the allocator's own lines, and assert one owner per value per frame. `IAI.Bench.ForceTagCollision`
then produced a genuine two-object frame (66,837 + 48,578 px) and the gate read
**`SINGLE-OWNER :: the extra component is that owner's own disjoint silhouette`**.

**It was right about its own data and wrong about the world.** The intruder was tagged *outside* the
allocator, so it appears in no allocator log. ⇒ the gate was rebuilt to read
**`FAnomalyStencilTagLedger`'s live tag map** — the actual `bRenderCustomDepth` value on the actual
components — which sees a collision **however it was produced**.

📌 **This is exactly why `G2` is a required gate and not a nicety. A gate built on bookkeeping
inherits the bookkeeping's blind spots, and a lever that bypasses the mechanism is the only thing
that finds them.** The rebuilt gate is also **~7× more sensitive**: on `M50PRE_B_FORCE` it reads
**22 violated frames** against the proxy's 4.

## §3. THE FIX

### §3.1 Ruling 2 — census headroom + honest exhaustion

| file | change |
|---|---|
| `AnomalyCensus.h/.cpp` | `EventTagHeadroom = 8`. `ArmNextBatch` stops claiming when `Ledger->NumFree() <= EventTagHeadroom`, counting `HeadroomStops`. The census already handled a short batch by requeueing. |
| `AnomalyMaskMeasure.cpp` | `AllocateTag` **no longer re-issues a claimed value**. It returns **0**; the record is marked `bKnownUnmeasurable` with reason `tag_pool_exhausted`; `ArmIfMeasurable` and `ArmProbeOnHidden` skip it; `BuildBaseTagSet` excludes tag 0. `ArmTargetMaskOwn` already tested `R.Tag != 0`. |

🔑 **Why headroom is the right lever and not merely the cheap one: the two consumers are not
symmetric.** The census is **ELASTIC** — it can arm fewer this batch and requeue, and always could.
The event allocator is **INELASTIC** — an event must have a tag or it cannot be measured. **The
elastic consumer yields.** Nothing about the census's semantics changes; it simply stops taking the
last eight values.

🔑 **And why the exhaustion path had to change anyway.** Even with headroom, the pool has a
structural ceiling (§5). The old behaviour at the ceiling was **a confident wrong number**; the new
behaviour is **an honest absence**, on the same `NOT_MEASURED` ⇒ ADMIT path ruling 3 uses.
⇒ **one mechanism, two causes** — the `A2` "one predicate, two consumers" shape.

### §3.2 Ruling 3 — unmeasurable targets admitted

| file | change |
|---|---|
| **new** `AnomalyMeasurability.h/.cpp` | `ComponentRendersAsNanite` promoted out of `AnomalyCensus.cpp`'s anonymous namespace, plus `IsKnownUnmeasurable(Actor, ShaderPlatform, OutReason)`. ⛔ **Inside `AnomalyCapture`, never `AnomalyViewport`** — that module has no render dependencies and must not gain them (`G127`). |
| `AnomalyCensus.cpp` | `ClassifyCandidate` calls the shared predicate. **Verdicts and counters unmoved** — `census_unmeasurable_nanite` read **29** on the bench G7 leg and **61** on Lyra, so the `G96` proof still fires. |
| `AnomalyMaskMeasure.h/.cpp` | `FAnomalyMaskRecord` gains `bKnownUnmeasurable` + `UnmeasurableReason`; classified at `FindOrAddRecord`; **`ArmIfMeasurable` SKIPS such a record.** |
| `AnomalyLabelWriter.h/.cpp` | one new `run_summary` key, `unmeasurable_targets_admitted`. |

🔑 **Skipping the arm is what makes this a four-file change instead of a veto rewrite.** `R.State`
initialises to `NotMeasured` and is promoted only on a contributing frame. Skip the arm ⇒ no frame
contributes ⇒ the state stays `NotMeasured` ⇒ `MaskStateVetoes` **admits without being touched**,
and every label field falls out of the A1/A2 code that already existed.

⚠ **The `G96` trap the plan declared in advance was avoided:** the predicate is **not** pushed into
`IsRenderableComponent` / the `G33` chokepoint. Doing so would make Nanite components stop counting
as `Renderable`, `NaniteOnly == Renderable` could never hold, and `census_unmeasurable_nanite` would
read a permanent 0 — a live diagnostic silently retired. **Both consumers pass the same argument**
(unlike A2's translucent predicate), and that is stated rather than left to a future diff.

## §5. NAMED LIMITATION, declared in the predictions file rather than discovered

**`EventClaimed` is never released mid-run, and that is deliberate** — `mask_map.json` maps value →
event for the whole session, so re-using a value would make two events in one session ambiguous.
With **55 assignable values** and **one permanent value per event**, a long enough run exhausts the
pool however much headroom the census leaves.

⇒ **The headroom removes the measured cause; it cannot remove the ceiling.** What `m50` changes is
what happens *at* the ceiling: no tag is issued, the event is admitted unmeasured, and
`TAG-POOL EXHAUSTED` stays an `Error` line that every gate reads.
