# 081-01 — m55 "measured change evidence": PLAN ONLY. Make `observable` mean measured visible change, for every anomaly class.

## 0. Why (read before the source)
Three findings this week say the same thing: the verifier cannot attribute pixel change to an anomaly (079 unit, G263); a size rule cannot see texture content (m52 G270 — Lyra events at ratio 26–31 with no pixel change); and `observable` for texture-class anomalies today means "labelled && held && target drawn", i.e. presence, not change (m49 A1). The client's F2 complaint ("labelled, nothing visible") is only closed when the producer measures, per frame, how much the target's own pixels changed because of the injection. That measurement must come from the render, inside the capture, where the target's mask is already known — not from post-hoc frame differencing.

## 2. The design question (answer with source, then propose)
D1 **What to measure.** Per frame, per tagged target: `change_px` = number of target-mask pixels whose colour differs from the SAME pixels one frame earlier by more than a threshold (in the final colour buffer the capture already reads — confirm which: pre- or post-tonemap, and what m49 reads), and `change_frac = change_px / target_pixels`. Options to evaluate: (a) extend the m34 reduce compute pass to also read the previous frame's colour target (retained one frame — memory and lifetime cost, RDG ownership) and accumulate per-tag change counts; (b) a separate small pass over the mask's bbox; (c) CPU readback of the two colour crops (reject unless (a)/(b) are impossible — say why). Camera motion changes every pixel: the measurement must be paired with a control — the same statistic over a ring/background sample or the whole frame — so that `change_frac_target − change_frac_control` is what the label carries (this is the ONLY place a ring/control is sound: same frame pair, same render, no attribution claim — evidence, not a verdict). State the exact fields.
D2 **What it means per class.** Hide-class (missing object): the target's pixels change at onset (object gone) — but after onset there is nothing to compare; define evidence as onset-frame change + `target_drawn_pixels == 0` thereafter (m49 already has the second). Texture-class (corrupted/missing texture, stuck mip, UV corruption m54): per-frame `change_frac_target` above a class floor while the silhouette persists. Flicker/lighting (m53, lighting mismatch): the target is a light, no silhouette — define the region as the light's projected influence (attenuation sphere → screen bbox, or the census of lit primitives) and the statistic as luminance change in that region vs the control; state what the mask pass can and cannot give here. LOD popping / clipping / time dilation: state whether the measurement applies, and what `observable` uses if not.
D3 **How `observable` changes.** Proposal: `observable = current rule AND change evidence ≥ class floor` for classes where it applies; `observable:null` when the measurement was unavailable (no previous frame, mask missing, first frame of the run). Schema: additive keys inside each row (`change_px`, `change_frac_target`, `change_frac_control`, `change_measured`), per-event `change_frac_max/median`; `label_schema` stays 2 (m51 bumps to 3 later). Floors are NOT chosen now: the plan proposes how they are DERIVED (from the bench sessions where the client-verified visibility is known, per class) and predeclared before the implementation gate.
D4 **Cost and safety.** GPU cost per frame at 1280×720 and 1080p; VRAM for the retained colour target; interaction with the mask readback cap (m51 R7) and the writer; what happens under the F1 held-frame path and the pairing defect (the previous-frame colour must belong to the previous CAPTURED frame — identity, again; state how the plan pins it and what it does if the pair is broken: `change_measured:false`).
D5 **Verifier interplay.** The 079 tool stays independent (frame differencing on disk); m55 evidence is the producer's claim. The tool gains a reading line per event comparing its own TRANSITION frames to the producer's `change_frac` onset (agreement is a CONSISTENT-strength statement, disagreement an OFFSET-NOTE — never a verdict).
