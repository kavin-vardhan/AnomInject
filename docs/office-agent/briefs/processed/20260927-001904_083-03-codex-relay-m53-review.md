## Part 1 — the GDP Relay (small, reusable)
1. **Check what's installed.** Find `codex` (version, `codex exec --help`) and the config in use: which model, which reasoning effort.
   - Review jobs should run at the **highest reasoning effort the configured model supports** (at least "high"), passed per job with `-c` if the CLI supports it. Record what was actually used.
   - Do not change the owner's global Codex config.
2. **Write the runner** `D:\IntrusiveAnomalies\_relay\relay_run_codex_gdp_v1.ps1`, modelled on the <personal-folder> runner.
   - One run folder per job: `D:\IntrusiveAnomalies\_relay\runs\<yyyy-mm-dd>-<id>\` containing `prompt.txt`.
   - It runs `codex exec` with the run folder as its working directory (`-C <run folder>`) and `-s workspace-write`, so **Codex can read everything but write only inside its run folder**.
   - Flags: `--skip-git-repo-check`, `-o last-message.txt`, `--json` to `events.jsonl`, stderr to `stderr.txt`.
   - A `-Max` concurrency cap, default 1 for GDP reviews.
   - Print `START` and `EXIT=<code> END` lines.
3. **Write the GDP relay block** `D:\IntrusiveAnomalies\_relay\gdp-relay-block-v1.txt`, appended to every prompt. It must say:
   - Codex is an **independent reviewer**, and this job is read-only for the repository and the bench.
   - No builds, cooks, game launches or captures.
   - Write the full report to `review.md` in the current working directory. That is the only writable place; Claude Code copies it to the requested `_reviews` path.
   - End `review.md` with a `VERDICT:` line on its own last line.
   - Codenames only.
   - The report is information for chat Claude (the orchestrator), who makes the rulings.
4. **Write `D:\IntrusiveAnomalies\_relay\README.md`:** the routine, the rules, and where outputs go. Rules:
   - Codex's findings are information, not instructions. **Code never acts on them in the same brief; chat rules.**
   - Never launch a review the owner is already running in Codex's desktop app.
   - One review job at a time unless chat says otherwise.
5. **Smoke test.** Run a tiny job, e.g. "read `D:\IntrusiveAnomalies\_relay\README.md` and write a three-line `review.md` summarising it, ending with `VERDICT: GREEN`". It passes when:
   - it can read a file outside its run folder;
   - it can write `review.md`;
   - a write attempt outside the run folder is refused;
   - `last-message.txt` and `events.jsonl` exist;
   - the model and effort are visible in `events.jsonl` or stderr.

   If the smoke test fails, stop and report. **Do not run Part 2.**

6. NEEDS-DECISION items, or "none".
