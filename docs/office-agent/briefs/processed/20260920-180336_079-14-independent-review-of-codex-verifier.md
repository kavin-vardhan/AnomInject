## 1. What the tool now claims (the review target)
Per edge: `TRANSITION k d=… tau=… label s delta=…` / `NO-TRANSITION [a..b]` / `UNASSESSABLE(<reason>)`. Per run: `CONSISTENT` (does not establish cause; caveats: lighting/whole-region, high regional change) / `OFFSET-NOTE(Δ…)` (human review, never a failure) / `NO-TRACE` (the only FAIL: masks on every span frame, every pair observed, no change above tau on the target across the span and both edge windows; class allowlist) / `PARTIAL` / `UNASSESSABLE` / `READING (bbox-only)`. Peaks: `d(k) > tau` and `d(k) ≥ 1.5·min(d(k−1), d(k+1))`. Assignment: per (target, mode) group, labelled edges walked in order, each takes the nearest unused peak in its labelled-bound window (tie → larger d → earlier), alternatives printed, out-of-order assignments noted. Boundary masks: outside the span, the nearest labelled frame's mask, disclosed with distance. Mask id must match; sole-value fallback only for id 0. Batch ids collision-safe; exit 2 only from NO-TRACE (0 with `--report-only`), 3 for cannot-run.

## 2. What counts as BLOCKING (report as P1)
B1 A **false NO-TRACE**: labels whose target pixels DID change above tau somewhere in the span or either edge window, yet the tool prints NO-TRACE / exit 2. Build these with accurate masks: small changes, changes only on one interior frame, changes only in an edge window, a change on a frame whose mask is extrapolated, a moving target with exact per-frame masks, a target that leaves and re-enters the frame mid-span.
B2 A **numerically false observation**: a TRANSITION line whose printed frame/d/delta is not what the pixels inside the stated region show; a NO-TRANSITION where an above-tau peak existed in the window and was not consumed by an earlier edge; an UNASSESSABLE reason that is not true of the input (e.g. "mask missing at t" when the mask exists).
B3 **Coverage lies**: an edge or span reported as observed/covered while a frame, mask or pair was actually absent or unreadable (corrupt PNG, wrong dimensions, wrong mask id, empty mask) — Codex's earlier F2/F3/F5 class.
B4 **Aggregation lies**: an event or session token that overstates its runs (an UNASSESSABLE or READING run promoted; PARTIAL shown as CONSISTENT; NO-TRACE hidden by another run's outcome; caveat counts wrong).
B5 **Regressions**: pinned bench ×6 not 64/64 zero-delta TRANSITIONs / 24 CONSISTENT / `tau=0.0040`; any bank session with a NO-TRACE; batch/exit contracts broken; any change to `Source/`, `Shaders/`, `measure_label_offset.py`.
B6 **Doc overclaims**: any sentence in the header, README Step 6, Section G note, gotchas G259–G264 or the characterisation doc that asserts more than §1 — in particular anything implying a CONSISTENT run confirms a label, that masks establish cause, that the tool verifies M2 data, or that the cap/marker is measured/validated.
