## Q1 Artifact acceptance — ACCEPTED with a redefined invariant and one carry-forward
1. The specified gate — banked MainWorld reduce comparison, byte-identical masks, identical count/observable rows, MASK-TIE, onsets, camera, old key sets across predecessor ×2 and candidate off/on/on/off — **passes exactly**. That was the invariance requirement; it is met.
2. The fixed CB_GateLevel recipe: all 71 occupied-pixel maps agree and every nonzero byte equals its row's `mask_value`; only the **tag numbers** differ. The predecessor-vs-predecessor diagnostic (0/71 raw, 71/71 occupancy, first/last tags 247/251 vs 227/250) proves tag allocation is non-deterministic run-to-run on this fixture **without m55**. So "raw mask bytes byte-identical" was never an achievable invariant on CB_GateLevel; the correct invariant is *occupancy-identical AND every nonzero byte == its row's `mask_value`*, which holds 71/71 in every comparison. Ruling: the fixed-fixture invariant is **redefined** to that (with the reason recorded), it passes, and a gotcha is added: *stencil tag values on CB_GateLevel vary run-to-run from the shared tag pool; compare mask occupancy and value-vs-`mask_value`, never raw bytes, when comparing runs.* Not an m55 finding. Optional, small, only if it falls out of a read: name where the tag-pool order is decided (the 080-06 M26 REDUCE-TABLE log may already show it) — no investigation beyond one paragraph.

The **FPS 21.5 vs 30 on evidence-OFF MAIN4** is a performance reading on a leg with m55 disabled, so it is not m55 cost, but it is carried forward verbatim to the Stage 3 A/B/B/A cost gate as a flagged prior: if the cost run shows any leg at that FPS, the run must explain it (hitch, shader prewarm, other) before the gate can be read.
