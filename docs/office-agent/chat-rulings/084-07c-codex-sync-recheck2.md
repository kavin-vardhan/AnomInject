**N2: the required trace-length repair works; the enlarged trace exposes a body-identity problem — medium.**

The default minimum is `1e-3` cm. UE 5.1's actual gate is `DeltaMag > UE_KINDA_SMALL_NUMBER`, i.e. `1e-4` cm (`AnomalyNearClipSlab.h:511–523`; `UE/Source/Runtime/Engine/Private/PhysicsEngine/Experimental/PhysInterface_Chaos.cpp:989–991`). The tenfold margin is sound for avoiding that gate. `PrepareConfirmSegment` uses the entire slab segment when the box-clipped segment is too short, and refuses the trace if even that segment is too short. Both grid paths count only accepted segments as valid traces (`AnomalyNearClipSlab.h:525–542,658–671,716–729`).

`MinFootprintRays=6` is a reasonable reading of the existing sampler's minimum coverage requirement: fewer valid global traces trigger the footprint grid, and fewer than six valid traces overall produce `TooFewValidTraces`, never Miss (`:517,611,688,750–773`). This is a minimum sampling contract, not proof that a finite grid finds every triangle; the existing grid-resolution limitation is not reopened. The zero-thickness wall, degenerate-only case and insufficient/sufficient trace controls are covered at `camera_clipping_slab_selftest.cpp:841–899`.

The full segment stays inside the slab: both endpoints are on its near planes along one view ray, and Chaos receives that finite segment's length (`AnomalyNearClipSlab.h:631–635`; `PhysInterface_Chaos.cpp:1037`). An ordinary independent body cannot make this a world trace against an unrelated object.

**A welded child is different.** `ResolveConfirmTarget` calls `P->GetBodyInstance()` with the default `bGetWelded=true` (`AnomalyViewport.cpp:624`; `UE/Source/Runtime/Engine/Classes/Components/PrimitiveComponent.h:1981`). UE returns the weld parent's body (`UE/Source/Runtime/Engine/Private/PrimitiveComponentPhysics.cpp:817–819`). The plugin checks the child's mesh setup, then traces the returned body and accepts only its boolean hit, without checking the hit component (`AnomalyViewport.cpp:630–636,1284–1292`). Chaos filters shapes against that supplied parent body (`PhysInterface_Chaos.cpp:997–1022`; `BodyInstance.cpp:425–429`). It does not establish that the hit belongs to the child being confirmed.

A concrete conditional case is a visible planar child at x=50 with large bounds and a hole covering the whole view there, welded to a parent with a complex-collision face at x=80. The parent can be hidden independently while retaining collision. With near planes 10 and 100, the child's clipped segment has zero length at x=50. The new fallback extends it to [10,100] and can hit the parent's face, producing a confirmed positive without `camera_clipping_unconfirmed`, although the visible child contributes no geometry in the viewed slab. This is a newly enabled false confirmation, not an outside-slab hit. The source-derived segment example is retained in `review-evidence.json` under `source_models.N2_welded_parent`; it was not executed in UE.

Proposed correction for chat: require a trace body/shape known to belong to the candidate, or classify welded candidates as unconfirmable until that identity is established. Merely changing the flag to `GetBodyInstance(..., false)` would itself need checking against Chaos's weld handling. A regression test would need to cover the production body-selection adapter, not just mathematical triangles supplied directly to `ConfirmSlab`.
