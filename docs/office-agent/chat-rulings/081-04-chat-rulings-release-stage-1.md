## Q1 Identity (D1–D3) — APPROVED as Codex specified
- **D1** Bind `run_epoch` and `cut_counter` at request creation (the game-thread arm/issue point), carry them unchanged through the colour and mask submissions, and reject old-generation work **before** a receipt is assembled or admitted. Receipts are immutable once published; a writer's later success is a separate immutable completion record keyed by the same identity, never a mutation. Gate G-EPOCH is strengthened: reset with an old colour readback **and** an old mask result still in flight (force it — issue, reset, then let them complete), expect both rejected with the counter and zero admitted receipts from the old generation.
- **D2** One supported capture owner: the change stage accepts exactly one view family — the one the capture subsystem already targets — and carries a **capture identity token** minted at issue time and shared by that capture's colour request, mask request and counts (the two request serials stay as they are; the token is the correlation key, not their raw ids). Mask receipts carry epoch, cut, token, geometry. Any callback for a family/view that does not carry the current token, or a second callback under an already-served token, is rejected and counted (`view_rejected`, `duplicate_callback`), never "first index-0 wins".
- **D3** G-COALESCE must **force** two distinct capture-mask requests to stay pending until one serving pass consumes both (bench lever that defers the mask pass by one frame is acceptable); record served-request count, request ids, token, payload owner; the gate requires the served-≥2 counter to be nonzero and the non-owner request to reach `mask_payload_missing` correctly. G-VIEW gains the two cases Codex named: two families at index 0 in the same scene frame (bench: a second, throwaway view family — cite what makes it), and a duplicate callback under one token.

## Q2 Closure and refusals (D4) — CONFIRMED
Ordering contract, in this order and written into §3: (1) phase/event end is observed on the game thread ⇒ a **closure watermark** (the last session index that belongs to the phase) is queued; (2) admitted work at or below the watermark resolves through the ordered stage, bounded by a terminal deadline stated in captured frames (propose 8) and wall time (propose 2 s), whichever first; (3) the phase record becomes immutable, then the event record; (4) results arriving after (3) are rejected and counted; (5) only then may a reset/FinishRun clear state — reset **persists** finalised records first (teardown included: a run that never reaches FinishRun still flushes its sidecar and final records on teardown, best-effort, with a `teardown_flush` counter). Work still unresolved at the deadline is finalised with the reason below, never silently dropped.
Enum revision (closed set, 14 values): keep the twelve; add `current_undelivered` (this frame's own readback/encode/write failed — colour, mask or writer, with a `stage` sub-field naming which) and `closure_timeout` (terminal deadline reached with work unresolved). `predecessor_undelivered` keeps its narrow meaning. No other value may be emitted; the field reference lists all 14.

## Q3 Artifact contract (D5) — CONFIRMED
- Sidecar pair records gain a compact `receipt` block: `run_epoch`, `cut_counter`, `capture_token`, `view_family_id`, `rect` (x,y,w,h), `extent` (w,h), `format`, `t_submit_ms`, `t_drain_ms` (both monotonic engine time, ms, integers; documented as submit = issue on the game thread, drain = render-thread drain completion) for the current frame, and the same `t_*` pair for the predecessor. The hitch caveat reads from those.
- `cam_delta` is three quantised fields, not one magnitude: `cam_dpos_cm` (integer cm), `cam_drot_deg` (tenths of a degree, integer), `cam_dfov_deg` (tenths). `cam_moved` = any of the three nonzero. All caveat fields; none a validity rule.
- Event record gains a top-level `reason` (nullable; set for zero-phase events, e.g. `no_labelled_frames`) and `phase_count`.
- Final event detail lives in the **sidecar only** for v1; `run_summary` carries counters plus one `change_evidence_file` path. R4's "both" is withdrawn.

## Q4 Implementation clarifications (D6–D7) — ACCEPTED
- **D6** Histogram claim corrected: exact strict-> thresholds recoverable from the bins are exactly 0, 2, 4, 8, 16, 32, 64; any other threshold needs the images. Bins unchanged. Control wording corrected: excluding the union of tag masks excludes their mask **pixels**; spill outside masks (lighting, shadow) remains in the control — say so where the claim was.
- **D7** Filter-then-freeze: apply the non-event-tag zeroing to the mutable local first, then freeze into the shared immutable ref, then hand to the mask writer and the change stage; the frozen buffer is the delivered mask by construction (assert equality against the written mask PNG in one gate). Colour: immutable canonical bytes + a separate completion record. Byte accounting: the m55 counter owns exactly the admitted canonical colour buffers and the retained pre-onset reference (so ≤ 3 buffers: predecessor, current, ref) and the frozen masks it holds; reservation happens at admission, admission fails with `budget_exceeded` **without** taking a reference; back-pressure never blocks writer workers — the change stage waits on its own queue only, and the predecessor a writer worker still holds is reached through the shared ref, not by waiting for that worker. State plainly that the writer's own total memory bound is an m51 limitation this stage does not bound.
