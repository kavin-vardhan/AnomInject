## R2 - accounting is still contradictory (blocking)

1. **Logical admission versus physical reservation is conflated again.** B.1 owner 4 and B.4 row 7 retain admission credit until GPU retirement. Frozen release-hardening A2.1 rule 6 (:1234) retires logical capacity at the terminal transition, and the 078-16 brief explicitly required preserving it while separately charging physical work. A physical reservation/readback can remain live after logical cancellation; it must have its own bounded account. B.6 claims the prior rule unchanged, so these two definitions cannot both govern. Keep A1.6's fire-ended AND physically resolved tag rule; do not substitute logical ArmsResolved alone for physical retirement.
2. **Pre-submit failure is mislabeled as post-submit.** B.2 says Failed(payload) is reached only after submission; B.4 row 4 reaches it with no submission, and row 10 puts ForceMiss after Submitted. Exact AnomalySceneViewExtension.cpp:93-105 returns on lookup miss before the readback is allocated (:147), AddEnqueueCopyPass (:149), and SubmitInFlight (:159). Empty rect and extent clamp also return first. 'Rendered scene' is not 'plugin readback submitted.' Keep explicit published-but-no-readback outcomes. A.2's claim that Matches minus Submits is *exactly* consumed-but-never-submitted requests also needs a boundary and one-to-one assumptions: it includes outstanding not-yet-submitted work and can be offset by repeated per-view submissions through the non-consuming lookup.
3. **RDG scheduling still is pass construction.** B.1 says owner 3 begins at AddEnqueueCopyPass, 'not at pass construction.' UE RenderGraphUtils.cpp:842-879 implements AddEnqueueCopyPass by GraphBuilder.AddPass; EnqueueCopy runs inside the later pass lambda. Define reservation/allocation, scheduled-pass ownership, GPU submission and retirement distinctly. No race between cancellation and scheduling may free a referenced readback.
4. **Conservation does not have one consistent admission boundary.** B.2 Armed already owns admission credit; A.4 'admission' is publication membership; B.4 row 3 is explicitly 'unadmitted' yet terminal Cancelled(unrendered), which B.3 counts on admitted's RHS. Define initial logical admission separately from publication admission. B.4 row 11 calls cap refusal 'not a hole' and mints no key; mid-run requested indices still require explicit failure accounting. A pre-StartRun configuration refusal is a different event.
5. **Late notification is counted as a second terminal.** B.2/B.3 place Rejected(late) in the disjoint terminal set; B.4 row 9 and N-LC2 say a previously terminal request's late completion changes no ledger. One cancelled request followed by a late delivery must remain one cancelled request, plus a separate late-delivery diagnostic. Old-generation duplicates likewise cannot overwrite an earlier terminal reason. This matters independently of the acknowledged missing late-completion injector.
6. **Retention/reconciliation is not yet sound.** B.5 does not define how a watermark advances over out-of-order terminals without rejecting an older live request. Monotonic issuance is not monotonic retirement. It also omits live/publication/payload references from reclamation and bounding of per-generation maps. Per-index reconciliation cannot be reconstructed from aggregate ledger counts after IDs are discarded: two different missing-index sets can have identical counts. Declare a bounded or streamed per-index record and final complete requested-index accounting; never infer it from written files alone.

Reduction tables and shared pixel payloads have lifetimes even without RGB/row jobs; census can request pixels (AnomalyCensus.cpp:797-802, also acknowledged in A.3). Reference/byte accounting for all payload consumers is required, not just the encoder's job lifetime. All physical balance equations need explicit outstanding terms or an explicit quiescent-only scope.

These are design contradictions, not runtime findings. No new run or checker was used to derive them.
