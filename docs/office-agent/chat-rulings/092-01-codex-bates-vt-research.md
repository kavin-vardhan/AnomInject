**092-01 — Independent read-only review: virtual textures on Bates**

**INFERRED — Answer to the owner's question.** There are credible plugin-only solutions for all three anomaly families, but none is a safe removal of the existing `virtual_texture` check. An ordinary render target cannot replace a streaming virtual texture in an unchanged VT sampler. The strongest general direction is a private texture that actually exposes a VT resource; a particularly small version of that design could implement blurry textures using UE's existing first-mip resource constructor. Mesh changes offer a separate, conditional route for UV tiling and normal corruption, including constant textures. They are not universal substitutes for the shipped texture operations. The proposed tangent recipe for `invert` needs correcting. These are source-supported designs, not implemented or tested fixes. Evidence and limitations follow.

It is different from a component whose required proxy bindings must all be transformable (`A/TexCorruptTree.cpp:665–739`). The supplied `virtual_texture` counts must therefore be interpreted with route selection, not as a universal property of an actor.

**VERIFIED-FROM-SOURCE — The MID setter accepts the object, but does not change the compiled sampler.** `UMaterialInstanceDynamic::SetTextureParameterValueByInfo` forwards a `UTexture*` (`EN/Private/Materials/MaterialInstanceDynamic.cpp:221–249`). Successful setter/getter round-trip is therefore not proof of successful rendering.

**VERIFIED-FROM-SOURCE — The renderer explicitly rejects a non-VT resource for a VT stack layer.** It obtains each replacement's resource and calls `GetVirtualTexture2DResource()`. It allocates a VT stack only when a valid producer layer was found (`3733–3752`). It will not sample that RT as the intended replacement image. Do not promise one universal black-screen outcome for every partly valid multi-layer stack, and do not claim that the setter itself always rejects or crashes: the source proves the mismatch and fallback paths, not a uniform result for every invalid mixture. Removing the guard would create label/picture risk, and some mixed configurations encounter additional assumptions/checks. **VERIFIED-FROM-SOURCE — A streaming VT is not an ordinary render target with a flag.** `UTexture2D::CreateTransient` creates conventional platform mip data (`EN/Private/Texture2D.cpp:1034–1065`). **INFERRED — This does not mean runtime VT resources are impossible.** UE publicly exports `FVirtualTexture2DResource` constructors, including an empty one explicitly intended for non-`UTexture2D` media textures (`EN/Public/TextureResource.h:161–214`; `EN/Private/Texture2D.cpp:1226–1236`). `UTexture` has virtual resource/type/VT-query methods (`EN/Classes/Engine/Texture.h:1450–1466`). The public renderer interface registers plugin producers and allocates VT stacks (`RC/RendererInterface.h:876–893`); `IVirtualTexture` explicitly supports runtime generation (`RC/VirtualTexturing.h:265–319`). A plugin can design a real VT-backed texture whose pages are generated from an RT or another source. That is a custom resource/producer implementation, not automatic conversion of the shipped RT. Runtime Virtual Texture volume assets are a separate material mechanism; substituting an RVT asset for an existing streaming-VT sample is not an automatic escape from its compiled resource contract.

**2a. Decode VT into a non-VT copy: useful intermediate, incomplete fix**

**INFERRED — Feasible decoding design.** A plugin can ship cooked draw materials with **Virtual Color / Virtual Linear Color / Virtual Normal** samplers, explicitly sample selected VT levels, and render a conventional texture. UE exposes region-specific tile requests and a render-thread pending-load operation (`RC/RendererInterface.h:888–893`; `VT/VirtualTextureSystem.cpp:1184–1237`), and its translator emits virtual sampling and normal unpacking (`EN/Private/Materials/HLSLMaterialTranslator.cpp:5667–5680`, `5779–5782`). The current plugin draw materials instead use ordinary sampler types (`P/tools/create_texcorrupt_assets.py:235–245`, `265–290`); new cooked permutations and a separate readiness/snapshot path would be necessary.

**INFERRED — Prefetch is work and changes residency.** Requested source tiles must really be available before accepting the copy; scheduling a request is not itself evidence of a complete image. Page borders, block/UDIM layout, mip selection, address/filter modes, sRGB conversion, normal unpack/re-encode, sparse fallback and asynchronous source/resource changes all matter. The ordinary RHI copy in `A/TexCorruptDraw.cpp:174–250` cannot interpret a VT physical cache as a spatial image. UE's VT lookup uses page tables to address that cache (`SH/VirtualTextureCommon.ush:302–326`; `EN/Private/Materials/MaterialUniformExpressions.cpp:1242–1275`). Prefetching the original shared source would also improve/alter its residency, conflicting with `R:25`. An acceptable design would need private producer/page residency or another bounded source snapshot strategy and an identity control; it must not quietly call “force resident” on the host source.

**INFERRED — Binding verdict: blocked for an unchanged VT sampler.** The decoded non-VT copy remains useful for inspection, transformed page generation or a separately compatible host material, but cannot directly serve the original VT binding. The exact source test is `MaterialShared.cpp:3711–3725`, not the presence of a parameter name. Even named VT parameters need a genuine VT replacement. Changing every affected material to an ordinary sampler would require corresponding cooked material shaders and preservation of its whole graph; a generic plugin replacement material would lose host shading features. A full VT wrapper around the copy solves the resource-type problem in principle, at additional memory/producer cost (`RC/VirtualTexturing.h:241–259`, `296–319`).

**2b. Mesh-side UV and tangent changes**

**VERIFIED-FROM-SOURCE — Mesh data and texture storage are separate.** The local vertex factory passes mesh texture coordinates and reconstructs the tangent basis independently of whether a material sample uses ordinary or virtual textures (`SH/LocalVertexFactory.ush:621`, `788–824`). Mesh-side changes therefore bypass the named-texture replacement requirement itself (`A/TexCorruptTree.cpp:462–465`). Whether the resulting picture still means the shipped subtype is a separate issue.

**INFERRED — Important correction to the suggested normal recipe.** Let stored tangent X be `T`, geometric normal be `N`, and the stored handedness be `s`. UE reconstructs `B = s × cross(N,T)`. A sampled tangent-space normal becomes `normalize(xT + yB + zN)`. Therefore:

| Intended effect | Change to stored X and handedness | Resulting basis | Classification |
|---|---|---|---|
| Shipped `invert`: flip sampled X and Y | `T' = -T`, **`s' = s`**, `N' = N` | `(-T,-B,N)` | INFERRED mathematical equivalence for the same input normal vector |
| Shipped `green_flip`: flip sampled Y only | `T' = T`, `s' = -s`, `N' = N` | `(T,-B,N)` | INFERRED mathematical equivalence for the same input normal vector |
| Proposed “negate X and bitangent sign” | `T' = -T`, `s' = -s`, `N' = N` | `(-T,B,N)` | INFERRED: **X/red flip only**, not shipped `invert` |

**VERIFIED-FROM-SOURCE — Sign evidence.** `EN/Public/Rendering/StaticMeshVertexBuffer.h:13–38` stores packed X and Z, with the determinant sign in Z.w; setters derive that sign from the supplied basis. `SH/LocalVertexFactory.ush:806–823` reconstructs B, then re-orthogonalizes X; `919–921` combines handedness with the instance transform determinant. Pixel reconstruction again uses `cross(N,T) * sign` (`SH/MaterialTemplate.ush:3431–3440`). The final tangent-space normal is normalized/transformed and receives the two-sided factor (`3033–3054`). Texture-side plugin `invert` sets both signs negative and `green_flip` only Y (`A/Anomaly_TexCorrupt.cpp:439–440`; `P/tools/create_texcorrupt_assets.py:97–110`; `D:1311–1315`). If using a setter that accepts full XYZ basis vectors, supply `(-T,-B,N)` for invert or `(T,-B,N)` for green flip; let it encode the correct sign.

**INFERRED — The algebra is exact at the basis-transform stage, not universally through an arbitrary material.** Texture-side corruption changes each sampled normal **before** the host graph; changing the mesh basis changes the final transform and any other graph operations consuming tangent-space axes. For a simple tangent-space normal-map material, and graph operations that commute with the sign flip, these agree algebraically, including reflected instance transforms when handedness is preserved correctly. For an arbitrary graph `f`, `f(sign × n)` need not equal `sign × f(n)`. Blends with unaffected procedural normals, tangent-space vector operations, parallax/view transforms, anisotropy, using normal channels in other outputs, world-space normal mode, or regenerated tangents can break equivalence. Encoding/quantization/filtering also prevents a blanket pixel-identical claim. Engine evidence: `SH/Common.ush:1371–1383` normal unpack; `SH/MaterialTemplate.ush:3033–3054` final graph output/space selection. Plugin evidence: the sample-stage sign code above. A flat `(0,0,1)` normal remains unchanged, so the route cannot truthfully claim a visible anomaly merely because a buffer changed. If the intended product accepts the broader basis effect, a separately specified subtype such as `tangent_basis_flip` would be more honest than asserting sample-stage equivalence on unverified graphs.

**INFERRED — UV × N can implement a restricted tile subtype.** With unchanged topology, multiplication is linear, so interpolating multiplied vertex UVs yields multiplied per-pixel UVs. For direct sampling through that channel, wrapping addressing and compatible mip selection, it repeats the same texture N times. This works for VT and constant samples too. Do not apply `frac` independently at vertices: interpolation across wrapped vertices would destroy the intended mapping. The shipped copy evaluates `frac(uv × N + offset)` inside the texture redraw (`P/tools/create_texcorrupt_assets.py:41–66`; `A/Anomaly_TexCorrupt.cpp:416`), and offsets source mip by `floor(log2(N))` (`A/TexCorruptPure.h:1450–1469`). Mesh UV scaling also changes derivatives, but explicit mip inputs, anisotropy, prefiltered copy mips and non-wrap sampling make strict equivalence conditional.

**INFERRED — It does not tile every texture in every host material.** Abstractly, the texture route gives approximately `T(frac(N × g(u)))`, whereas mesh scaling gives `T(g(N × u))`. A host offset/panner makes these differ; another UV channel is unaffected; world-aligned/procedural coordinates may ignore mesh UVs entirely. Scaling all channels may alter lightmaps, opacity, WPO, masks or nontexture graph calculations. UE separately retrieves UV channels/lightmap coordinates (`SH/LocalVertexFactory.ush:621`, `1040`), whereas the plugin's UV family requires its whole relevant texture footprint (`A/TexCorruptTree.cpp:665–680`). A restricted fallback should record channels and use a truthful new subtype such as `uv_channel_tile` unless equivalence to the documented `tile` has been established for that material. It cannot silently relax complete-component picture agreement.

**INFERRED — Scramble is not a generic vertex-UV edit.** The shipped scramble is a discontinuous texel-cell permutation, with a different affine offset on each cell (`P/tools/create_texcorrupt_assets.py:41–66`; `D:1310`). A fixed triangle's interpolated UV mapping cannot represent arbitrary discontinuities through its interior. It is possible in principle to split every triangle at every relevant UV-cell boundary, duplicate seam vertices and assign piecewise mappings for one known direct UV sample. Thus “mathematically impossible for any mesh” is too strong. But multiple UV channels, different sample coordinate expressions, filtering across cell edges, LODs and potentially huge topology expansion make this an unsuitable generic mesh fallback. Per-island permutation or per-triangle offsets are plausible separate effects, named for example `uv_island_shuffle` or `uv_triangle_offset`, **never `scramble`**. Exact texture-cell scramble belongs in a texture/VT-page transform or a compatible precompiled material path.

**VERIFIED-FROM-SOURCE — Cooked input access is a real constraint.** `bAllowCPUAccess` exists specifically to retain cooked geometry on the CPU (`EN/Classes/Engine/StaticMesh.h:1105–1110`); cooked serialization uses this policy (`EN/Private/StaticMesh.cpp:491–531`). Original mesh-description access is editor-only (`EN/Classes/Engine/StaticMesh.h:1295–1314`). UE does expose asynchronous GPU-buffer readback with readiness, enqueue, lock and unlock (`E/Source/Runtime/RHI/Public/RHIGPUReadback.h:31–37`, `88–96`).

**INFERRED — Practical acquisition plan.** Read existing cooked CPU render buffers when retained. Setting `bAllowCPUAccess` after discarded data is gone does not reconstruct it. Otherwise copy available GPU vertex/index buffers into staging resources, fence/read back and reconstruct the needed attributes. This must preserve packing, precision, index width, sections, color overrides, seams and every UV channel. Retain a coherent mesh/resource generation through the copy, as `R:24` requires for texture snapshots. GPU readback is a candidate mechanism, not proof all RHIs or streamed/stripped LODs are recoverable: nonresident or cook-stripped LODs are not magically in the captured GPU buffers. A packaged test is indispensable; PIE often retains data unavailable in a cook.

**VERIFIED-FROM-SOURCE — Material usage is a cooked-shader requirement, not just a boolean to toggle.** UE's missing-usage path warns that the default material will be used in game (`EN/Private/Materials/Material.cpp:1734–1795`); static-lighting usage can trigger default-material fallback on a static mesh (`EN/Private/StaticMeshRender.cpp:2224–2227`). **VERIFIED-FROM-SOURCE — `SetStaticMesh` has important side effects.** On a registered static component after play has begun, the normal setter can refuse the change (`EN/Private/Components/StaticMeshComponent.cpp:2172–2180`). When it succeeds it dirties render state, recreates physics state, updates navigation relevance, notifies streaming, updates bounds and refreshes material/PSO state (`2198–2227`). Changing mobility itself re-registers components and can propagate to children (`EN/Private/Components/SceneComponent.cpp:2686–2702`).

**INFERRED — Collision, navigation and physics cannot be hand-waved away.** UV/tangent edits do not require a changed collision shape, so preserve the original immutable collision data and navigational behavior wherever possible. But recreating a physics actor can disturb velocities, contacts, overlaps or constraints even when its shape is identical. Changing static mobility just to enable a swap can disturb baked lighting and registration. A render-only replacement is preferable for such cases if identity can be proved; active simulation is a separate hard case. Restoring the mesh pointer alone is not proof of exact physical or visual revert. These are rules 1, 2 and 4 concerns, not an excuse to modify host assets globally.

That is defensible only when the event and target mask intentionally cover that entire component. It is not per-instance targeting. Splitting one instance adds transform/custom-data/random-ID, cluster, physics and mask work. Engine evidence: `EN/Private/InstancedStaticMesh.cpp:1296`, `1399`, `1684–1733`, `2527–2610`; `EN/Private/HierarchicalInstancedStaticMesh.cpp:2897`, `3212`. Skeletal meshes require skin weights, bone mappings, morph, cloth and skin-cache/LOD data, not a frozen static copy (`EN/Public/Rendering/SkeletalMeshLODRenderData.h:126–142`). Skin-cache tangent recomputation can overwrite the intended basis (`EN/Private/GPUSkinCache.cpp:1489–1500`). Skeletal support is a substantial separate project. Nanite is already excluded by default (`A/TexCorruptTree.cpp:1199–1232`; `D:956`); cloning its fallback does not establish identity with Nanite rendering.

**VERIFIED-FROM-SOURCE — Target-mask integration is not automatic for a replacement component.** Visibility/admission currently recognizes static-mesh and skinned-mesh component geometry (`I/AnomalyViewport.cpp:794–829`). The stencil pass enumerates primitives but checks renderability and event scope before tagging; it saves and restores existing custom-depth/stencil state (`C/AnomalyStencilTag.cpp:146–191`, `251`, `326–391`).

**INFERRED — Mask/revert design.** Keeping the existing admitted component and swapping only a valid private mesh retains its component identity, but all other side effects above remain. A separate dynamic/procedural/render-only component needs explicit admission, scope and mask handling; the hidden original must not be tagged as the changed picture. Installation must become label-active only after the altered render state is actually usable, and teardown must use the existing transition discipline (`D:939–1000`). Retain the original mesh, raw material override state and every changed component property; restore only while the event still owns the installed replacement, leaving later game-authored changes alone. The current texture route models this ownership check and raw-override restoration (`A/Anomaly_TexCorrupt.cpp:1363`, `1456–1461`, `1553`, `1595–1648`). Release private GPU/CPU resources only after rendering no longer references them, including owner destruction and interrupted events.

**INFERRED — Memory bound.** A mesh clone adds vertex/index data per copied LOD, frequently CPU and GPU copies plus staging. Budget positions, packed tangent basis, every UV channel, colors, indices and auxiliary rendering data, with a peak during original + staging + replacement overlap. A full uncompressed BGRA8 texture chain alone is approximately `4 × W × H × 4/3` bytes, before scratch/VT cache allocations. The shipped RT cap (`D:1357`) is not automatically a cap on a new mesh/producer/readback route. A shared peak-memory ledger and bounded preparation queue are necessary to meet rule 3; refusing an actual cap excess remains legitimate.

**INFERRED — Best initial VT-blur design: private coarse VT resource using existing cooked data.** Retain the source texture, then have a transient plugin texture create its own `FVirtualTexture2DResource(sourceOwner, sourceVTData, sourceFirstMip + drop)`. The exported constructor takes exactly that last parameter (`EN/Public/TextureResource.h:164–166`). UE registers an upload producer with that first-mip offset (`EN/Private/Texture2D.cpp:1239–1250`, `1303–1332`), and the upload producer adds the offset when reading source pages (`EN/Private/VT/UploadingVirtualTexture.cpp:61–64`, `128–130`). Bind this **genuine VT** in a private MID, with matching stack tile/border sizes and original sample interpretation. This preserves the host's compiled VT shader rather than trying to feed it an RT. No engine-source modification is implied.

**VERIFIED-FROM-SOURCE — Supporting API/ownership details.** The source VT built-data pointer is exposed in `FTexturePlatformData` (`EN/Classes/Engine/Texture.h:779`); its full implementation and `FUploadingVirtualTexture` are engine-private. A plugin need not instantiate the private uploader to call the exported resource constructor with an opaque pointer. The upload producer keeps a raw data pointer and does not delete that built data in its destructor (`EN/Private/VT/UploadingVirtualTexture.cpp:61–97`). VT resources release their own allocation/producer (`EN/Private/Texture2D.cpp:1487–1492`). Materials normally allocate their own VT stack rather than requiring `AcquireAllocatedVT()` on each texture (`EN/Public/TextureResource.h:185–191`).

**INFERRED — Conditions and limits on that design.** This is the smallest convincing source route, but it is still a prototype proposal. Keep the source UObject/platform data alive through every pending IO/render operation; do not install a borrowed platform-data pointer into a second owning `UTexture2D` and create double-free ownership. Implement accurate virtual material type/query/size metadata on the wrapper; do not fake only the boolean. Derive the baseline from the effective existing VT resource, not from ordinary resident-mip telemetry. Retain original SRGB/filter/address/normal interpretation and compatible layer formats. The constructor clamps dropping so the virtual dimensions do not go below one tile (`Texture2D.cpp:1247–1250`); stronger blur below that finest-size limit needs a producer that deliberately supplies coarser source information. Validate multi-layer stacks, sparse/UDIM sources and nonzero existing bias. Registration/cache lifetime and packaged linkage must be demonstrated before claiming this works in the plugin.

**INFERRED — Per-object effect, but new route semantics.** The private resource affects only components whose bindings are replaced, even though it reads the source's cooked data. The original source producer remains unchanged. That is proxy blur on a VT, not the old “held resident mip count” route. Labels/telemetry should explicitly record VT proxy mode, effective source first mip/drop, dimensions and readiness; do not report a measured hold based on `GetNumResidentMips()`. Existing proxy docs already distinguish the picture from holding source residency (`D:714–724`). Route selection also needs updating: current auto dispatch checks sharing only among textures classified as ordinary eligible (`A/Anomaly_StuckLowMip.cpp:732–741`), so a VT-only object does not automatically arrive at a newly added VT proxy merely because the proxy can now handle it.

**INFERRED — Plugin integration is more than construction.** A new route needs VT-aware texture facts, eligibility, uniformity/identity analysis, memory accounting, preparation states and ownership/teardown evidence. It cannot keep treating ordinary `PlatformData->Mips` or `CachedSRRState` as VT residency, or silently fall through the existing Standard2D/parameter gates. Existing assumptions are explicit in `A/TexCorruptTree.cpp:322–377`, `448–465`, `509–530` and `A/TexCorruptUniform.cpp:338`; the different engine residency meaning is explicit in `EN/Private/Texture2D.cpp:455–479`. The existing routes should remain intact while the new route reports its own measurable guarantees.

**INFERRED — Private does not mean free of pool effects.** Independent producer identity prevents another object from sharing the corrupted page mapping. Its pages can still compete for physical cache space. Physical spaces are acquired/reused by description (`VT/VirtualTextureSystem.cpp:989`), and pool pressure can feed the global residency bias (`2675–2685`). Budget pages/preparation/concurrency and measure unchanged co-users; do not assume a private page-table-space flag guarantees an isolated physical cache. This is another reason to start with coarse VT sources instead of decoding all fine tiles globally.

**INFERRED — More general VT producer, for all three anomalies.** A custom `IVirtualTexture` can generate pages from transformed source data, including correct borders and mips, and expose a `FVirtualTexture2DResource` compatible with the host stack (`RC/VirtualTexturing.h:241–259`, `296–319`; `EN/Public/TextureResource.h:161–214`). It could provide UV tiling/scramble and normal X/Y flips in texture space, preserving arbitrary downstream host graph behavior better than basis changes. It can also expose only coarse detail for blur. A full non-VT snapshot wrapped in such a producer is one option, but duplicates memory; on-demand page transforms require more complex source acquisition, GPU draws/encoding and fences. A default-constructed resource needs correctly implemented virtual size/format/tile methods and its own allocation handling; blindly calling the stock `AcquireAllocatedVT()` would dereference `VTData`/owner (`EN/Private/Texture2D.cpp:1495–1512`). This is substantial plugin code, not a blocked engine capability.

**2d / 3. Constant textures, material-side alternatives, and the hold misconception**

**VERIFIED-FROM-SOURCE — Why named parameters matter to today's texture routes.** `A/TexCorruptTree.cpp:462–465` rejects `ParameterInfo.Name.IsNone()`. The eventual install is `SetTextureParameterValueByInfo` on a private MID (`A/Anomaly_TexCorrupt.cpp:1124–1144`). For an unnamed texture expression UE skips `FMaterialRenderProxy::GetTextureValue` and obtains the compiled indexed texture reference (`EN/Private/Materials/MaterialUniformExpressions.cpp:120–125`, `637–651`). Thus a new arbitrary parameter name, or overriding only `GetTextureValue` on a proxy, does not redirect those constant samples. UV needs all applicable bindings, normal needs its applicable normal maps and blurry proxy its eligible streaming footprint (`A/TexCorruptTree.cpp:665–712`); one unnamed required binding can produce `partial_footprint`.

**VERIFIED-FROM-SOURCE — The hold does not need texture parameters.** It gathers `UTexture2D`s using `Component->GetUsedTextures`, not a named-parameter list (`A/Anomaly_StuckLowMip.cpp:265–279`, `379–401`). It changes the source texture's cinematic-mip limit (`950–985`), so constant samples see the same resource change. Source sharing is the constraint: it checks world users and ordinary streamability (`392–400`, `827–871`). Existing hold revert restores the saved cinematic setting and requests stream-in (`1219–1226`, `1466`). A uniquely used ordinary streamable constant texture is already eligible in principle; there is no parameter guard to remove from that route.

**INFERRED — Interpretation of Bates's blurry `texture_not_parameter` count.** The 635 primary and 392 partial subreason cases concern the named-binding proxy evaluation/selected route, not proof that hold fundamentally requires a parameter. The census evaluates hold separately and emits `hold_eligible`, `proxy_eligible`, `auto_hold`, `auto_proxy` (`A/TexCorruptTree.cpp:1824–1852`, `1915–1916`). Those missing route totals are necessary before proposing a hold-policy change. Forcing hold for shared constant textures would corrupt non-target co-users; that fails rule 2. For VT constants, both the current hold mechanism and ordinary MID replacement remain unsuitable.
