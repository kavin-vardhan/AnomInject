## 0. The shipped contract, and the hypotheses being decided

**VERIFIED-FROM-SOURCE — Tile:** `TileN` accepts only **2, 4, 8, 16**, default **8**; N=1 is an identity fixture, not a released knob value (`A/TexCorruptState.cpp:241–244`). The copy shader uses `frac(UV * N + offset)`; shipped offsets are zero. For destination mip L it samples source mip `clamp(L + floor(log2(N)), 0, sourceMipCount-1)`, subject to the existing source/drop/bias bookkeeping. Thus the released copy deliberately has N repetitions and less detail in its top level; it is not simply a host-material UV multiplier with full original magnification detail. Sources: `P/tools/create_texcorrupt_assets.py:41–66,235–246`; `A/TexCorruptPure.h:1450–1469`; `A/Anomaly_TexCorrupt.cpp:402–419`.

**VERIFIED-FROM-SOURCE — Scramble:** K is a **cell count per axis**, integer **2–64**, default **8**, not a pixel size and not restricted to powers of two. At a source/destination mip of dimensions W_L × H_L, nominal cell dimensions are W_L/K × H_L/K. The forward permutation is `j=(A*i+B) mod K²`; destination cell j samples source cell `i=Ainv*(j-B) mod K²`, preserving its fractional position within the cell. Cells are row-major. A is chosen from the ascending coprimes of K² using `(H>>16) mod phi(K²)`, B is `H mod K²`, and the identity A=1,B=0 is changed to B=1. H is CRC32, initial CRC zero, of three little-endian 32-bit words: capture seed, this anomaly family's per-attempt ordinal, and `0x53434D52`. This is not a general Fisher–Yates permutation. Sources: `A/TexCorruptState.cpp:241–244,591–599`; `A/TexCorruptPure.h:1277–1413`; `P/tools/create_texcorrupt_assets.py:41–66`.

**VERIFIED-FROM-SOURCE — Lower mips and shared attempt:** every destination mip is drawn separately from the corresponding **original source mip**, with the same K/Ainv/B. Lower scramble mips are **not generated by downsampling a scrambled top level**. The attempt derives the permutation once and passes it to its texture copies. The render target is PF_B8G8R8A8; source address modes, filter and sRGB settings are carried over. Sources: `A/Anomaly_TexCorrupt.cpp:402–425,476–507,819–822`; `A/TexCorruptDraw.cpp:42–70`. The explicit source mip setup is in `P/tools/create_texcorrupt_assets.py:235–246`.

**VERIFIED-FROM-SOURCE — Normal meaning and admission:** invert negates decoded tangent-space **X and Y**; green_flip negates **Y only**. The copy's decoded Z is left alone, then encoded along with RGB. The shipped admission rule accepts normal maps only in **PF_BC5**; the color/data support list also includes DXT1, DXT5, BC7, BGRA8, and appropriate BC4/G8 data textures. DXT5 normal maps are not silently admitted as ordinary color. Sources: `A/Anomaly_TexCorrupt.cpp:439–440`; `P/tools/create_texcorrupt_assets.py:97–111`; `A/TexCorruptPure.h:194–225`; `A/TexCorruptTree.cpp:387–419`; `P/docs/client-readme.md:1419`.

**VERIFIED-FROM-SOURCE — Atomic scope:** the documentation's operational unit is a **complete component footprint**, not necessarily every component on the actor. UV requires its relevant spatial texture bindings; normal requires its normal-map bindings. Nonspatial textures can be exempt. A failing required binding prevents partial success for that footprint; other complete components can be selected and represented in the scope. Sources: `A/TexCorruptTree.cpp:665–739`; `P/docs/client-readme.md:1302–1315,1364–1382`. This distinction matters when counting Bates gains.

## 1. Producer plumbing in UE 5.1.1

### 1.1 Public registration, ownership and the unavailable inner shortcut

**VERIFIED-FROM-SOURCE:** the actual descriptor name is **`FVTProducerDescription`**, not `FVirtualTextureProducerDescription`. It specifies dimensions, tile size, border, block geometry, MaxLevel, texture formats, fallback colors and physical groups. A plugin can implement `IVirtualTexture`, `RequestPageData`, `ProducePageData`, task collection and `IVirtualTextureFinalizer::Finalize(FRDGBuilder&)`, then call `IRendererModule::RegisterVirtualTextureProducer`. Requests and production are on the render thread; `GetLocalMipBias` must be thread-safe. Targets provide the destination physical texture and page coordinates. Sources: `RC/VirtualTexturing.h:140–189,241–331`; `RC/RendererInterface.h:882–893`.

**VERIFIED-FROM-SOURCE:** renderer registration owns the supplied producer. Release evicts its pages, gathers/waits for production tasks, then deletes the `IVirtualTexture`. Registering the same owning pointer as two independent producers is not an ownership scheme. Sources: `VT/VirtualTextureProducer.cpp:11–40,56–96`. A layered proxy should own its backend once or share a separately reference-counted backend; it must not double-delete an engine producer.

**VERIFIED-FROM-SOURCE:** `FUploadingVirtualTexture` is in an Engine **Private** header and its class/constructor/methods have no `ENGINE_API` export. It borrows `FVirtualTextureBuiltData` and routes requests/production through the engine's streaming manager. `FVirtualTexture2DResource::InitRHI` constructs it as a **local pointer**, registers it, and retains a handle, not an accessible producer pointer. An editor-only `InitializeEditorResources` hook receives that pointer; it is absent as a shipping escape hatch. Sources: `EVT/UploadingVirtualTexture.h:72–112`; `EVT/UploadingVirtualTexture.cpp:61–97,99–156`; `EN/Private/Texture2D.cpp:1303–1337`.

**VERIFIED-FROM-SOURCE:** the public renderer interface exposes register/release and allocation/request operations, but no producer-pointer lookup. `FVirtualTextureSystem::FindProducer` and the producer container are in Renderer Private headers, without a public module export. A second Proof A resource gives another public **handle**, not a supported shipping route to its `IVirtualTexture`. Sources: `RC/RendererInterface.h:876–893`; `VT/VirtualTextureSystem.h:61–83`; `VT/VirtualTextureProducer.h:14–22`; `EN/Public/TextureResource.h:183`.

**INFERRED:** a plugin can wrap an inner producer that it implements/owns itself. It cannot assume that adding Engine private include directories makes `new FUploadingVirtualTexture`, its streaming manager, or `FindProducer` link in a modular packaged build. A monolithic build accidentally exposing private code is not portable proof. The private `FVirtualTextureLevelRedirector` demonstrates an engine-owned wrapper, not an exported plugin facility (`EVT/VirtualTextureLevelRedirector.h:9–16`). Consequently the selected design needs its own cooked-page reader and uploader, or a separately approved engine API change. No engine change is selected here.

### 1.2 The private UTexture binding pattern remains usable

**VERIFIED-FROM-SOURCE:** `FVirtualTexture2DResource` has exported constructors and exported virtual `InitRHI`/`ReleaseRHI`. Its `AllocatedVT`, `VTData`, `TextureOwner`, `ProducerHandle` and `FirstMipToUse` members are **protected**. `GetProducerHandle` is nonvirtual; `AcquireAllocatedVT` and `ReleaseAllocatedVT` are also nonvirtual. There is no protected producer-pointer member. The empty constructor initializes data/owner/allocation to null; the source-data constructor performs normal size/mip bookkeeping. Sources: `EN/Public/TextureResource.h:161–215`; `EN/Private/Texture2D.cpp:1226–1256`.

**VERIFIED-FROM-SOURCE:** inherited `InitRHI` dereferences the texture owner and installs the stock uploader. Inherited `AcquireAllocatedVT`, when no allocation exists, dereferences `VTData`/`TextureOwner` and constructs an allocation using their fields. Therefore neither is a generic custom-producer initializer. Sources: `EN/Private/Texture2D.cpp:1263–1337,1495–1514`. Proof A uses the exported source-data constructor and overrides editor setup without changing the stock producer; its UTexture owns a resource of the genuine VT resource type (`BA/AnomalyPrivateVT.cpp:43–77,80–141`; `BA/AnomalyPrivateVT.h:13–46`).

**INFERRED:** a derived resource can override `InitRHI`, initialize the sampler and producer descriptor, register its own producer into the protected `ProducerHandle`, supply correct virtual size/format/mip getters, and establish the protected allocation. It must either give inherited allocation code valid compatible metadata or create the allocation itself before inherited `AcquireAllocatedVT` sees it. It cannot “override” the nonvirtual accessor to fix a wrong descriptor. The ordinary material code obtains the genuine VT resource and its handle, so a transient UTexture can bind this custom resource using Proof A's target MID pattern (`EN/Private/Materials/MaterialShared.cpp:3711–3750`; `BA/Anomaly_TexCorrupt.cpp:1212–1218`). A compiled, packaged resource-lifecycle proof is still required.

### 1.4 GPU alternative and its limits

**VERIFIED-FROM-SOURCE:** physical BC textures are not ordinary float UAVs. UE maps BC1/BC4 storage to `PF_R32G32_UINT` and BC3/BC5/BC6H/BC7 to `PF_R32G32B32A32_UINT` for format-alias support. The physical-space allocator adds the alias UAV only when the RHI advertises it. In this engine's D3D12 implementation that capability is enabled for resource heap tier above 1 and NVIDIA; it is not an all-GPU assumption. Sources: `E/Source/Runtime/RHI/Public/RHIUtilities.h:51–85`; `VT/VirtualTexturePhysicalSpace.cpp:86–95,111–154`; `E/Source/Runtime/D3D12RHI/Private/D3D12Texture.cpp:609–618`; `E/Source/Runtime/D3D12RHI/Private/Windows/WindowsD3D12Device.cpp:1486`; `E/Source/Runtime/RHI/Private/RHI.cpp:1507`.

**VERIFIED-FROM-SOURCE:** the inspected runtime-VT compression path allocates integer block textures at one quarter the texel dimensions, writes compressed blocks with compute shaders, then copies those integer-block outputs into the physical BC texture. Its comment describes direct final-pool alias writing as future work; it does not prove a universal post-upload in-place editor. Sources: `VT/RuntimeVirtualTextureRender.cpp:454–466,590–594,932–952,1149–1167,1282–1298,1327–1337`.

**INFERRED:** a custom producer finalizer can use that **integer scratch + BC copy** architecture, or a validated aliased-UAV architecture, to generate transformed private pages. Reading raw existing BC blocks is an additional problem: a BC SRV gives decoded samples, and UAV-format alias support alone does not establish every desired typed UAV load/copy operation. A GPU donor allocation sampled as textures can reconstruct output, but brings donor readiness, extra residency and decode/re-encode costs. It also cannot assume access through ordinary VT sampling to every cooked sub-tile mip (§2). This is a viable separate engineering option, not a free wrapper around the existing uploader.

**INFERRED:** transforming a private page once after prefetch is insufficient: eviction and re-upload would restore untransformed data. Transformation must be part of production **every time**, before the ready page becomes visible. Only the assigned private page regions may be written; a shared physical-pool texture is not owned wholesale by this event. The selected route uses CPU block work and its own uploader to avoid making the proof depend on one vendor's BC alias path. Sources: public target-region contract `RC/VirtualTexturing.h:249–261,299–319`; upload/reuse path above; Proof A prebind readiness `BA/AnomalyPrivateVT.cpp:179–315`.

### 1.5 Physical pool cost

**VERIFIED-FROM-SOURCE:** residency lookup keys include producer handle, virtual address, level and physical group. A new producer handle does **not** deduplicate equal source bytes or equal repeated tiles against the source producer. Compatible producer formats/tile geometry can reuse the same physical **pool**, but occupy different page slots. Allocations referencing the same producer may share its pages; that does not make a private producer share the source's pages. Sources: `VT/TexturePagePool.cpp:204–222`; `VT/VirtualTextureProducer.cpp:74–92`; `VT/VirtualTextureSystem.cpp:989–1015`.

**INFERRED — Estimate:** for resident page count p_l in output layer l, incremental occupied page bytes are approximately

`sum_l p_l * ceil((T+2b)/blockWidth_l) * ceil((T+2b)/blockHeight_l) * bytesPerBlock_l`.

Add page tables, persistent root pages, IO buffers, decoded/compressed caches, staging, task data and any donor pages. This follows the engine's physical tile memory calculation (`VT/VirtualTexturePhysicalSpace.cpp:167–174`); it is occupied pool capacity, not a promise that VRAM allocations grow byte-for-byte. A newly needed pool can allocate a whole configured pool; an existing pool can instead evict other pages.

| Illustrative geometry, not a proposed cap | INFERRED occupied payload |
|---|---:|
| T=128, b=4: one BC5/BC3/BC7 page | 18,496 bytes = 18.0625 KiB |
| Same geometry: BC1/BC4 page | 9,248 bytes |
| Same geometry: BGRA8 page | 73,984 bytes |
| One 4096² layer, complete allocated levels 0–5: 1,365 pages, BC5 | 24.08 MiB |
| Same full footprint, BGRA8 | 96.31 MiB |
| Three full layers, BC1 + BC5 + BC1 | 48.15 MiB |
| Three full layers, all 16-byte BC blocks | 72.23 MiB |
| N=8 enlarged variant, 32768², full levels 0–8: 87,381 BC5 pages | 1,541.33 MiB |

**INFERRED:** full-chain figures are sizing examples, not expected residency per view. Same-size transforms retain the source virtual page grid; the N-times-larger variant has about N² as many finest pages, although actual visible working sets depend on derivatives and screen coverage. Even normal-only output adds normal-pool occupancy while co-users retain source pages. Shared-pool pressure can affect co-user quality through eviction/residency bias (`VT/VirtualTextureSystem.cpp:2675–2685`), despite correct target binding. Proof A's existing 512-page prefetch bound would not admit the illustrative fully requested 4K chain; changing it requires measured page/memory/time data, not a new number invented in this review (`BA/AnomalyPrivateVT.cpp:247–278`; `R/092-03c-ruling.md:24,43–47`).

## 2. Tile as an address remap

**INFERRED — Coordinate conventions:** W,H are the effective source dimensions after the same source-resource/first-mip bookkeeping used for identity; T is the interior tile width, b the border, L a destination local mip, and q=log2(N). First consider one complete power-of-two source block, integer power-of-two N, and fully available intended mips. Multi-block, sparse, biased, mixed-resolution and root-clamped cases must preserve the corresponding engine offsets; they are not covered by blindly applying the simple formulas. Sources for those offsets: `EN/Private/Texture2D.cpp:1239–1256,1303–1329`; `EVT/UploadingVirtualTexture.cpp:99–156`; source mip law `A/TexCorruptPure.h:1450–1469`.

### 2.1 Variant (a): unchanged virtual dimensions

**INFERRED — Confirmed with qualifications:** at destination level L use source mip `m=min(L+q,lastCookedMip)`. Where source copies span integral whole pages, destination page (x,y) maps to source page

`(x mod (W_m/T), y mod (H_m/T))`, at source level m.

It is **not** simply `(x >> q, y >> q)`; that would group destination pages rather than repeat the smaller source image. The Morton-coded address must be decoded/remapped/re-encoded. This follows the shipped `frac(N*UV)` and explicit mip law (`P/tools/create_texcorrupt_assets.py:41–66`; `A/TexCorruptPure.h:1450–1469`) and the producer's bit-interleaved address contract (`RC/VirtualTexturing.h:289–310`). Border and sub-page handling remain below.

**INFERRED — Magnification difference, quantified:** let lambda be the original continuous derivative LOD before its lower clamp. Ignoring upper/root clamps and VT stochastic rounding, direct shader tiling samples at `max(0,lambda+q)`, whereas this variant samples at `max(0,lambda)+q`. Their mip difference is

| Original lambda | Variant (a) minus direct UV×N mip |
|---|---:|
| lambda >= 0 | 0 |
| -q < lambda < 0 | -lambda |
| lambda <= -q | q |

**INFERRED:** the maximum loss is q mip levels, N times coarser linear source resolution, N² texel area. For shipped N=2/4/8/16 it is up to 1/2/3/4 mips. This is a difference from **direct shader tiling**, but it agrees with the released copied-texture mip intent, including the coarser top level. VT uses anisotropic derivative calculation, global bias, stochastic mip selection and clamping, so this equation is the continuous idealization, not a claim about every final pixel (`SH/VirtualTextureCommon.ush:249–265,311`; shipped explicit law above).

### 2.2 Variant (b): virtual dimensions N×W by N×H

**INFERRED — Confirmed in the aligned range:** keep source mip L and map to `(x mod Wp_L, y mod Hp_L)`, where Wp_L/Hp_L are integral source page counts at L. Increasing the logical texel dimensions causes implicit derivatives to select the q-higher source mip that direct UV×N would select, while still allowing original level-0 detail under magnification. Texel-center positions also agree for integer N. This describes direct shader tiling where the copies and halos can be represented; it is **not** the shipped same-size mip law. The derivative/scale basis is `SH/VirtualTextureCommon.ush:249–265`; packed page-table scales are `VT/AllocatedVirtualTexture.cpp:445–478`.

**INFERRED:** grow the **block's pixel/page dimensions** while preserving the intended UV domain. Merely setting `WidthInBlocks`/`HeightInBlocks` to N is not equivalent: the engine packs reciprocal block counts into the UV scale, used for multi-block/UDIM addressing (`VT/AllocatedVirtualTexture.cpp:469–473`). Explicit-MipLevel material samples are another exception to the derivative argument: multiplying UV alone does not automatically change an explicit requested mip. The comparison oracle must specify the material mip mode (`EN/Private/Materials/HLSLMaterialTranslator.cpp:5543–5614`).

### 2.3 Non-power-of-two N, borders and the mip tail

**VERIFIED-FROM-SOURCE:** released tile does not accept non-power-of-two N; scramble K does. The engine's source blocks are power-of-two sized, though the full block grid need not be. Its VT builder upsizes small blocks to at least the tile size and limits produced mip count to `min(ceilLog2(maxDimension)+1,12)` in this implementation. Metadata's separate maximum-mips constant is 16; it does not mean this builder produces 16. Sources: `A/TexCorruptState.cpp:241–244`; `EVT/VirtualTextureDataBuilder.cpp:281–307`; `EVT/VirtualTextureBuiltData.h:15–18`.

**INFERRED:** for hypothetical non-power-of-two integer N, (a) cannot be an exact single-mip remap using log2(N): fractional source LOD needs filtering/resampling, and the source period W_L/N may not align to pixels/pages. For (b), integer copy counts can work at aligned levels if geometry fits, but a stack mixing enlarged and original layers has dimension ratio N; a non-power-of-two ratio violates the allocator's exact shift checks. Enlarging every relevant layer together avoids that particular ratio between them, but does not remove geometry, alignment and tail requirements. Fractional N is not an integer modulo-copy construction. No N extension is recommended (`VT/AllocatedVirtualTexture.cpp:339–355`; shipped accepted-N rule above).

**VERIFIED-FROM-SOURCE:** cooked pages contain already generated halo texels. The builder applies Wrap, Clamp or Mirror while copying a bordered source rectangle. It uses the build address settings; the texture-derived settings force Clamp for UDIM/multi-block sources and otherwise use the asset address modes. Borders can be zero or power-of-two values starting at 2, so a border of 2 is a real BC-alignment case. Sources: `EVT/VirtualTextureDataBuilder.cpp:97–179,647–653`; `EN/Private/TextureDerivedData.cpp:968–1001`.

**INFERRED:** reusing a Wrap page at a repetition boundary supplies the opposite source edge, which is appropriate for that internal repeat seam. A Clamp or Mirror source page supplies the wrong neighboring texels for a repeated **copied image** at an internal copy seam. Those destination halos must be reconstructed from the destination's adjacent copy; the outer destination boundary still follows its preserved address mode. Changing the sampler cannot repair bytes already baked into a physical page. Sparse/UDIM holes need explicit source-neighbor and fallback semantics, not a blanket modulo over the bounding rectangle. The shipped copy's `frac` mapping plus inherited destination address mode is the reference (`P/tools/create_texcorrupt_assets.py:41–66`; `A/TexCorruptDraw.cpp:42–70`).

**INFERRED — Important tail qualification:** below one page per copy, `Wp_L=0` obtained by integer division is not an address formula. However, it is also wrong to claim **every** such level needs fresh decoding. `CopyRectangleBordered` fills the whole out-of-image portion of the physical rectangle, not only a thin border. For a power-of-two Wrap source whose sub-page period divides T, a stored small-mip physical page can already contain the repeated pattern across its full interior and halo. That page can sometimes be copied intact, even when the period is below four texels. Evidence: full out-of-bounds loops `EVT/VirtualTextureDataBuilder.cpp:117–179`, physical-page compression `:647–694`.

**INFERRED:** otherwise a 4×4 BC-block composer can assemble tail pages only when the required source/destination phase and fragment boundaries align to entire BC blocks, or a source block already contains exactly the needed repeated pattern. At periods below four pixels, or at misaligned seams, different fragments generally share a destination block. Independently encoded fragments cannot simply be bit-spliced into one valid palette/index block. Decode the affected samples, construct the destination block and re-encode it, or use an uncompressed output layer throughout. A producer's layer format is fixed, so “BC pages above the tail, RGBA pages below it” is not one layer (`RC/VirtualTexturing.h:172–177`). The selected UV design uses reconstruction and same-format re-encoding where copying is invalid.

**VERIFIED-FROM-SOURCE:** the allocated VT clamps MaxLevel to the log2 of its smaller dimension in **tiles**, then to 11. Stored sub-tile cooked mips and mips addressable through a particular ordinary allocation are therefore not interchangeable. A CPU reader can inspect stored tiles; sampling a donor VT cannot assume it can request all those sub-tile mips. Sources: `VT/AllocatedVirtualTexture.cpp:60–67`; cooked count `EVT/VirtualTextureDataBuilder.cpp:307`. A 4096² source from this builder may stop at a 2×2 stored mip; code must use its actual NumMips, not invent a 1×1 level.

### 2.4 Virtual-size limits and equivalence

**VERIFIED-FROM-SOURCE:** this version has log2 maximum page-table extent 12, i.e. 4096 pages on an axis; up to eight texture layers; packed 12-bit page coordinates and four-bit space/level fields. The allocator rejects extents exceeding its address-space tree and imposes alignment. Allocation can ultimately hit a `checkf` when no VT space remains. Sources: `RC/VirtualTexturing.h:50–55`; `VT/AllocatedVirtualTexture.cpp:445–478`; `VT/VirtualTextureAllocator.cpp:396–413,493–513`; `VT/VirtualTextureSystem.cpp:811–871`.

**INFERRED:** the broad logical upper bound is 4096×T pixels per axis, e.g. 524,288 at T=128, before block layout, MaxLevel, fragmentation, space count and memory constraints. This is not the RHI's ordinary single-texture-size limit and is not a promise an event of that size can allocate. The N×W proposal must preflight actual allocation geometry and whole-event capacity before invoking paths that assert. Reducing host quality or overflowing a page table is not an acceptable way to make it fit. Same-size (a) avoids the N² address expansion and mixed original/enlarged-layer ratio problem.

**INFERRED — Pixel identity decision:** neither variant is proven pixel-identical to shipped non-VT tile on a nominally identical source asset. Variant (a) preserves the shipped per-mip transform law; variant (b) intentionally changes magnification detail. Cooked VT pages can have different compression phase/halos from an ordinary mip, output BC pages differ from the shipped BGRA8 RT, and VT's stochastic LOD, root limit, anisotropy/border and residency differ from ordinary sampling. Sources: shipped RT and per-mip draws `A/TexCorruptDraw.cpp:42–70`, `A/Anomaly_TexCorrupt.cpp:476–507`; engine page building and sampling above. Select **(a), `tile_vt_mipcopy`**, with source-mip/cell-copy semantics stated explicitly and a separate pixel oracle; do not rename (b) as the existing tile behavior.

## 3. Scramble as pages and compressed blocks

**INFERRED:** use the exact released CRC/affine permutation, once per attempt, on **each source mip separately**. At mip L, page permutation is a valid interior fast path only when both cell dimensions W_L/K and H_L/K are integers and multiples of T. It moves the entire cell's pages with their within-cell page offset; it does not randomly shuffle all pages independently. At smaller cells, whole 4×4 BC blocks can be moved only when cell edges and source/destination block phases align. Sources: shipped permutation `A/TexCorruptPure.h:1277–1413`; source-mip behavior `A/Anomaly_TexCorrupt.cpp:402–425,476–507`; physical bordered-page construction `EVT/VirtualTextureDataBuilder.cpp:647–694`.

**INFERRED:** those fast paths do not fix cell-boundary halos. A copied source page's halo still describes the source cell's old neighbor. The destination cell's new neighbor may be elsewhere. At every permutation seam, halos must describe the **new destination image**, including corners. BC blocks crossing that boundary must be reconstructed where necessary. A two-texel border can put the interior edge halfway through a compressed block even when the cell occupies whole pages. This follows from the actual accepted border settings (`EN/Private/TextureDerivedData.cpp:997–1001`) and the shipped final copied texture's filtering (`A/TexCorruptDraw.cpp:42–70`).

**INFERRED:** below four pixels per cell, cells generally contribute fragments to the same compressed block, so pure block permutation is not generic. Even at the top mip K=3, for example, does not divide a power-of-two width; the shipped normalized-coordinate shader produces fractional sample positions. Correct reconstruction must evaluate the shipped destination texel-center mapping and source-mip filtering, not round cells to an integer size. At mips where nominal cells become less than one texel, the shipped draw samples that mapping at the remaining texel centers; it neither preserves every cell visibly nor averages all scrambled cells. Sources: allowed K `A/TexCorruptState.cpp:244`; mapping `P/tools/create_texcorrupt_assets.py:41–66`; independently redrawn mips `A/Anomaly_TexCorrupt.cpp:476–507`.

**INFERRED — Selected route:** a cooked-page producer with page/block copies for proven aligned interiors and a CPU sampler/compositor plus same-format encoder for every affected boundary/tail block. Its cache key must include source generation, mip, layer, transform parameters and required neighbors. Preserve decoded-normal treatment for normal inputs, linear/sRGB interpretation for color/data, and alpha behavior from the released copy function (`P/tools/create_texcorrupt_assets.py:68–111`; source classification `A/TexCorruptPure.h:194–225`). General runtime codec support is part of the work; the editor TextureCompressor is not assumed callable in the shipping plugin.

**INFERRED — Naming decision:** call this **`scramble_vt_cells`**. It follows the released K/seed/per-mip cell meaning, but reconstructed compressed seams/tails can add encoding error and VT sampling remains different. A page-only approximation that leaves wrong halos, averages the scrambled top image to make lower mips, or clamps K down at small mips is **not** the released scramble. Re-encoding errors must be measured against the per-mip oracle before the owner can decide any acceptance tolerance; this review supplies none.

## 4. Normal invert and green_flip

### 4.1 BC5 algebra, rounding and Z

**VERIFIED-FROM-SOURCE:** BC5 is represented as two BC4-style endpoint/index blocks in UE's bundled decoder. The first supplies X/red and the second Y/green. The inspected D3D12 mapping for PF_BC5 is `DXGI_FORMAT_BC5_UNORM`. Sources: `NV/BlockDXT.cpp:343–378,516–538`; `E/Source/Runtime/D3D12RHI/Private/D3D12RHI.cpp:144`. This review's `255-v` algebra is for **unsigned** BC4 channels, not a recipe for BC4/5 SNORM; the signed reference decoder has different endpoint handling (`DX/BC4BC5.cpp:95–127`).

**INFERRED — Exact rational transform:** for original endpoints (a,b), write `(a',b')=(255-b,255-a)`. The comparison is preserved: a>b iff a'>b', and equality stays equality. Remap every 3-bit index as follows:

| Original mode | Index permutation |
|---|---|
| Eight interpolated values, a>b | `[1,0,7,6,5,4,3,2]`: 0↔1, and i→9−i for i=2…7 |
| Six interpolated values plus 0/255, a<=b | `[1,0,5,4,3,2,7,6]`: 0↔1; i→7−i for i=2…5; 6↔7 |

**INFERRED:** each rational palette value after remapping is `255 - oldValue`. In eight-value mode the denominator is 7; the reversed numerator weights plus complemented/swapped endpoints give `7*255 - oldNumerator`. The six-value mode is the same calculation with denominator 5, and the two explicit constants swap. Endpoint and index operations are each involutions, so applying the block transform twice restores **every input byte**, including equal-endpoint blocks and unused indices. The source equations used for this derivation are `NV/BlockDXT.cpp:343–378` and `DX/BC4BC5.cpp:39–91`.

**VERIFIED-FROM-SOURCE — Integer-decoder counterexample:** the bundled NVTT reference computes interpolated byte entries using integer division. For a=0,b=1,index=2 in six-value mode, the old decoded value is 0. After transformation the decoded value is 254, whereas `255-old` is 255. Thus “BC5 complement is unconditionally decoded-byte exact” is false for an actual decoder included in this engine source. Source: `NV/BlockDXT.cpp:343–378`.

**INFERRED — Worst-case rounding bound for that decoder:** write an old rational entry as k+f with 0<=f<1. If f=0, the complemented entry is exact. Otherwise `floor(255-(k+f)) = 254-k`, one below `255-floor(k+f)`. The absolute discrepancy is therefore **at most one 8-bit channel LSB**; endpoint and fixed-constant cases are exact. Nearest-integer rounding of these odd-denominator palette fractions gives symmetric complements. This bound concerns decoded BC channel values, not the final normal, lighting or frame.

**VERIFIED-FROM-SOURCE — Local arithmetic check:** `LOCAL/bc4_algebra.py` exhaustively enumerated 65,536 endpoint pairs × 8 entries against that floor reference. It found no mode changes, no index-involution failures, and maximum error 1 LSB; the nearest-integer mathematical model found 0 LSB. Results and the counterexample are recorded in `LOCAL/bc4-algebra-results.txt:1–8`. This was a CPU algebra calculation, not an Unreal build or GPU test.

**VERIFIED-FROM-SOURCE:** UE's normal unpack shader uses AG when `DXT5_NORMALMAPS` is compiled, otherwise RG, maps XY from [0,1] to [-1,1], and computes `Z=sqrt(saturate(1-dot(XY,XY)))`. Both ordinary Normal and VirtualNormal material samples call this unpack operation. Sources: `SH/Common.ush:1371–1383`; `EN/Private/Materials/HLSLMaterialTranslator.cpp:5779–5782`. The shipped operation negates decoded X/Y or Y and does not negate Z (`P/tools/create_texcorrupt_assets.py:97–111`; `A/Anomaly_TexCorrupt.cpp:439–440`).

**INFERRED:** complementing BC5 R and G implements the intended invert; complementing G alone implements green_flip. Exact sign flips preserve X²+Y² and therefore reconstructed positive Z. A one-LSB encoded-channel discrepancy can change the corresponding signed component by up to 2/255, and Z's square-root sensitivity near the horizon can amplify the normal error. Do not claim a one-LSB bound for shaded output. BC sampling/rounding is performed by hardware; these engine sources do not prove a universal GPU rounding policy. A known-block GPU oracle on the actual RHI is required to establish its pixel error. BC byte involution can pass even with the wrong sign/channel interpretation, so it is only one control.

**INFERRED:** preserve the source's actual mip/bias, non-sRGB normal interpretation and compiled channel layout. Transform all texels in the physical page, including halo/padded regions, and supply appropriate transformed fallback color in the producer descriptor (`RC/VirtualTexturing.h:172–177`; fallback consumption `VT/AllocatedVirtualTexture.cpp:50–53`). Do not normalize a tangent normal again merely because a compression routine offers that option. The shipped BGRA8 render-copy quantization and direct compressed sampling are different paths, so the new names **`invert_vt_bc5` / `green_flip_vt_bc5`** are warranted until a stronger equivalence proof exists.

### 4.2 Other formats

| Format | Source finding and design classification |
|---|---|
| BC3 / DXT5nm, compiled AG layout | **VERIFIED-FROM-SOURCE:** BC3 alpha uses the same 8/6-entry construction; its color decoder forces four-color mode regardless of endpoint ordering (`DX/BC.cpp:318–365,902–940`). Normal unpack reads X from A and Y from G (`SH/Common.ush:1375–1382`). **INFERRED:** invert alpha's BC4 block for X; complement the 6-bit green endpoint values `g→63-g` without changing the color indices for Y. Invert does both; green_flip does only green. This is rationally exact, with decoder/expansion rounding to verify. No unconditional decode/re-encode is needed for this narrowly established layout. It is outside the current shipped BC5 admission rule and needs its own format-specific proof/subtype extension. |
| BC7 normals | **VERIFIED-FROM-SOURCE:** the mode table has different partitions, rotations, endpoint/index precisions and p-bit layouts (`DX/BC6HBC7.cpp:1093–1114`); a p-bit can be appended to several channels of an endpoint (`:2620–2654`), with fixup/index rules (`:2656–2683`). **INFERRED:** the BC4 permutation is not a generic BC7 transform. Some mode/channel combinations admit endpoint complements; shared p-bits and channel rotations prevent treating arbitrary R/G-only changes as independent bit edits. A general implementation needs mode-aware proofs or decode/transform/re-encode. Re-encoding adds lossy error and appreciably more CPU/GPU work than the fixed BC5 bit operation. |
| Uncompressed unsigned normalized channels | **INFERRED:** `v→255-v` for 8-bit storage is exactly reversible for the selected RG/AG channels; leave other channels unchanged and use linear normal interpretation. Other integer widths use their actual channel maximum. Floating-point `1-v` incurs ordinary float rounding. Filtering/sign equivalence is conditional on matching sampler, mip and normal-layout semantics. Basis: normal unpack `SH/Common.ush:1371–1383`; normal's uncompressed format selection `EN/Private/Texture.cpp:3202–3210`. |
| Other target-platform encodings, including mobile formats | **INFERRED:** no BC recipe applies merely because the asset is a normal map. Read the actual cooked format and implement its decoder/transform/encoder or demonstrate an exact format-specific operation. Counting these assets as BC5 would overstate coverage. Basis: target-format selection `EN/Private/Texture.cpp:3031,3134–3140,3233–3235` and stored VT layer formats `EVT/VirtualTextureBuiltData.h:130–157`. |

**INFERRED — Cost comparison:** BC5/BC3 endpoint/index work is fixed work per compressed block with no search and no extra output bytes. General BC7/other reconstruction needs a decoded working tile plus encoding work for transformed blocks, and introduces another lossy encoding stage. Outputting uncompressed RG/BGRA instead trades encoder work for much greater physical-pool occupancy; for the BGRA case the example in §1 is four times BC5. Since physical layer format is fixed, uncompressed fallback cannot be selected independently for just difficult mips (`RC/VirtualTexturing.h:172–177`). No millisecond estimate is justified without a runtime benchmark.

## 5. Multi-layer stacks and mixed VT/non-VT footprints

### 5.1 What the engine actually permits

**VERIFIED-FROM-SOURCE:** the material compiler merges VT samples into a stack according to common coordinate expression/hash and scope, mip mode/input hashes, address modes, aspect ratio, preallocated-stack identity, adaptive/feedback settings and free stack capacity. “Same UVs” is a useful common case, not the complete merge test. Pixel format is not the merge key. Source: `EN/Private/Materials/HLSLMaterialTranslator.cpp:5543–5614`.

**VERIFIED-FROM-SOURCE:** a normal streaming material stack builds its allocation with a **producer handle per texture layer**. It requires matching tile size and border, and sets `ProducerLayerIndex=0` for each sampled UTexture. `FAllocatedVirtualTexture` then maps each layer to its producer's physical group/format. It does **not** require base color, normal and ORM to all have the same pixel format. Different formats are normal stack members; physical-group/pool compatibility is a separate matter. Sources: `EN/Private/Materials/MaterialShared.cpp:3711–3750`; `VT/VirtualTextureSystem.cpp:610–639`; `VT/AllocatedVirtualTexture.cpp:28–55`; descriptor `RC/VirtualTexturing.h:61–98`.

**INFERRED — Direct answer:** one normal layer can be replaced by a private genuine VT while the base-color and ORM layers keep their source producers, provided the replacement preserves the sampler's intended interpretation, compatible tile/border and effective geometry. The material will build a combined allocation using those different handles. This is exactly the useful architecture for normal-only corruption: material sampling/UVs stay where they were, and source co-users keep the source handle. Sources: engine allocation path above; Proof A genuine-resource/target-binding pattern `BA/AnomalyPrivateVT.cpp:43–141`; `BA/Anomaly_TexCorrupt.cpp:1212–1218`.

**VERIFIED-FROM-SOURCE — Differing sizes:** the allocator selects common block dimensions, then derives each producer's local mip bias from size ratios and checks that an integer left shift exactly reproduces each common dimension. It uses the smaller axis bias when overridden aspect ratios differ, effectively cropping in that case. Tile, border and dimensions are checked separately. Sources: `VT/VirtualTextureSystem.cpp:610–639`; `VT/AllocatedVirtualTexture.cpp:322–359`.

**INFERRED:** different layer sizes are allowed when their relationships fit those power-of-two shifts and intended aspect behavior. For variant (b), an N=2/4/8/16 enlarged layer can coexist with unchanged smaller layers through local mip bias, subject to limits; a non-power-of-two N cannot be assumed to pass. Enlarging only some layers also changes the common allocation geometry and root constraints even though the others still sample their own producers. Same-size tile and normal transforms avoid introducing these new ratios. Replacing an aspect-mismatched layer must not rely on the engine's crop behavior to claim identity.

### 5.2 Whole-footprint transformation and mixed paths

**INFERRED:** tile/scramble must transform all **required spatial bindings in the complete component footprint**, including base color, normal and ORM that share the affected UV, and any other required bindings in separate stacks. A producer transforming only base color is not sufficient just because the event can be made visible. Conversely normal invert/green_flip transform required normal maps and leave color/ORM on their source producers. The rule comes from the released family/required-binding logic, not from whichever layers happened to merge into a stack (`A/TexCorruptTree.cpp:665–739`; `P/docs/client-readme.md:1364–1382`).

**INFERRED:** one event can combine existing non-VT RT copies and the selected private VT producers. They must share exactly the same attempt's N or K/A/B/Ainv, seed and ordinal; each layer applies the same normalized cell map using its own source mip dimensions. Snapshot all required bindings, prepare every replacement, complete readiness, then bind the component atomically. Any required-path failure rolls back the proposed footprint. Do not increment the scramble ordinal per layer or make a new random permutation per producer. Sources: release's once-per-attempt derivation and mip setup `A/Anomaly_TexCorrupt.cpp:402–425,819–822`; Proof A mixed ordinary/VT preparation and prebind flow `BA/Anomaly_TexCorrupt.cpp:320–338,425–447`; accepted mixed case `R/092-03c-ruling.md:28–37`.

**INFERRED:** matching parameters gives coherent spatial intent, not guaranteed identical sample values at a VT/non-VT seam. Per-layer compression, resolution and sampling remain in the subtype/pixel-oracle contract. A failed texture is not repaired by applying the mesh route to the remaining layers: that would combine different coordinate semantics and can double-transform a texture already copied.

### 5.3 Extending stuck_low_mip proxy_vt beyond Proof A

**VERIFIED-FROM-SOURCE:** Proof A currently rejects when the source resource's layer count is not one, the compiled material stack layer count is not one, or the stack is preallocated. It reports `virtual_texture:stack_layout`. The single-layer restriction is a plugin gate, not the engine's general inability to mix producers. Sources: `BA/TexCorruptTree.cpp:529–539`; `R/092-03c-ruling.md:43–47`; engine per-layer allocation above.

**INFERRED — Narrow extension:** use **one private Proof A-style VT per required streaming texture layer**, with the same intended effective drop, source pins and private producer handles. Preserve each layer's original relative resolution and apply the drop with correct first-mip/source-bias bookkeeping. Check the resulting tile/border, ratios, max levels and layer/group mapping as a whole. If minimum-tile constraints cause layers to clamp differently, the purported common drop is not established; measure/evaluate the actual layer result before binding. This reuses Proof A's real cooked-data producers without requiring the new UV/normal reader (`BA/AnomalyPrivateVT.cpp:80–141`; `EN/Private/Texture2D.cpp:1239–1256`).

**INFERRED — Readiness change:** prefetch must establish the **actual combined material allocation's** intended page-table entries, including each layer's producer-local mip bias and physical-group/page-table-layer mapping. Prefetching each UTexture's standalone allocation may warm physical bytes but is not by itself proof that the combined table points to them at the correct mip. Proof A's per-page/per-level checks and one-expected-producer assumptions need generalization, not deletion (`BA/AnomalyPrivateVT.cpp:179–315`, especially `:229,262–269`; `VT/AllocatedVirtualTexture.cpp:28–55,322–359`). Whole-component readiness still precedes target binding.

**VERIFIED-FROM-SOURCE — Multi-layer producer interfaces:** the public producer interface supports a layer mask and a descriptor containing multiple texture layers; the allocation descriptor has explicit `ProducerLayerIndex` values (`RC/VirtualTexturing.h:75–77,172–177,296–319`). But ordinary material UTexture stack construction always selects layer **0** of each handle (`EN/Private/Materials/MaterialShared.cpp:3738–3739`). The preallocated runtime-VT branch is distinct (`EN/Private/Materials/MaterialShared.cpp:3659–3674`).

**INFERRED — Binding consequence:** several transient UTextures returning the same multi-layer handle do not automatically expose layers 0/1/2. A single shared backend needs per-UTexture facade producers exposing their chosen source layer as layer 0, or a more invasive custom/preallocated allocation/material path. Select the one-private-texture-per-layer extension for proxy_vt; keep multi-layer backends as an optimization requiring a separate binding design. Evidence: the layer-0 assignment and allocation interfaces immediately above.

**INFERRED — Frequency and measurement:** multi-layer stacks should be common in cooked materials whose base color, normal and ORM samples share compatible coordinates, mip modes, address modes and aspect ratio, because the compiler deliberately merges them. No defensible percentage follows from source, and the current Bates census does not supply one. The useful office reading is: compiled-stack layer-count histogram 1…8; source producer layer count; preallocated versus streaming counts; unique producer/physical-group counts; and, most importantly, **whole components newly eligible if stack_layout alone were solved**, with remaining/dependent blockers still recorded. This directly sizes the existing blur extension as well as UV/normal work. Sources: compiler merge test above; present gate `BA/TexCorruptTree.cpp:529–539`; ruling's requested counts `R/092-03c-ruling.md:50,55`.

## 6. Lifetime, identity, revert and pixel oracles

### 6.1 Reuse from Proof A, with the new responsibilities named

**VERIFIED-FROM-SOURCE:** Proof A pins its source UTexture, borrows its VT data, creates a distinct producer, checks resource layout, waits for resource initialization, and establishes requested page-table entries before binding. Its page checks distinguish an exact requested mip from an ancestor fallback. Release calls ReleaseResource and completes a render fence before dropping readback/data/source ownership. The event restores owned material state and leaves a slot to the game when the game has replaced the plugin's MID. Sources: `BA/AnomalyPrivateVT.h:44–46`; `BA/AnomalyPrivateVT.cpp:80–174,179–315`; `BA/Anomaly_TexCorrupt.cpp:261–278,425–447,1487–1549`.

**VERIFIED-FROM-SOURCE:** the accepted Proof A record includes native 1920×1080 identity, positive blur, timing boundaries, co-user isolation, mixed ordinary/VT targets and destroy/displacement/world-end cases, within its stated layout/prefetch bounds. That is evidence for the mechanisms and tested fixture, not blanket acceptance for transformed pages or multi-layer stacks. Source: `R/092-03c-ruling.md:14–37,43–47`.

**INFERRED — Proposed lifecycle:** retain the same snapshot/prepare/prefetch/bind/revert order. For the new producer, pin the source UObject **and** retain/validate the source resource/data generation used by all asynchronous reads. A strong UObject reference alone does not prove a mutable resource's platform-data pointer can never change. Cache keys and pending work must belong to the retained generation. This extends the compatibility ruling's coherent-snapshot requirement (`R/090-10x-chat-ruling-compatibility.md:24–25`) and Proof A's borrowed-data lifetime (`BA/AnomalyPrivateVT.cpp:103–105,156–174`).

**INFERRED:** all plugin IO/transcode/composition tasks must participate in producer task collection or an equivalent completed ownership scheme before deletion. The renderer waits only the tasks supplied through that contract (`VT/VirtualTextureProducer.cpp:29–37`; `RC/VirtualTexturing.h:322–325`). GPU copies and staging buffers must remain valid through GPU consumption; a render-command fence alone must not be mistaken for completion of arbitrary untracked asynchronous IO or all GPU work. The engine upload cache explicitly defers buffer reuse for the buffer-update path (`EVT/VirtualTextureUploadCache.cpp:443–448`). Do not keep raw TargetLayers pooled-target pointers after Finalize returns (`RC/VirtualTexturing.h:254–259`).

**INFERRED:** prepare without changing any host/co-user texture residency policy, global VT biases, pool sizes or source bytes. Revalidate component/material/binding identity before commit. Restore only still-owned bindings, clear remaining plugin MID references, unregister/release through the fenced path, and wait for all source-dependent work before unpinning. Test failed preparation and partial-stack failure as thoroughly as successful revert. Private handles isolate writes, but pool pressure can still change co-user appearance (§1.5); native identity needs a simultaneous co-user oracle under that pressure.

### 6.2 Controls that can fail, not just no-op successes

| Mode/control | INFERRED oracle and failure it must expose |
|---|---|
| Common producer identity | A private producer with **unmodified page bytes**, same geometry/sampler/mips, bound on one target; a second object samples the original source. Native 1920×1080 before/during/after images must expose wrong mips, source SRGB/filter/address changes, missing page readiness, wrong target binding and revert residue. Source basis: Proof A accepted identity `R/092-03c-ruling.md:14–25`; resource checks `BA/AnomalyPrivateVT.cpp:124–137`. |
| Tile N=1 | Inject N=1 as a proof-only path despite the released knob constraint. Exercise source biases, rectangular sizes, borders, multiple layers and mixed ordinary/VT footprints. Deliberately wrong page coordinate, mip shift or border should fail. A path that never binds can pass N=1, so it must also fail a positive N>1 oracle. Mapping source: `A/TexCorruptPure.h:1450–1469`; `P/tools/create_texcorrupt_assets.py:41–66`. |
| Positive tile | For variant (b), a home reference material sampling the source VT at UV×N is a useful derivative-LOD oracle within supported levels. For selected (a), use an independent per-mip reference implementing `frac(N*UV)` with source mip L+q, plus a near-magnification comparison demonstrating the intentional difference from UV×N. Build the tail reference from independently decoded cooked mip data or an independently generated fixture reference; an ordinary source-VT sample can clamp at its allocation root and cannot validate every stored sub-tile mip. Cover wrap/clamp/mirror, negative UVs, mip transitions and roots/tails. Do not declare (a) broken solely because UV×N shows more top-mip detail. Sources: shipped mip law and VT LOD/root clamp in §2. |
| Scramble identity permutation | Inject A=1,B=0,Ainv=1 explicitly; the production seed routine intentionally excludes this permutation. Its pages, boundary halos and every generated lower mip must return source identity. Deliberate wrong halo, source L+1, or per-layer permutation must fail. Sources: `A/TexCorruptPure.h:1346–1394`; `A/Anomaly_TexCorrupt.cpp:476–507`. |
| Positive scramble | Use an independently generated reference image **at every mip**, using the recorded CRC input and K/A/B, with color/cell IDs and spatially aligned normal/ORM channels. Compare a serialized/copied destination image with correct post-copy filtering. A direct piecewise-UV shader alone is insufficient at cell boundaries because its filtering can follow the old source neighbor rather than the new destination neighbor. Include K=3 and sub-four-pixel/sub-one-pixel cells. Source basis: mapping `P/tools/create_texcorrupt_assets.py:41–66`; copied-RT filter and mip behavior `A/TexCorruptDraw.cpp:42–70`; `A/Anomaly_TexCorrupt.cpp:476–507`. |
| Invert twice / green_flip twice | Apply the transform twice to the **first transform's output bytes**, not twice independently to the original. Byte identity must hold for both endpoint modes, equal endpoints, every index and all page borders. An implementation doing nothing also passes; require the one-transform positive oracle. Source equations: `NV/BlockDXT.cpp:343–378`; local enumeration `LOCAL/bc4-algebra-results.txt:1–8`. |
| Positive invert / green_flip | A reference material samples and unpacks the original source VT, multiplies decoded XY by (-1,-1) or (1,-1), and outputs encoded normals unlit for pixel comparison; also inspect a lit target. Use asymmetric X/Y patterns, both BC4 modes, 0/255 entries and near-horizon normals. A flat map or Y≈0 image can conceal the operation. Wrong index remap, omitted endpoint swap, wrong channel and a no-bind mutant must fail. Normal semantics: `SH/Common.ush:1371–1383`; `P/tools/create_texcorrupt_assets.py:97–111`. |

**INFERRED:** identity cannot establish all transformed-image semantics, and involution cannot establish which axis was flipped. Positive output, target-only change, exact revert, timing/readiness and physical/CPU memory recovery are distinct controls. Extend Proof A's tested displacement, object destruction, world end, saturation and prefetch-failure cases to in-flight custom IO and combined stacks. Measure actual normal-channel/frame errors before the owner sets any tolerance; do not promote the arithmetic one-LSB bound into a new acceptance threshold (`R/090-10x-chat-ruling-compatibility.md:17–25`; `R/092-03c-ruling.md:28–37`).

## 7. Mesh route versus producer route, per mode

**VERIFIED-FROM-SOURCE:** the local vertex factory passes mesh UVs and reconstructs the tangent basis independently of texture storage. It derives B=`cross(N,T)*s`, then re-orthogonalizes T. The material graph supplies its final normal before tangent-to-world conversion, or supplies a world-space normal directly. Sources: `SH/LocalVertexFactory.ush:621,791–825`; `SH/MaterialTemplate.ush:3033–3054`. The producer route changes texture samples where the released copy changes them; mesh/basis edits act at a different location in this pipeline (`P/tools/create_texcorrupt_assets.py:41–111`).

| Mode | Mesh route | Selected producer route |
|---|---|---|
| Tile | **INFERRED:** UV-channel multiplication is cheap once a faithful private mesh exists and can reach unnamed samples using that channel. It is equivalent only for suitable direct coordinates; a graph `g(UV)` receives `g(N*UV)`, while texture replacement changes sampling at `N*g(UV)`. Offsets/panners, other channels, world/procedural coordinates and the shipped coarser top-mip rule break a universal equivalence claim. It would need `uv_channel_tile`. | **INFERRED:** same-size source-mip remap preserves the released texture-space operation point and L+log2(N) intent. It leaves mesh/graph coordinates intact and handles named required bindings across supported mesh classes. It costs private pages, IO and halo/tail reconstruction. New subtype `tile_vt_mipcopy`; see §2 for exactness limits. |
| Scramble | **INFERRED:** still **not generic**. Interpolated UVs on an unchanged triangle cannot express arbitrary interior cell discontinuities. Splitting at every cell boundary can realize an authored restricted case, but changes topology and grows with cells/UV footprints; multiple channels, dynamic graphs, every LOD and new-neighbor filtering remain. This design round supplies no result that reverses 092-01's conclusion. | **INFERRED:** the producer can evaluate the actual per-mip destination mapping, including fractional cells, at page-generation time. Page/block copies accelerate aligned interiors; reconstructed boundaries/tails complete the algorithm. Biggest UV implementation/encoding cost, but no topology restriction. New subtype `scramble_vt_cells`. |
| Invert | **INFERRED:** negate stored T, retain s and N, yielding (-T,-B,N). This gives the desired XY sign result for the **same simple tangent-space normal input**. It is not generally equivalent to flipping selected sampled normals before arbitrary graph operations, and it can affect other tangent consumers. It would need `tangent_basis_flip` unless the material class is proven. | **INFERRED:** complement both BC5 channel blocks before the host material consumes the sample. Preserves the sample-stage operation through downstream graph logic, subject to compression/rounding and normal-layout qualifications. Fixed small work per block; adds private normal pages. New subtype `invert_vt_bc5`. |
| Green_flip | **INFERRED:** retain T and N, negate s, yielding (T,-B,N). Negating both T and s instead flips **X only**, not XY. Same graph/basis caveats as invert. | **INFERRED:** complement only BC5 G blocks; source X and reconstructed-Z meaning follow §4. Same private-page cost as invert, somewhat less bit work. New subtype `green_flip_vt_bc5`. |

**VERIFIED-FROM-SOURCE — Geometry cost is substantive:** cooked CPU geometry is retained when the mesh's CPU-access setting requests it; otherwise a general clone needs another data acquisition route. `SetStaticMesh` can refuse a static registered component after play begins and, when accepted, dirties render state, recreates physics, updates navigation relevance/streaming/bounds and PSOs. Sources: `EN/Classes/Engine/StaticMesh.h:1105–1110`; `EN/Private/Components/StaticMeshComponent.cpp:2172–2227`. A rendering-only replacement avoids some setter effects but introduces its own material/lighting/shadow/mask and lifecycle identity work; it is not supplied by the current texture-copy implementation (`A/Anomaly_TexCorrupt.cpp:1124–1144`).

**INFERRED — Four-rule comparison:** mesh cloning/basis editing must prove unchanged geometry rendering, every relevant LOD, component/instance scope, lighting/tangent consumers, collision/navigation behavior and restoration. These principally threaten picture, wrong-object and revert rules, with clone/readback memory under the hard-cap rule. The producer instead risks incorrect page mips/halos/formats, falsely ready mappings, shared-pool pressure, private IO/resource leaks and stale bindings. It has a larger shared runtime-page implementation cost than a narrow mesh experiment, but it avoids broad geometry substitution and retains the existing texture operation point. Sources: the cited mesh code; producer/lifetime sections 1/6; four-rule ruling `R/090-10x-chat-ruling-compatibility.md:21–25`.

**INFERRED — Bates coverage and effort comparison:** mesh routes might reach some of the unnamed bucket as well as some VT targets, but no census establishes the fraction having suitable geometry access, component scope and commuting material graphs. The producer route can preserve the texture path on currently admitted component classes without obtaining vertex buffers, but still needs replaceable bindings; it does not solve unnamed constants. A narrow mesh tile/normal proof could still be roughly 1–2 engineer-weeks, with several more for LOD/readback/render/revert hardening; a generic mesh scramble has no bounded estimate worth selecting. Those earlier rough ranges remain reasonable comparisons, not a demonstrated cheaper production route (`R/092-01-codex-bates-vt-research.md:204–212`). The new private-API findings increase confidence that the producer needs real engineering time; they do not make the mesh semantics more general.

**INFERRED — Other options considered:** a full decoded non-VT RT wrapped back into a custom genuine VT is possible in principle but adds full-image memory/copying and still requires the VT resource/producer and source readiness; ordinary RT binding alone fails the compiled VT contract (`EN/Private/Materials/MaterialShared.cpp:3711–3725`). A GPU producer with integer-block scratch avoids a runtime CPU encoder for some formats but requires its own source/donor and RHI proof (§1.4). Neither is a better initial proof than the bounded BC5 cooked-block reader/transform/uploader. Runtime material rebuilding, global VT pool/bias changes, shared source edits and mesh fallback inside one texture event are not selected routes.

## 8. Recommendation, coverage, effort and first proof

### 8.1 One route per mode

| Mode | INFERRED selected route and subtype | Deliberate contract |
|---|---|---|
| Tile | Plugin-owned cooked-page transforming producer; **variant (a), same virtual size**; `tile_vt_mipcopy` | Released N set and explicit source L+log2(N) law; page remap where valid; destination halo/tail construction where needed; same-format output with reconstruction only when copying is invalid. No N×W variant in this implementation. |
| Scramble | Same producer architecture; per-mip affine cell map; `scramble_vt_cells` | Released K, CRC seed, ordinal and A/B mapping; independent original-source mip sampling; page/block fast paths plus required reconstructed blocks. No downsampling of a scrambled top level. |
| Invert | Same producer architecture; BC5 R+G endpoint/index transform; `invert_vt_bc5` | Decoded tangent X/Y sign intent, unchanged positive reconstructed-Z meaning; byte-involution control and measured GPU rounding. No mesh/basis fallback. |
| Green_flip | Same producer architecture; BC5 G endpoint/index transform; `green_flip_vt_bc5` | Decoded Y-only sign intent, same controls; no assumption that a flat map demonstrates the effect. |

**INFERRED:** the BC5 suffix states the first normal format contract explicitly. Other actual normal formats would use adapters within this same producer architecture after their own algebra/pixel validation; they are not silently treated as BC5, and they do not justify advertising coverage today. For UV, preserve the source's fixed output format and use tested runtime decoders/encoders for affected blocks. This selects one design rather than leaving compressed versus uncompressed output unresolved. A full-uncompressed producer remains a comparison option, not an automatic fallback that can unexpectedly consume four times the pool space. Basis: format/layer constraints and costs in §§1,3,4.

**VERIFIED-FROM-SOURCE — Integration boundary:** the release's ordinary texture facts/snapshot path assumes ordinary mip/resource state (`A/TexCorruptTree.cpp:322–377`), and its uniformity analysis declines VT (`A/TexCorruptUniform.cpp:338,346–379`).

**INFERRED:** the producer route therefore also needs VT-aware source facts, joint eligibility, no-effect/uniformity evaluation, memory accounting and event preparation; removing the early VT refusal is not sufficient. Effective VT dimensions and source first mip must come from the retained VT resource/data, not ordinary resident-mip telemetry (`EN/Public/TextureResource.h:180–204`; `EN/Private/Texture2D.cpp:1239–1256`). Proof A supplies a starting pattern for those facts and readiness, not UV/normal acceptance by itself (`BA/TexCorruptTree.cpp:529–539`; `BA/AnomalyPrivateVT.cpp:80–141`).

**INFERRED — Why separate subtypes:** intent can match without universally identical pixels. BC5's rational sign transform has a known integer-decoder caveat; UV reconstruction may add compression error; VT mip/filter/residency behavior differs from the shipped BGRA8 copies. A truthful route label plus independent positive oracle is preferable to claiming an equivalence not established by source. Retaining an existing subtype name would require the orchestrator/owner to accept demonstrated equivalence for a specified contract, not just the N=1 or double-invert control. This follows the label/picture rule (`R/090-10x-chat-ruling-compatibility.md:21–25`) and the shipped copy implementation (`A/TexCorruptDraw.cpp:42–70`; `A/Anomaly_TexCorrupt.cpp:476–507`).
