**P2-1 — Changed pixels do not establish that the requested mode was implemented.** Location: docs/predictions/2026-09-28-m53-s2.md:538; also :539 and :541.

The cheapest real defect that passes S2 is a one-scalar error: implement normal invert with NormalSignX = +1 instead of -1, leaving NormalSignY = -1. It is then green_flip with an invert label. Both modes change all four NN1 cells, so G1-NAT passes onset, every positive frame and restoration; G1-SYN passes its edges; G2 passes; identity regression is untouched. Logging the requested mode and expected strength also passes. The graph distinguishes the modes at tools/create_texcorrupt_assets.py:97, but no Q row compares either result with its expected transform. A scramble implementation that uses a fixed visible permutation while logging the seeded pair has the same escape. Tile/swap reference comparisons are only D.

Proposed fix: retain G1 as an alignment gate and add an independent, mode-specific output oracle. For example, fixed asymmetric cells can identify the sampled source cell for tile/swap/scramble and the expected signed/encoded normal for invert/green_flip/flat; noise needs a reference tied to the authored noise sample and amplitude. Compare a small set of distinctive values or an expected image, with the existing measured rendering tolerance. Include a wrong-mode negative, not only a no-change or shifted-label negative. A scalar read-back alone does not prove that the graph consumed the scalar. This belongs in S2's mode implementation qualification, not S3's strength calibration.

**P2-2 — Drift's new snapshot path has no independent correctness, isolation or rollback qualification.** Location: docs/predictions/2026-09-28-m53-s2.md:183; also :235, :537 and :553.

The static reference is defined as the next drift event drawn once at a fixed offset. It therefore shares the newly added snapshot path with the moving event. A wrong SrcMip while populating the snapshot can affect both identically: drift-versus-static passes, the offset log passes, all dimensions pass the tripwire, and G1 still sees changed pixels. The identity regression exercises the existing direct-source path, not this extra sample/encode/decode. In addition, the two drift inputs are non-streaming data/color textures (Bank/M53S1_RD_OPAQUE_A1/_leg/game.log:2002 explicitly reads class=data). Leaving a level MID bound to the live source while directing the tripwire at an unused snapshot passes those legs; it fails on a shared source whose residency subsequently changes. UV drift also handles normal bindings, which these two inputs do not qualify.

The byte-accounting design is right, but its tests need to exercise the new ownership edges. The S1 allocation-failure and cleanup proofs do not prove rollback after a snapshot was allocated, nor release of a drift snapshot on teardown. A missed release can occur only on that new failure path and escape the planned successful drift legs and identity lifecycle legs.

Proposed fix: add a snapshot-versus-original identity check independent of the drift reference, including the supported normal/data encoding paths; prove the level-MID source actually is the snapshot; exercise a real post-Apply source-residency change while drift remains active; and cover allocation failure after snapshot acquisition plus one abnormal drift exit. A boundary-budget case should distinguish outputs-plus-scratch from outputs-plus-snapshots-plus-scratch. Retain noclear, which tests a different, useful defect. If drift is deferred under D5, remove it from the qualified auto-draw set for that disposition as well.

**P2-3 — P-VSM is a useful screen, but its three causal verdicts are not discriminated.** Location: D:/IntrusiveAnomalies/_reviews/082-10-chat-ruling-s2-plan.md:33; also :34–35 and S2:511.

Disappearance with Cache 0 establishes cache dependence, not which side was stale or whether restore code was defective. A material swap can refresh a previously stale null shadow; that also produces a persistent install-versus-null difference and disappearance with cache disabled. Conversely, both anomalies can expose the same engine invalidation behavior without either restoring the wrong material. “Cache invalidation” and “plugin-wide restore issue” are not mutually exclusive outcomes.

The comparator also changes the intervention. Anomaly_CorruptedTexture.cpp:112 swaps every slot of each selected component. The banked m53 identity events commit only 12 of 30 slots. Their later events refuse, whereas the older swap can fire repeatedly. A different trace, or its absence, cannot by itself identify an m53-specific restore defect when slot coverage, material properties and post-revert intervals differ.

Proposed fix for S2-0: reproduce cache-on identity against fresh same-build nulls; pair each cache setting with its own non-installing controls; log and match the installed component/slot footprint and use a single event followed by an equally long clean tail. If the existing comparator cannot match that footprint, record the limitation instead of assigning a unique cause. Record the original/raw/resolved material and the post-revert slot state, including override-array length. Add a no-material-change render-state/cache-refresh control, or an equivalent controlled cache refresh after revert, with a matching null. A small material-path × cache-on/off matrix is more informative than the present decision tree. Its result should distinguish “cache-dependent,” “reproduced by another material swap,” and “specific to this tested m53 path”; a causal defect classification needs the additional state evidence. The bank readings supporting this finding are detailed below.

**P2-4 — The renamed-successor gate predicts an exact material that the sweep cannot restore.** Location: docs/predictions/2026-09-28-m53-s2.md:545; implementation: Source/AnomalyInjector/Private/Anomalies/Anomaly_TexCorrupt.cpp:1164.

The planned renamed successor inherits the host MID. Its name no longer resolves the saved slot, so the owner sweep calls SetMaterial(slot, nullptr). The source explicitly calls this cleanup, not exact restoration (:1166). TC_UC1 has an explicit M_TC_UC1 override and a WorldGridMaterial asset default: Bank/M53S1_G4_TWO_A1/_leg/game.log:2004 records both. Thus the intended unresolved + swept=1 result leaves the successor on WorldGridMaterial, not pointer-identical to M_TC_UC1. The proposed row will stop even when the current cleanup contract works exactly as designed.

Proposed fix: settle the contract before S2-1. If R8.3's existing cleanup guarantee remains, the renamed row should prove that no successor slot retains an owned MID, the fallback is the asset default, and resources are released; it must not claim exact restoration. Keep the same-name variant as the exact-restore control. If exact restoration of an arbitrarily renamed successor is required, that needs an explicit successor-identification/ownership design and source work beyond the proposed bench lever. Changing a fixture to make its default accidentally equal the original would hide the distinction.

**P2-5 — PinRestoring does not ensure that there is a Restoring entry to pin.** Location: docs/predictions/2026-09-28-m53-s2.md:239 and :507; implementation: Source/AnomalyInjector/Private/Anomalies/Anomaly_StuckLowMip.cpp:772.

The lever is anchored in TickAlways's Restoring loop. Revert first skips insertion when GetNumResidentMips() is already at baseline (:772–784); TickAlways returns immediately for an empty list (:852). With Apply at frame 30 and Revert at 36, a HOLD line proves that m52 changed its control state, not that the texture streamed down before Revert. A fast or delayed streaming trajectory can take already-back and leave nothing to pin. Frame 42 then does not read T7, stopping P-M52 or G5 despite the pin echo.

This is a real state transition, not just an imagined timeout: the m52 bank distinguishes awaiting-restore from later RESTORE VERIFIED. Bank/M52D_M52D_G3_HOLD_NAT/session_20260920-213538/anomaly_log.txt:1245 records six entries awaiting restoration; :1287 still refuses after six frames, and :1306 records completion after seven. Those host timings do not prove what the new two-tile fixture will do.

Proposed fix: the premise and each gate leg should prove a measured residency drop before Revert and actual insertion into Restoring, then read the entry at the m53 decision. Alternatively, explicitly make the lever pin insertion as well as removal and label that part a state/plumbing test. Include pin cleanup on run end. Also correct S2:413/:617: targeted m52 already bypasses both the perceptibility ratio and co-affected limit (Anomaly_StuckLowMip.cpp:344–356). StuckMipMinTexelRatio 0 does not repair this recipe; the shared pair is justified by shared-texture coverage, not a targeted ratio rejection.

**P2-6 — The level-change runner can terminate before the object-lifetime assertion, and its negative uses the wrong ledger phase.** Location: docs/predictions/2026-09-28-m53-s2.md:477 and :544.

The runner is specified to stop at post_teardown, but the Q row also requires an object census after obj gc. A retained render-target UObject can coexist with a balanced payload ledger: killing on the earlier token leaves C3 unmeasured. In addition, the late-open negative is described as having no world_teardown line with live bytes. OnWorldTeardown calls Revert before logging (Anomaly_TexCorrupt.cpp:1315–1329), so the intended successful mid-event case also normally has live=0; its nonzero quantity is pending. That wording does not distinguish an actual live-event teardown from a vacuous late open.

Proposed fix: require APPLIED before open, a world-ending target-loss/revert for that event, the old-world pending/not_yet_due reading, and a tagged new-world reading at or after the due frame from the same outstanding ledger ticket. Wait for a separate post-GC census-complete token before terminating. Prove the object census can see a deliberately retained named RT and that missing/misordered world tokens fail. The global ledger makes a new-world reading feasible; the new ticket must survive destruction of the old anomaly instance, where PostRevertFrame is currently cleared (:1333). This reading establishes the declared ledger/object contract, not an independent measurement of physical GPU deallocation.

**P2-7 — The proposed telemetry shape is useful but unsupported by the worklist, and its partition rule rejects NoApply.** Location: docs/predictions/2026-09-28-m53-s2.md:221–222 and :476; serialization: Source/AnomalyInjector/Public/AnomalyTelemetry.h:5 and Source/AnomalyCapture/Private/AnomalyLabelWriter.cpp:152.

Telemetry currently supports primitive fields and one top-level array of primitive-field objects. A textures[] row cannot itself contain slots[], and uv_offset cannot be a numeric array through the existing interface. The plan's source list (:256–257) omits both the shared telemetry model and the JSON writer. Implementing only the listed m53 producers either loses those fields or changes their promised JSON shape. Empty slots_installed[] also needs explicit representation, rather than relying on AddArrayEntry when there are zero entries.

The validator's installed ∪ untouched = inventory rule is wrong for NoApply-1. That branch collects qualified textures/slots and creates MIDs, then skips commit (Anomaly_TexCorrupt.cpp:959–977). Untouched currently contains unqualified slots (:688–699), not qualified-but-deliberately-uncommitted slots. On a fully qualified one-slot NoApply fixture both sets are empty. Requiring every texture key to be merely installed OR untouched also allows a partial event to attach its transformed texture to a refused slot and still pass.

Proposed fix: include the serialization changes explicitly, keep old keys/types unchanged, and define empty arrays. Use one canonical full-component-path + slot identity in all joins; a bare StaticMeshComponent0[0] is ambiguous across owners. Distinguish committed, refused and bench-qualified-but-uncommitted slots, or scope the partition assertion to real commits and separately validate NoApply. Verify each binding-to-slot relationship against that event's captured binding inventory, not only membership in a broad union. With those corrections, the fields do resolve the earlier P2-3 problem: an offline reader can identify exactly which actor/component/material slots a partial event affected and which texture bindings they used. They do not create a pixel mask or per-instance ISM attribution.

**P2-8 — G-SEED can pass without the required mode RNG draw, and the empty-set rule contradicts its stated protocol.** Location: docs/predictions/2026-09-28-m53-s2.md:201 and :550; log source: Source/AnomalyInjector/Private/AnomalyAutoInjectorSubsystem.cpp:397.

A faulty implementation that always chooses Modes[0] without consuming the stream produces identical repeat runs, selects an allowed mode, and leaves m53-disabled runs unchanged. It passes the written G-SEED. Mutating a synthetic sequence with an extra draw proves that the comparator notices a changed sequence; it does not prove the shipping code consumed the prescribed draw. Refusal-dependent consumption has the same blind spot if both launches encounter the same refusals.

The empty-set sentence says both “draws nothing” and “draw count never depends on configuration.” UE's FRandomStream::RandHelper(0) consumes nothing, while RandHelper(1) consumes a draw (Engine/Source/Runtime/Core/Public/Math/RandomStream.h:186). Those claims cannot both hold. Finally, the existing Auto.Fire log has id, target and result, but no hold or mode; the successful HUD string rounds hold to one decimal (:391), and refused attempts have no hold there. The complete sequence evaluator at S2:474 needs a new, explicit input protocol.

Proposed fix: decide the empty-set contract, then test the actual selection routine against an independent known-answer stream. Cover zero/one/multiple enabled modes and applied/refused attempts, logging id, target, full-precision hold, mode, attempt ordinal and enough stream/draw state before Apply to diagnose a mismatch. If constant draw count is intended, an empty m53 set must still consume the defined draw before refusing; non-m53 ids must consume none. Keep the real census-off comparisons, but use them as integration evidence in addition to this protocol test. P-SEED's single sizing leg cannot establish repeatability; the lock should also require nonvacuous coverage of both ids and refused as well as applied m53 attempts.

**Mode and resource assessment.** The design contains eight product modes total: four for uv_corruption and four for normal_corruption. Cross-family mode names are intended to refuse; it is not an eight-by-two admission matrix. The UV family transforms admitted color, data and normal bindings; the normal family transforms normal bindings.

I compared the authoring script with the committed material assets, not only with scalar-name declarations. The complete UV_FN, UV_ENCODE, NORMAL_UV_FN and NORMAL_ENCODE strings in tools/create_texcorrupt_assets.py are present in their corresponding committed .uasset bytes. The authored expression and sampler contracts are therefore available already. This supports zero new plugin-asset authoring/cooks for these scalar changes; it is not a claim that the fixture cook never processes existing dependencies, or that compiled runtime output was proved by this static inspection.

The scramble CRC proposal is sound as a deterministic local derivation that consumes no scheduler RNG. Choosing a from the sorted coprime set makes the affine map bijective, and replacing (1,0) with (1,1) avoids the identity permutation. I independently checked modular inverses for every coprime coefficient for K=2 through 64. At the largest K, the shader's largest integer product is 4095 squared = 16,769,025, below 2-to-the-24; the stated float-integer bound holds. The three declared invisible K=8 pairs are fixture symmetries, so naming/excluding them with at least four remaining events is reasonable. Exclusion must be driven by independently recomputed seed/ordinal/pair data, not a potentially false pair log alone.

Before implementation, specify the CRC input as exactly three 32-bit words in a declared byte order, the CRC initialization, and whether the first attempt ordinal is 0 or 1. Add known-answer vectors and refusal-interleaving/reset cases. Hashing a padded aggregate or using FiresApplied would break that contract. None of these choices requires another pool-stream draw.

For drift, the planned payload equation is correct: sum the full BGRA8 chains for outputs, add one equally sized snapshot chain per unique output, then add the required scratch allocations. The snapshot must enter both the admission calculation and reservation before any allocation, and join release/rollback/pending accounting. The existing allocation loop distinguishes Output from an else-as-Scratch branch (Anomaly_TexCorrupt.cpp:199–285); adding an enum alone is insufficient. Make snapshot dispatch, array capacity, strong references and release explicit. Texture binding and the mip tripwire must accept the snapshot UTextureRenderTarget2D instead of assuming the old UTexture2D source type. Those are implementation consequences of the stated design, not evidence that a new plugin material cook is needed.

Also make drift's clock unambiguous. “Event-local frame index” must not silently mean the ordinal of saved labelled images. The bank has a first labelled image at engine frame 42 and the next at 45 because settle frames are not saved. Capture's SettleAfterFire branch skips captures (AnomalyCaptureSubsystem.cpp:742), while TickAlways continues. Tie the formula to a declared engine-frame/time origin, specify behavior across unsaved settle frames, and verify the first Apply frame in both dispatch orders. Existing ApplyFrame is a safer shared reference than independently incrementing a counter on Apply and TickAlways. Log both the draw frame and the offset used. The plan's assertion that both hooks precede label sampling is useful but does not alone settle this indexing choice.
