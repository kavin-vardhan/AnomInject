## 2. What blocks A6 (for chat)
- **O1, the WorldState file.** It is unavoidable for any recipe that saves a map. The writer is unconditional on `PostSaveWorld` whenever the editor holds a folder state for the world, with no switch, and `-nowrite` guards only the config writer (ConfigCacheIni.cpp:1478). The path is exactly predictable: `Saved\Config\WorldState\<CRC32(UTF-16 package path)>.json`, so 1202994220 for EA_Core and 2530609069 for EA_Travel. One option is an FC5-style recorded class keyed to exactly those names, recorded and never a STOP; any other WorldState name would still stop. The file from this run remains in place, and whatever the next arming does with it needs a rule.
- **O2, `Saved\Backup`.** Today no check sees it. It is created on the re-save of an existing package, and the recipe's `new_level` + `save_current_level` always re-saves. Two options: record it as a class, or suppress it per process with `-ini:EditorPerProjectUserSettings:[FAutoPackageBackup]:Enabled=False`. The reader is `GConfig->GetBool("FAutoPackageBackup","Enabled",…,GEditorPerProjectIni)` at PackageBackup.cpp:231-236, and `-ini:` overrides apply per ini file (ConfigCacheIni.cpp:1151). That flag must be proven in a smoke before it is relied on. The existing 7,549-B backup remains.
- **O3, the empty `Content\EuropaPhaseA` folder.** EX3 moved the files, not the folder. Content's hashed file set is equal, but a folder-existence check, such as my feature gate's `europa_phase_a_absent`, will now fail. The next arming needs to accept it or chat must rule.
