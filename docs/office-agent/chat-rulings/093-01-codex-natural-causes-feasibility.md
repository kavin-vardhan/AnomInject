## 3. Q2 — Pilot probes: what the public APIs really report

**I — Direct answer:** there is **no single public UE 5.1 API** that returns, for an arbitrary object and a specified capture frame, “these draw commands used this material and these textures, and this object contributed pixels.” The APIs below expose different levels of state. The distinction is essential: a successful setter/getter round-trip is not a GPU binding receipt; resident mips are not sampled mips; a recent-render timestamp is not a per-view draw result. This negative finding follows from the public interfaces and the private draw-selection implementation cited below; it is an API audit, not a proof about every possible engine extension.

**V — What the release already does:**

1. `A/Anomaly_StuckLowMip.cpp:1554-1588` supplies held/restoring texture watch records: baseline mips, held target, resource ID and **one primary owner**. `C/AnomalySveCapturer.cpp:56-103` samples RT resource state, current first mip and resource identity, with explicit no-resource/uninitialized/nonstreamable/partially-resident states. `C/AnomalySceneViewExtension.cpp:191-197` takes this sample at the same after-pass callback as captured scene colour. **I — Frame keying proposal:** freeze a per-request tuple `(run_epoch, session_index, capture_request_id, sample_game_frame, owner_scene, owner_target, view_family_id, view_index)` and binding/resource generations. Collect RT observations and colour/mask receipts under that tuple; reconcile asynchronously before writing final membership. Do **not** associate a late observation with the most recent GT tick. A missing owner render or lost receipt is unknown/unpaired, never measured zero. The F1 contextual branch provides the ownership/family-ID foundation (`F1:C/AnomalyCaptureOwnership.h:5-23`; `F1:C/AnomalySceneViewExtension.cpp:65-91,175-191`). No fixed one-frame latency is source-guaranteed; the first usable verdict arrives when the relevant owner render and GPU readbacks complete. Storage can retain the original frame key despite later decision time.

**V/I — VT context, not release capability:** `VT:A/AnomalyPrivateVT.cpp:271-355` checks page-table entries with GPU readbacks for a bounded private allocation; `:298` tests mapped address/level, and `:359-365` has finite readiness attempts/time. That is **prefetch readiness of owned allocations**, not a passive host-object sampling oracle. It must not be advertised as ordinary resident-mip telemetry. The source distinction agrees with `R/092-01-codex-deimos-vt-research.md:114-134` and `R/092-04-codex-vt-transform-design.md:50-68`; engine interfaces above were independently checked.

## 5. Q4 — Engine fallbacks, including PIE/cooked differences

### a. Failed material

**V:** a missing usage flag is checked in `EN/Private/Materials/Material.cpp:1734-1747`. Under `GIsEditor && !FApp::IsGame() && bAutomaticallySetUsageInEditor`, UE sets the flag, rebuilds shaders and attempts to dirty the package (`:1749-1775`). That includes ordinary PIE editor operation; it is **conditional**, not an unconditional repair promise. Cooked games do not take this editor repair path; the engine warns and callers select default material (`:1790-1805`; static-lighting example `EN/Private/StaticMeshRender.cpp:2225-2227`). This is why deliberately stripping a host usage flag in PIE is both unreliable and inconsistent with the no-dirty requirement.

**V:** non-default material compile failure reports default-material use; failure of the default itself is fatal (`EN/Private/ShaderCompiler/ShaderCompiler.cpp:4656-4674`). `FMaterialRenderProxy::GetMaterialWithFallback` walks to a complete fallback and may submit compile jobs (`EN/Private/Materials/MaterialShared.cpp:4207-4228`). **A missing permutation is not identical to an incomplete whole shader map**: base pass tries the requested shaders and walks the proxy fallback chain only if needed (`RN/BasePassRendering.cpp:507-513,1742-1760`). Other passes/domains have their own choices; no generic “everything becomes world grid” conclusion follows for UI, decal, volume, post-process or invisible geometry. Default selection is domain-dependent (`EN/Private/Materials/Material.cpp:503-520`).

**I:** in the usual visible surface-mesh case, the configured default surface material is the appropriate fallback expectation; the whole material's appearance changes, not only one missing texture. A direct default-material swap is an honest R1 test. Triggering missing usage/compile/permutation dynamically on arbitrary cooked host materials, restoring them exactly, and proving the chosen fallback per draw has **no supported universal public injection/probe pair**. Use a plugin-owned authored failure fixture if studying a particular usage failure; do not sell it as general runtime host shader failure.

### b. MID texture parameter set to null

**V:** both public MID setters forward to `SetTextureParameterValueInternal` (`EN/Private/Materials/MaterialInstanceDynamic.cpp:221-249`). The internal function can create an entry, but assignment and RT update occur only inside `if (Value && ensure(...))` (`EN/Private/Materials/MaterialInstance.cpp:3412-3437`). Therefore:

- **V:** with an existing non-null MID override, setting null leaves that override unchanged.
- **V/I:** with no prior override, it can leave a null entry, which is not a valid texture override: GT lookup tests parameter validity (`MaterialInstanceSupport.h:495-506`); RT lookup rejects null (`:293-317`) then walks parent (`MaterialInstance.cpp:270-285`). Effective lookup therefore continues to a parent/default value.
- **I:** neither case deliberately binds a real null texture. “Null means clear the override” is also wrong for the public setter. Restore the original slot/MID or deliberately clear the private MID's overrides and reconstruct them; do not mutate the host MID to conduct this experiment.

### c. Null or resource-less texture during uniform fill

**V:** ordinary 2D texture uniforms fall back to **`GWhiteTexture->TextureRHI` and its sampler**, not `GEngine->DefaultTexture`, when the resolved value/resource is invalid (`EN/Private/Materials/MaterialUniformExpressions.cpp:910-999`). Cube uses `GWhiteTextureCube` (`:1009-1040`); 2D arrays/cube arrays/volumes use the corresponding black resources (`:1050-1159`); absent external resources use white (`:1189-1192`). VT uses page-table/physical-cache fallback resources, including black uint tables and black physical SRV (`:1233-1238,1319-1323`). These are different typed cases.

**I:** a non-null plugin-owned texture with no usable resource could reach the ordinary 2D fallback, provided the compiled sampler and all validity checks permit it. That is a different candidate from null-MID MISS-3 and needs its own no-crash/control proof. Releasing or corrupting a shared host resource to force it is unnecessary and has no acceptable exact restore argument. White input does not imply a white final object: the host graph still determines colour, opacity, roughness and shading.

### d. Missing normal map

**V:** unconnected material Normal has the attribute default `(0,0,1)` (`EN/Private/Materials/MaterialShared.cpp:5295`). A texture sample with missing input can fail compilation (`EN/Private/Materials/MaterialExpressions.cpp:2701-2709`), leading to the material fallback behavior above. Runtime null MID assignment follows (b); a resource-less ordinary normal sample follows (c), **not a special flat-normal substitution**. Normal unpack takes RG or AG, remaps XY into −1..1, reconstructs Z (`SH/Common.ush:1371-1383`).

**I:** white fallback decoded as a normal is not flat `(0,0,1)`; applying that unpack to white produces XY=(1,1), Z=0 before subsequent shading normalization. NRM-3 should explicitly bind an encoding-compatible flat-normal texture and label a missing/placeholder-normal **content assignment**, not claim UE automatically supplies it for every failure. PIE/cooked share runtime lookup/unpack; compile-time missing inputs differ by shader availability and cook results.

### Exact cvar value and set-by restoration

**V:** cvar `Set` rejects lower priority (`CO/Private/HAL/ConsoleManager.cpp:164-201`) and records the new priority (`:204-217`). `SetWithCurrentPriority` is public (`CO/Public/HAL/IConsoleManager.h:525-543`). Render-thread-safe variables have an ordered shadow copy (`:80-85`). **Saving only `GetString()` is not exact for arbitrary floats:** both float `GetString` and convenience `Set(float)` use `%g` (`CO/Private/HAL/ConsoleManager.cpp:783-785`; `CO/Public/HAL/IConsoleManager.h:519-522`), whose default precision can lose float bits.

**I — Proposed RCV algorithm:** on GT, record known registered type, exact `GetInt`/`GetFloat` (raw float bits for verification), string where genuinely string-valued, and `GetFlags() & ECVF_SetByMask`; also record relevant operational flags. Apply using `Set(text, savedSetBy)` so no priority elevation is needed. Format float values with sufficient round-trip precision (9 significant decimal digits for finite binary32, not default `%g`); reject nonsensical budgets rather than inventing a safe range. On owned revert, `Set(savedExactText, savedSetBy)`, execute normal sink processing, compare typed readback/priority and wait for RT/effect recovery. Never use `ECVF_Set_NoSinkCall_Unsafe` for these sinks. `IConsoleVariable` reference registrations do not reliably reveal type via `IsVariableFloat` (`CO/Private/HAL/ConsoleManager.cpp:929-944`); use the known audited type for each proposed control.

**I:** if implementation instead elevates to SetByCode/Console, simply setting the old lower-priority value back will fail. Restore the value while holding the owned priority, then restore only the set-by bits via public flags **after ownership checks**, or clear owned priority bits before setting at saved priority; both need callback/sink ordering review. Prefer avoiding elevation. Host writes during the event cannot be made exactly reversible without trampling host intent; record lost ownership and relinquish the lever. No public transaction recreates callback side effects or proves that an identical intervening host write never occurred. One-cause-at-a-time is necessary but not sufficient for exclusive host ownership.

**V/I — Alias trap:** legacy VT pool scale and `.Group0` have separate console objects but a shared backing float (`VirtualTextureScalability.cpp:71-84`); cvar refs report their own `MainValue` (`CO/Private/HAL/ConsoleManager.cpp:942-956`). Save both objects' values/priorities **and** effective group value via exported `VirtualTextureScalability::GetPoolSizeScale(uint32)` (`EN/Public/VT/VirtualTextureScalability.h:29`). Restore in an order whose final backing value matches the saved effective scale, then verify all readbacks. If the pre-existing alias state cannot be reproduced, do not advertise an exact-restore pool-scale experiment. Same issue applies to RVT Group0 aliases.

**V/I — Ordinary pool default trap:** `CheckUserSettings` begins with the **current** `GTexturePoolSize`. For `r.Streaming.PoolSize=-1`, it recalculates only if the configured VRAM percentage and graphics-memory statistic are positive; otherwise it retains that current value (`EN/Private/Streaming/StreamingManagerTexture.cpp:1479-1497`). Merely restoring `-1` can therefore leave the squeezed budget in place. Save the effective byte budget through `IStreamingManager::Get().GetRenderAssetStreamingManager().GetPoolSize()` (public `EN/Public/ContentStreaming.h:160,461,713`; implementation `EN/Private/Streaming/StreamingManagerTexture.h:96`) in addition to cvar values. **I:** a strict Engine-only pool experiment needs a reproducible restoration route: for a stable MB-aligned budget, temporarily replay the saved effective budget with live updating enabled, observe it applied, then reinstate `-1`/fixed mode in an order that preserves that budget. If saved fixed mode was on, reinstate it **after effective-budget recovery but before a different saved raw PoolSize value**. A non-MB-aligned or independently changing effective budget may not be reproducible through the integer-MB cvar; do not arm under an exact-restore claim without resolving that case. Direct byte-budget access is exported from **RHI**, not Engine (`RH/Public/RHI.h:626-630`), and would require an additional module/design decision. Restoring cvar metadata alone is insufficient.

### Pool warnings without changing the owner's display

**V:** the ordinary over-budget warning is drawn directly to Canvas in `DrawMapWarnings`, not solely through `AddOnScreenDebugMessage` (`EN/Private/UnrealEngine.cpp:11723-11731`). Map-warning drawing is controlled by `GAreScreenMessagesEnabled` and `GEngine->bSuppressMapWarnings` (`:11930-11942`); debug-message system flags alone are insufficient. `AddOnScreenDebugMessage` itself is compiled out in Test/Shipping (`:10847-10850`), but the map-warning call site is guarded by `!UE_BUILD_SHIPPING`, so do not assume Test removes every warning.

**V/I — Preferred capture-only route:** use the owner-bound scene-colour SVE image upstream of viewport HUD/Canvas composition. Release capture hooks `EPostProcessingPass::VisualizeDepthOfField` and copies scene colour (`C/AnomalySceneViewExtension.cpp:149-162,241-262`); viewport rendering then invokes HUD, PostRender and stats (`EN/Private/GameViewportClient.cpp:1707,1803,1851,1874`). That keeps these Canvas warnings out of the **captured image**, while leaving the interactive display/logs alone. Confirm the selected capture backend uses that image; backbuffer/synchronous fallback is not equivalent. A missing eligible SVE image should remain capture-unpaired, not silently switch to a differently composed picture. Global `DisableAllScreenMessages` or `bSuppressMapWarnings` for an entire event would also suppress the owner's view and is **not capture-only**. If a later implementation chooses scoped suppression for a backbuffer path, it needs an owner-viewport draw-boundary hook and exact restoration; none was established by this source study.

### Aiming and baseline coverage

**V:** retention priority explicitly favors forced/terrain/low-resolution assets, visible mip demand (+1024), non-huge resources, small/high-priority assets and recent use (`EN/Private/Streaming/StreamingTexture.cpp:384-402`). Budget reduction iterates lowest priority first (`EN/Private/Streaming/AsyncTextureStreaming.cpp:419-455,680-705`). Therefore **“off-screen goes first” is a tendency with exceptions**, not a universal ordering. `BoostTextures(actor,factor)` is public (`EN/Public/ContentStreaming.h:443`) but is a temporary demand multiplier automatically reset after calculation (`EN/Private/Streaming/StreamingManagerTexture.cpp:693-709`), not a target-first eviction API.

**I:** BLUR-2 can be escalated until some visible resources suffer, but this does not guarantee the chosen target, a bounded number of co-effects, or acceptable frequency. Pre-boosting all other textures, forcing them resident, disabling streaming globally, or painting a fallback would change the experiment's cause and conflict with the supplied compatibility ruling. Prefer BLUR-1 for aimed ordinary-texture blur. No claim of office pool pressure or safe pool magnitude is made.

**V/I:** a complete **ordinary streamable 2D** binding inventory can be compared against a resource-generation-aware RT pre-arm baseline, including every visible user of shared textures; Q2 gives the APIs. It cannot truthfully report resident-mip deficit for **every possible texture type on every object**: VT uses pages; render targets/nonstreaming textures have no ordinary streaming deficit; external textures and arrays have different resources; unenumerated shader resources and material fallback need explicit coverage states. Record `not_applicable`/`unknown`, not fabricated zero deficit. Even a full residency census does not tell which texture samples contributed visible colour that frame.

## 10. Q9 — Measured masks when the original stops drawing

### Why the existing route is insufficient

**V:** mode 1 saves main/depth/shadow/GI/ray/decal flags, disables those contributions and leaves custom depth available (`I/AnomalyHiddenClass.cpp:101-127`); it restores saved flags at `:163-171`. Its own description contrasts mode 0, which calls `SetActorHiddenInGame` and loses hidden-frame custom depth (`:47-51,81-84`). The existing shader counts the would-be surface (RT0) and scene-depth agreement (RT1) separately (`P/Shaders/Private/AnomalyVisibleMask.usf:39-51`).

**V/I:** a genuine distance/frustum cull removes the original primitive before custom-depth mesh commands are collected (`RN/SceneVisibility.cpp:817-848,2727-2729`). Keeping `bRenderCustomDepth` enabled does not rescue that geometry. More seriously, `FStaticMeshSceneProxy::CanBeOccluded()` requires `!ShouldRenderCustomDepth()` (`EN/Private/StaticMeshRender.cpp:1919-1922`), and the occlusion loop immediately treats a primitive without CanBeOccluded as unoccluded (`RN/SceneVisibility.cpp:1279-1284`). Thus **tagging the original ordinary static mesh can prevent GONE-2**. Editor selection can also defeat occlusion (`:1290-1298`). A zero measurement after genuine culling and a successful visibility workaround are not equivalent evidence.

### Proposed bounded reference-surface route

**INFERRED — First scope:** ordinary non-Nanite `UStaticMeshComponent` with reproducible opaque/masked geometry. Other classes are admitted only when their geometry can be reproduced correctly, not refused because of a name/suffix. Proposed sequence, using public component flags and existing GPU-mask infrastructure (therefore subject to the module qualification in Q1):

1. Before arming, retain the **pristine target geometry**, transform, materials, component/mesh generation, LOD settings, custom primitive data where relevant, and unmodified bounds. Create a plugin-owned transient reference component sharing the original mesh/material resources. Copying a spline, ISM/HISM, skeletal/cloth pose or custom proxy by pretending it is a plain static mesh is not valid.
2. Register that companion with main pass, ordinary depth, shadows, dynamic indirect/distance-field lighting, ray tracing, decals and collision disabled. Enable only the required custom-depth/stencil measurement; give it an owned tag. Use unclipped/pristine bounds and no distance cull on the companion. Public main/depth setters are `EN/Classes/Components/PrimitiveComponent.h:1768-1774`; existing flag treatment is `I/AnomalyHiddenClass.cpp:101-127`; cull setters are `EN/Private/Components/PrimitiveComponent.cpp:1794-1827`. For an ordinary static companion, set `bIgnoreInstanceForTextureStreaming` **before registration** so it does not introduce another ordinary streaming demand (`EN/Classes/Components/StaticMeshComponent.h:315-321`; `EN/Private/Components/StaticMeshComponent.cpp:1081-1085`). This does not establish that every VT feedback or host postprocess interaction is absent.
3. Prove the companion is an **equivalent measured surface** while the original still draws: geometry/coverage/depth agree in the owner view, and introducing/removing it leaves captured colour unchanged within the separately established clean noise behavior. Same material pointer alone is insufficient: WPO can depend on primitive identity, object bounds, per-instance data and time; masked coverage and LOD/dither must match. Start with content where that equivalence is demonstrable.
4. Arm the cause on the **original only**. In the same owner view, rasterize the companion into custom depth and compare with that frame's real scene depth. Reference depth in front of or equal to actual scene depth measures the expected visible silhouette, with real occluders removed. The strictly nearer part identifies missing front-surface support; pair it with source-frame colour evidence and the original's state. Depth equality remains ambiguous for coplanar geometry, just as in the shipped method. Do not call it an exact draw-command or cull-reason receipt.
5. Retain the measured mask, target identity and frame key through readback and restoration. Restore the original cause first; observe recovery, then retire the companion and its tag after all requests referencing it are complete. No host mesh or material is duplicated for editing, dirtied or saved; only the transient component is created/destroyed.

**I — GONE-2-specific rule:** never enable custom depth on the original to prove occlusion failure, including through census/event tagging. Release any plugin-owned original tags before baseline/history qualification; account for the renderer history reset/lag. A host original already using custom depth is ineligible for this *occlusion-query mechanism* unless an independently authorized change to that host feature is part of the experiment. Do not silently disable its legitimate custom-depth use. A companion does not require changing the original's CanBeOccluded state. The global buffered-query lever still lacks reliable aimed yield, even after fixing the observer effect.

**I — Residual interactions:** companion custom depth can affect a host's outline/postprocess and consume a nearest-depth sample that another tag wanted; it can also create VT feedback or rendering cost. These are real picture/measurement/resource concerns. Ordinary streaming exclusion addresses only one of them. If the companion changes colour or culling/streaming behavior materially, this route has not qualified that target; do not suppress the evidence by painting a mask or disabling the host effect globally.

**V/I — Alternative:** a dedicated `USceneCaptureComponent2D` with only the reference component visible can rasterize a separate reference-depth image (`CaptureScene` / `CaptureSceneDeferred`, `EN/Classes/Components/SceneCaptureComponent2D.h:158-169`; `SetVisibleInSceneCaptureOnly`, `PrimitiveComponent.h:1776-1782`). It must then compare that depth against the **captured owner view's** scene depth, not its own empty-world depth. Matching projection, rect, jitter, pose, LOD, WPO and frame state is substantial work; the engine explicitly warns that `CustomProjectionMatrix` does **not affect culling** (`SceneCaptureComponent2D.h:61-67`). This is an L alternative, not a drop-in guarantee. Its view must never consume the owner capture's request. A cached pre-arm mask is valid only while camera, geometry and occluders are demonstrably unchanged; it is not a general measured-mask solution for moving GONE-2/4.
