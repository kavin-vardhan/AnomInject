Add a short "Known limitations of this build" subsection to the readme's troubleshooting section (section 7), in plain client language, consistent with the readme's tone. Three items:

1. **Capture with one live game view.** Run the game in a new window (Play → New Editor Window) or as the packaged game, and close or pause other realtime editor viewports while capturing. With several realtime views open in the editor, a capture can occasionally record a frame from an editor view instead of the game view and label it as the game. Packaged and standalone games have one view and are not affected.
2. **Two rare edge cases for UV/normal corruption.** (a) When the plugin cannot tell which parts of an object it changed, the label box and target mask cover the whole object even if only some of its parts look different. (b) A texture that varies only in a channel the material does not use can be swapped with no visible change; the event is still labelled. Both are rare. The labelled preview images (or the overlay inspector) make them easy to spot.
3. **Anti-aliasing tip.** With temporal anti-aliasing (TAA/TSR) the picture can trail the label by a frame or two at an event's start and end (already described in §8.7). To avoid it, use FXAA: add `-ExecCmds="r.AntiAliasingMethod 1"` to the game's launch command (merge it into an existing `-ExecCmds` with a comma, since only one is used), or type `r.AntiAliasingMethod 1` in the console before capturing. Type `r.AntiAliasingMethod` alone afterwards to check it reads 1; some games reset it from their own graphics menu. Project Settings → Rendering → Anti-Aliasing Method → FXAA makes it permanent for a project.
