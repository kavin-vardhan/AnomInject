# 09423 fixture-authoring amendments

Authority: [094-22-ruling EX1-EX6](D:/IntrusiveAnomalies/_reviews/094-22-ruling.md), amending [EW2/EW3](D:/IntrusiveAnomalies/_reviews/094-21-ruling.md). The accepted [09422 mechanism and source citations](09422-authoring-design.md) remain applicable except for the in-session paragraph superseded below. This job only re-arms and dry-runs; the later real run needs chat's ruling.

The two stock UE4Editor/Python authoring sessions and exact three output packages are unchanged. No descriptor, config, probe, production source, binary or manifest changes. The EU4 false override, -nowrite, -SkipCompile and -stdout remain mandatory. -unattended stays absent under EX4. All existing Content and config files are checked before and after each session.

EX1 replaces image-name exclusions with the current process ancestry. Every poll records the running EpicGamesLauncher roots and every descendant, including EOS overlay children. Each ancestry chain is recomputed from that poll; creation times reject a parent younger than its child. A matching image outside that tree has no blanket exemption. Any foreign Unreal/game/UBT/UHT process outside the tree still blocks the full measured start gate. An absent launcher still waits; the kit never starts it. The separate live observe-only collector receipt after both dry runs is evidence of the actual process tree, not a launch admission.

EX2 leaves the full measured start gate unchanged: human idle 300 seconds, free physical memory at least 6 GiB, GPU at most 15 percent, no foreign Unreal process, and three spaced passing polls. After a session starts, only a disk floor breach, free commit below 6 GiB, and the 1800-second deadline act. Physical memory, GPU, input and foreign processes are recorded only. They neither interrupt nor rerun the authoring leg. Collector errors/staleness are recorded; a slow observational collector cannot delay the independent deadline or the fast direct disk/commit readings. Hard scope/protected-state failures remain failures.

The outer disk supervisor retains EU2 pauses before a session. A recipe-state phase receipt, bound to the current helper PID and the exact EW2 scope, transfers in-session floor handling to the runtime monitor. The runtime monitor stops its retained editor PID tree, including crash-report children, without an EU2 pause. The ledger floor check also refuses immediately instead of entering a pause after authoring starts. The phase receipt cannot authorize a different recipe, stale wrapper or foreign helper. No process-creation success can release the launched lock.

EX3 explicitly permits repeated saves of the same newly declared package within its one session. It does not permit overwriting a pre-existing package or an earlier attempt's output. A failed session's declared partial outputs are moved into <attempt>/quarantine/<filename>. quarantine-receipt.json records exact source/destination, hash, size, mtime and file identity before the first move, then each completed move and its hash verification. Only exact declared paths are eligible; aliases, non-regular files, hard links, pre-existing files and reused quarantine destinations refuse. Existing Content is rehashed before and after the move. Nothing outside the declared paths is moved. A move failure retains its partial receipt and remaining files for review; no automatic retry follows. A retry needs chat's new arming, even after successful quarantine.

Arming job 09423 has three fresh prelaunch slots for each recipe and one permanent launched lock per recipe. One global lock serializes both recipes. The config cites EW2/EW3 plus EX1 through EX5 and states "armed for EW2". The old 09422 arming is rejected, and all its real paths remain absent. The 09417 owner kit remains spent and unchanged.

Runtime outputs remain confined to the accepted routing: caches and shader scratch under D:/IA_Europa/Caches/425, attempt receipts under D:/IA_Europa/Receipts/09423, TEMP under D:/IA_Europa/Temp/09423, and only the three declared new Content packages. Quarantine is within the same attempt receipts on D:. Wrapper EUROPA_* metadata and secret-class variables never enter runtime/build/collector children. All three EW1 manifests remain bound without re-generation.

The EX1-EX5 candidate passed 57 targeted can-fails, 89 kit regressions, 48 measured-gate cases, and the existing 33-case static check on the first attempt. Tests only use synthetic packages under owned scratch and harmless Python children. Actual authoring, clean exit, and runtime behavior require the later real leg.
